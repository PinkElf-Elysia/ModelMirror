## 完成结果

你会把一次成功的 Workflow 或私有 Xpert Chat 运行，经过脱敏素材确认、经验分析和人工决策，交给已经预填的 Skill Creator。这个过程不会自动创建文件、安装 Skill 或修改已有版本。

## 适用对象

适合刚完成一项有重复价值的任务，希望保存做法，但不想手工重新描述全部需求的人。

## 开始前

- 运行必须已经成功完成；失败、取消、等待审批和公共 App 运行不能沉淀。
- 需要使用私有控制台，并且 Skill Creator 可用。
- 点击“分析并预填”可能调用当前配置的模型 Provider 并产生费用。调用前页面会明确提示。
- 完整对话、工具参数、附件和本机路径不会发送。最终输出片段默认不选中。

## 真实范例

一个发布检查 Workflow 成功找出了命名和扩展名问题。你希望以后每次发布都复用同一套检查，但不希望把这次发布的具体文件名写死在 Skill 中。

## 操作步骤

1. 在已完成的 Workflow 运行结果或私有 Xpert Chat 回复下，点击“沉淀为 Skill”。

   你应看到脱敏素材清单，而不是空白 Creator。此时尚未调用模型，也没有创建 Skill。

2. 检查目标、成功步骤、工具名称、用户修正和输入输出结构。只保留适合复用的项目。

   “最终输出片段”默认关闭。只有你确认片段不含不应外发的内容时才勾选。

3. 点击“确认这些素材”，再点击“分析并预填”。

   配置模型时，本次确认的摘要会发送给当前 Provider；没有配置模型时，页面会生成可编辑的手工提纲，不会外发。

4. 检查建议：新建 Skill、更新现有 Creator Skill，或这次不沉淀。

   第三方 Skill 只会作为可能重叠的提示，不能被这个流程直接更新。选择新建且与已有能力高度重叠时，需要说明新的适用边界。

5. 补全正例、近似反例、预期输出和成功标准，然后点击“确认并打开 Creator”。

   Creator 会显示来源运行和已确认的提纲，并直接进入素材与资源计划。后续仍要完成触发验证、资源构建、行为评测和独立安装确认。

## 刷新和恢复

分析中刷新页面不会重复调用模型。未处理的候选也会出现在 [Skill Creator](/skills/create) 的“待处理运行经验”中，可以继续完成。

如果页面提示来源已变化，重新打开原运行检查。系统不会用旧 run、旧版本或失效证据继续创建 Skill。

## 常见问题

### 为什么建议“不沉淀”？

常见原因包括任务只发生一次、内容只是个人偏好或环境事实、证据不足、已有 Skill 已覆盖，或做法无法稳定泛化。建议可以由你复核，但来源、安全和版本冲突不能绕过。

### 原运行成功是否等于新 Skill 已通过？

不等于。原运行证明这次任务完成，不证明尚未生成的 Skill 在其他任务中也有效。进入 Creator 后仍需重新执行 with-skill 评测。

### 可以直接更新从 Git 或本地导入的 Skill 吗？

不可以。自动更新只支持当前可编辑的 Workspace Creator Skill，避免覆盖第三方来源和不可编辑内容。

## 限制

- 当前只支持成功完成的经典 Workflow 和私有 Xpert Chat。
- 不支持失败运行、公共 Xpert App、workflow-native、后台自动学习或自动安装。
- 关闭运行经验开关后会回到旧的 Creator capture 行为，已保存候选不会被删除。

打开预填 Creator 后，先确认触发正反例和资源计划；需要从零创建时，直接进入 [Skill Creator](/skills/create)。
