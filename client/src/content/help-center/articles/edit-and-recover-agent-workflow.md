## 完成结果

你会修改一个已经发布的 Agent 或工作流，并在运行失败时找到失败记录、理解原因、决定是否重试或调整。本教程不改动已发布版本的对外行为，只创建新的草稿或查看诊断信息。

## 适用对象

适合已经创建过 Agent 或工作流、现在需要调整它，或遇到运行失败想排查的用户。不需要会写代码。

## 开始前

- 确认你已有一个发布过的 Agent（到 [Agent Studio](/agents/studio) 查看）或保存过的工作流（到 [经典工作流](/workflow) 查看）。
- 想清楚要改什么：是调整角色说明、增加工具，还是改变流程步骤。
- 修改 Agent 草稿和再发布本身不调用模型；只有实际运行才可能产生模型费用。

## 真实范例

你的"周报整理助手"已经发布 v1，但你想让它输出更简洁。你不希望改动已发布的 v1（别人可能正在用），而是新建一个草稿，调整后发布为 v2，让新版本生效。

## 操作步骤

### 修改已发布的 Agent

1. 打开 [Agent Studio](/agents/studio)，在"我的智能体"列表中找到你要改的 Agent，点击进入工作区。顶部会显示"已发布 v1"和当前草稿 revision；已发布版本是**不可变快照**，你改的是草稿，不会影响 v1。

2. 修改你想要的配置：名称、说明、标签、开场问题，或下方工作流画布中的节点。

3. 点击"保存信息"保存草稿。此时 v1 仍然生效，草稿是独立的。

4. 确认改动没问题后，点击"发布预检"。通过后点击"发布 v2"。

5. 发布成功后，顶部状态变为"已发布 v2"。别人再使用时会用 v2；v1 作为历史版本保留在右侧版本记录中，可随时对照。

### 查看失败的工作流运行

6. 打开 [运维](/runtime)，在"运行记录"区域，用顶部的状态筛选选择"失败"。

7. 失败的工作流会以红色/异常样式显示。点击它展开详情，查看失败原因和涉及的任务。

8. 根据失败原因决定下一步：如果是配置问题，回到工作流画布调整后重新运行；如果是临时性问题，可以重新运行一次。

## 常见问题

### 改已发布的 Agent 会影响正在用的人吗？

不会。已发布版本是不可变快照。你改的是草稿，只有发布新版本（如 v2）后，新版本才对之后的使用生效。旧版本保留在版本记录中。

### 能回退到旧版本吗？

已发布版本都保留在版本记录中。如果需要回到旧行为，可以基于旧版本的内容重新调整草稿并发布，而不是原地修改旧版本。

### 工作流失败了一定要重跑吗？

不一定。先在运维页查看失败原因。如果是数据或配置问题，修复后再运行；如果是外部服务临时不可用，稍后重试可能成功。

## 限制

- 本教程基于源码核对当前界面，未逐屏重放全部操作；截图后续补充。
- 修改草稿不产生费用；但发布新版本后，新版本的实际运行仍按所选模型计费。
- 工作流失败恢复仅覆盖"查看记录 + 调整后重跑"，不覆盖自动重试、死信等高级恢复机制。
