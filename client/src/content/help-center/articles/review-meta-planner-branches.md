## 完成结果

你会检查 Meta Planner 候选中的条件分支、成功终点和错误终点，预览一项修改后再确认应用，并为分支准备可重复的路径评测用例。操作不会自动批准提案或发布 Agent。

## 适用对象

适合已经生成 Meta Planner 候选，需要确认每条分支是否通向正确结果，并准备路径回归评测的用户。

## 开始前

- 打开 [AI 工作流生成器](/agents/meta-agent)，页面会自动载入最近更新的待审候选。当前页面没有任意历史候选选择器，不要把自动载入的候选误认成另一份历史结果。
- 候选应显示“控制流静态证据”；没有该区域时，不要根据画布连线猜测分支是否有效。
- 人工预览与应用候选修改不会调用模型；生成候选、明确授权的定向模型修复和真实评测可能产生费用。
- 路径评测只能使用候选报告中的语义结果名，例如 `router:case_1`，不要填写画布内部 ID。

## 真实范例

一个请求分流候选包含三种互斥结果：`router:case_1` 进入批准回答，`router:case_2` 进入拒绝回答，`router:default` 以 `UNSUPPORTED_REQUEST` 结束。静态报告应分别显示两个成功来源和一个错误终点。

成功路径用例可以只检查路径，不要求固定回答文本：

```json
{
  "path": {
    "required_outcomes": ["router:case_1"],
    "forbidden_outcomes": ["router:case_2", "router:default"],
    "terminal": "success",
    "error_code": null
  },
  "weights": {"workflow_path_match": 1}
}
```

## 操作步骤

1. 在候选详情中找到“控制流静态证据”，核对路由数量、场景数量和成功来源数量。
2. 逐条检查场景：每个语义结果应只到达一个成功来源或一个明确错误终点；出现不可达、多个终点或缺少默认路径时先返回修改候选。
3. 修改候选名称或说明后选择“预览元数据变更”。确认弹窗只列出预期操作，并查看变更前后的候选摘要。
4. 选择“确认应用”。Proposal revision 应只增加一次；若页面提示冲突，刷新并重新预览，不要覆盖另一窗口的修改。
5. 选择“评测候选”，创建或打开评测集，在用例的 `path` 中填写必经结果、禁止结果和成功或错误终点。预期错误用例还应填写稳定的安全错误码。
6. 保存评测集草稿并检查可发布状态。手工评测集不要求生成校准；针对性生成的数据集编辑后需要重新校准。发布评测集后，才运行可能产生费用的真实评测。

## 常见问题

### 失败候选如何人工修复？

生成失败且原图已安全保留时，详情显示“失败候选人工修复”，而不是把诊断占位图当作真实候选。

诊断按来源分区：“当前原图复核”是加载后对保留原图的检查；“生成阶段诊断”是生成当时的失败；
“提案审批校验”仍决定能否批准。“诊断占位图校验（非模型产物）”只属于不可执行的占位候选，
其中缺少模型不表示原图也缺少模型。旧报告若未记录来源，保留为“历史混合诊断（来源未分离）”，
不能据此猜测根因。恢复状态始终显示“待修复”，占位图场景不作为当前原图的静态证据。

1. 载入与编辑：展开“原始生成与修复诊断”，区分当次产出图、修复输入和单独展示的当前复核；“未执行”不等于通过。有结构化位置时点击“定位”，否则不猜测节点。在“节点配置”编辑标题或语义配置；缺少连线时，在“连接修复”选择来源、目标和命名端口，将修改加入“待应用改动”。复杂修改可使用“高级：编辑完整修复操作”，仍不能提交原生节点 ID、Handle、版本或越权资源。
2. 预览与应用：点击“校验并预览修复”，此时提案尚未变化；失败则继续检查诊断，通过后仍需点击“确认应用修复”。修改后必须重新预览。应用成功只增加一次 revision，恢复普通候选编辑；审批、评测和发布仍是后续独立操作，不能把修复通过当作运行效果证据。

中间修改仅保留在当前编辑区，刷新页面会丢失未应用操作。发生版本或资源冲突时，重新加载候选后核对并重新预览，不覆盖另一窗口。
未保留原始图的历史失败、未能解析或含敏感字段而未保留的产物会明确显示不可恢复；系统不会从占位图伪造原图。
人工编辑与预览不会调用模型，也不执行工作流或业务写入。

![失败候选的原图复核与连接修复区，提示 write 缺少 records 输入](/help-center/89b72c67/r7-repair-diagnostic.png)

这类诊断表示原图已保留但连接不完整，并非“没有原图”。先核对缺少的端口，再加入连接修改。

![人工修复预览通过但尚未写回，待应用改动为 lookup 到 write 的数据连接](/help-center/89b72c67/r7-repair-preview.png)

上方“当前原图复核”仍失败、下方“修复预览通过，尚未写回”可以同时出现：二者检查的不是同一状态。
不要重复加入相同连接，也不要为改变上方状态再次付费调用；只有“确认应用修复”才写回提案。

若显示“失败生成描述修复”，说明描述已安全保留，但尚未展开为原图。服务端提供受限语义契约时，
“语义修复操作 JSON”可提交 `update_node`、`clone_agent`、`replace_control_flow` 和 `set_final_output`。
展开“操作字段契约”核对必填字段；任务、资源、模型身份和授权仍锁定，不能删除原业务节点。
例如替换控制树使用 `control_flow` 字段，不放进 `config`；修改原节点必须给出 `node_ref`。
旧服务未提供此契约时，仍仅可在“控制结构 JSON”调整 `control_flow`，不能推定额外编辑权限。
诊断会区分未知、重复及遗漏引用，
重复项同时显示首次位置。公共后续节点应放在分支之后，且不能读取仅在某条分支存在的数据。
修改后仍须预览并显式应用；其他语义错误未解决时不能应用，也不能改占位图绕过检查。

若显示“资源种类校验未通过”及“Agent 资源绑定 JSON”，只能修正顶层 Agent 绑定数组。
数据表由查询/写入节点自己的 `resource_ref` 引用，不属于 Agent 绑定资源；无绑定授权时数组应为 `[]`。
该入口不改变节点自有资源、任务、控制结构或授权。只有资源种类错误、其余结构与安全检查通过且
资源 ID 在授权目录内的描述才会保留；仍须完整预览通过再显式应用，不会自动删除错误项或付费重试。

### 何时可以再请模型定向修复？

仅在原图已保留且仍未通过校验时，展开“定向模型修复”。先选择精确模型、填写补充修复要求，
再点击“查看本次外发内容”。检查完整正文、网关、模型和输出 Token 上限：其中包括目标、
失败图内的节点 Prompt、诊断及授权资源安全元数据；系统不额外读取数据表记录或附件正文。
例如可要求“保留低分更新与高分不写入两条分支，只修正可信记录来源”，不能借此扩大表或字段授权。

这一步不调用模型。确认内容无敏感信息后，手动勾选本次费用授权，再点击“授权并执行一次修复”。
每次最多一次 completion，不自动重试，不计入原始生成的三次预算。改变模型、要求或预算后要重新确认；
确认 15 分钟后或服务重启后失效。一个提案最多 20 次显式修复，达到上限不能删除历史换取新额度。

收到建议后核对诊断和回执，再点击“载入人工编辑区”，接着按上文进行人工预览与应用。
建议不会自动保存或覆盖已有本地操作，也不会执行写节点。预检通过不代表业务结果已正确。
若连接中断，先点击“刷新调用回执”，不要重复点击调用；系统不会自动重发。
历史结果不确定时，新调用还需确认可能再次计费。实际 Token 缺失会显示“不可验证”，不是零费用。

### 为什么不能直接填写节点 ID 或连线 Handle？

这些是画布内部信息，可能随编译变化。路径评测使用候选报告中的语义结果名，才能在重新编译后保持含义稳定。

### 生成描述简化后，是否可以省略业务分支？

不能。模型仍需明确选择业务条件、数据来源、顺序、分支和并行路径；系统只派生变量、端口类型和内部连线。
不会自动补上“未找到记录”分支，也不会把互斥分支改成串行。仍应检查静态场景及实际评测。
严格解析且安全保留的描述即使尚未展开为原图，也可使用上述语义修复及显式定向模型修复；
模型建议必须先载入本地编辑区，再独立预览和确认应用，不会自动保存。
资源种类或输入模式失配的保留草稿仍只允许各自的人工窄修复，不开放上述模型入口。
显示“旧问题尚未复核”时，不代表原问题已消失；修复请求尚未执行到该检查阶段。
无法解析、超限或敏感而未保留的产物，以及历史未保留描述，不能从占位图重建。

### 为什么错误终点用例不能同时检查回答文本？

错误终点表示流程按设计停止，没有成功回答。此类用例只在实际路径和安全错误码都匹配时通过。

### 为什么保存后不能立即发布评测集？

针对性生成的数据集修改后会使旧校准失效。手工评测集不受这项校准门禁限制；请检查保存结果、用例校验或版本冲突提示。
