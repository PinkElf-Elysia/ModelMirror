## 完成结果

你会为只读 HTTP 请求、数据表查询或知识检索配置一条明确的错误分支。预期的外部运行故障会生成不含原始响应或数据的安全回执，并沿红色“错误”出口继续；配置、权限和安全策略错误仍会终止工作流。

## 适用对象

适合需要在远端服务暂时不可用、返回非成功状态，或本地只读查询短暂失败时执行通知、降级或记录动作的工作流用户。它不是忽略所有错误的开关，也不会把凭据、内网访问或配置错误变成成功。

## 开始前

请在[经典工作流画布](/workflow)准备一个 V2“安全 HTTP 请求”、只读“数据表查询”或 V2“知识检索”节点，并为成功输出和错误回执分别声明不同变量。默认策略仍是“停止工作流”；只有显式启用错误出口并接好一条错误连线后，预期运行故障才会被处理。

本功能本身不产生模型费用。HTTP 请求可能把你配置的数据发送到目标公网服务；数据表和本地知识检索仍遵守各自的权限与数据边界。

## 真实范例

一个只读公网 GET 用来获取状态数据：成功时进入解析步骤；服务返回 503 时，错误分支收到 `HTTP_STATUS_NOT_SUCCESSFUL` 安全回执并写入内部告警。若地址指向内网、凭据无效或返回 401/403，系统会失败关闭，不允许用错误分支绕过安全门禁。

## 操作步骤

1. 在画布中选择支持该能力的只读节点，展开“失败处理”。
2. 将处理方式从“停止工作流”改为“输出到错误分支”。
3. 选择或创建一个独立错误变量，例如 `request_error`；它不能与正常输出、常量或其他节点输出重名。
4. 从节点卡片的红色“错误”出口连接一条错误处理路径。该出口必须恰好有一条连线。
5. 保留普通出口的成功路径。两条路径互斥：一次运行只会选择其中一条。
6. 使用不含用户数据和密钥的合成样例手动运行，分别验证一次成功结果和一次可处理的外部失败。
7. 在运行区确认成功节点显示正常完成，或失败节点显示“已处理失败”、安全错误码和 `attempts: 1`；确认未选择分支没有执行副作用节点。

## 常见问题

### “已处理失败”和“工作流失败”有什么区别？

“已处理失败”表示节点遇到了已归一化、允许路由的运行故障，写入安全回执后沿错误分支继续。只要后续路径成功，整个工作流可以完成，也不会触发正式失败处置入口。“工作流失败”表示错误不可路由，或错误分支本身再次失败，工作流会停止并按既有规则派发一次脱敏失败事件。

### 为什么有些错误不能进入错误分支？

配置和合同错误、凭据或权限错误、功能开关关闭、SSRF/DNS/TLS 等安全门禁、变量缺失、资源不存在、Schema 漂移、取消和未知内部异常都必须失败关闭。错误出口只处理明确识别的外部状态、网络、响应格式或只读查询运行故障。

### 打开“新建工作流”时为什么会先询问是否恢复草稿？

如果浏览器中已有未发布的本地草稿，画布会先显示恢复选择。选择“恢复本地草稿”继续原图；选择“使用默认工作流新建”只打开默认图，原本地草稿仍保留到你保存或转换为止。这避免旧草稿被静默载入后误执行。

## 限制

本轮只覆盖 V2 安全 HTTP 请求、数据表只读查询和 V2 知识检索。它不支持写请求、数据表写入、模型、Agent、MCP、子流程或知识写入提议的错误路由，也不提供整次执行重放或人工从失败节点继续。

错误回执只包含固定错误码、分类、节点身份、尝试次数和安全文案；不会包含 URL、请求头、响应正文、表记录、检索文本、凭据或堆栈。若业务确实需要原始外部内容，应在成功路径中显式处理，不能从错误信息中恢复。
