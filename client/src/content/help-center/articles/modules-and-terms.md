## 完成结果

你会知道当前任务应该从哪个入口开始，以及需要资料、工具、固定流程或故障排查时该去哪里。

## 适用对象

适合第一次使用模镜，或在模型、Agent、工作流等入口之间拿不准的人。

## 开始前

先用一句话写下要完成的事。只判断眼前任务，不需要先学会所有模块。

## 模镜怎样组织功能

模镜把“查找能力”“完成任务”“保存做法”和“排查运行”分开放置。你不需要按固定顺序浏览全部模块，只需从当前任务需要的那一层开始。

- **资源入口**：[模型](/help/modules/models)、[Agent](/help/modules/agents)、[MCP](/help/modules/mcps)、[Skill](/help/modules/skills)和[提示词](/help/modules/prompts)。这里用来查找可以直接使用或组合的能力。
- **工作台与设置**：[经典工作流](/help/modules/workspace/workflow)、[RAG 知识库](/help/modules/workspace/rag)、本地数据表、Coding 和系统设置。这里用来固定过程、管理资料或配置环境。
- **运行与排查**：[Runtime 运维](/help/modules/runtime)集中显示运行记录、客户端宿主和运行资源。它帮助定位问题，实际修改仍要回到对应模块。
- **实验功能**：Workflow Native、Science 和矩阵绿洲与稳定入口分开。实验范围可能变化，不能代替已经开放的主路径。

## 一项任务通常怎样向后延伸

- 先用**模型**完成一次任务，确认输入和期望结果是否成立。
- 需要反复使用同一角色和要求时，再保存为 **Agent**。
- 需要固定多个步骤、分支或人工确认点时，再使用**经典工作流**。
- 任务必须根据自己的资料回答时，连接 **RAG 知识库**；必须使用外部服务时，再查看 **MCP**。
- 已经验证有效的做法可以整理为 **Skill**，供以后复用。
- 运行失败或连接状态不明时，到 **Runtime 运维**查看可见状态，再回到原模块处理。

Agent Studio、AI 工作流生成器和专家团都属于 Agent，其中专家团是多角色协作的二级功能。经典工作流属于“工作台与设置”；Workflow Native 是独立实验入口，不替代经典工作流。Science 暂无独立可用入口，当前不要把它当成已经开放的功能。系统设置通常由有权限的人操作。

完整层级见[按模块浏览](/help/sections/modules)。

## 常用词是什么意思

| 页面用语 | 白话说明 |
| --- | --- |
| Agent | 保存下来的角色、要求和工具组合，便于以后重复使用 |
| Workflow | 按固定顺序连接多个步骤的工作流 |
| MCP | 让 AI 连接外部工具或服务的方式 |
| Skill | 可以安装、创建和重复使用的做法 |
| RAG | 先从指定资料中查找内容，再让模型回答 |
| Runtime | 查看运行记录、连接和环境是否就绪的运维页面 |
| Provider | 提供模型或其他服务的连接方，通常由管理员配置 |

## 看见入口不等于现在可用

进入页面后还要检查三件事：按钮是否可用，当前环境是否已经配置，以及这次操作是否会发送数据或产生费用。目录中有某项能力，只能说明可以查到它，不能证明真实调用已经验证。

发送、上传或启用工具前，阅读[操作前检查可用性、费用与数据影响](/help/check-availability-cost-data)。遇到“待适配”“开关未开启”或“需要配置”等提示时，阅读[功能暂不可用时怎么办](/help/recover-unavailable-feature)。

## 常见问题

### 完全不确定从哪里开始怎么办？

先用模型完成一次真实任务。之后再判断需要重复的是角色，还是整个多步过程。

### 专家团为什么不单独列为一个模块？

专家团处理的是多角色协作，属于 Agent 下的二级功能。可以从 Agent 目录进入。

### Runtime 能直接修复失败任务吗？

Runtime 主要用于查看状态和定位问题。需要修改 Agent、工作流、MCP 或设置时，应回到对应模块操作。

## 限制

本文帮助你选择入口，不代表目录中的每项能力都已配置或可以真实运行。具体按钮、状态、费用和数据范围以当前页面提示为准。
