# R17第二版候选资格威胁模型

## 受保护对象

- R1–R16已资格产品链、MVP声明和父仓零耦合边界。
- 用户凭据、其他worktree、共享服务、容器、持久化数据和本机路径。
- 候选来源、许可证、执行证据和推荐结论的可追溯性。

## 主要威胁

- 浮动tag、子模块、归档或依赖换身导致来源不可复现。
- install script、原生二进制、动态下载或默认网络产生未披露外部影响。
- 候选读取父环境变量、绝对路径、Git凭据或其他worktree。
- 运行日志、临时路径、时间和随机值污染可提交报告。
- 以README、项目热度、mock或静态审计冒充可执行资格。
- 功能丰富的框架成为第二套世界状态、Runtime或任务权威。

## 控制

- 先验证commit、tree、许可证和依赖表面，再执行候选。
- 候选只在`C:\tmp`固定checkout中运行，使用空白专用环境、loopback和有界进程。
- 默认`--ignore-scripts`；必要生命周期脚本和Docker必须另行披露或审批。
- 普通verify离线；详细日志仓外，Git只保留canonical脱敏摘要和SHA-256。
- 硬门优先于评分；来源、许可、安全或权威边界失败即拒绝。

## 失败策略

任何身份歧义、未知许可、未披露网络、进程残留或越界写入均停止该候选，不修改产品路径，也不以部分证据形成推荐结论。
