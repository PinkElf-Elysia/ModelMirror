# R18第二版全景选型威胁模型

## 受保护资产

- R16已资格MVP、Creator默认入口、Godot产品场景和R1–R17正式合同。
- 父仓源码、共享栈、供应商凭据和其他worktree。
- 候选评估的来源身份、许可证闭包、可重复证据和结论置信度。

## 主要威胁

1. 热门度、README功能数量或用户点名替代运行与许可证证据。
2. 把架构参考冒充可执行依赖，或把Harness失败误判为候选不适合。
3. 候选安装脚本、动态下载、网络、子进程、任意写入或未知二进制越界。
4. 服务候选获得供应商密钥、共享卷、父API或第二套权威世界状态。
5. 商业产品基准转化为账号、试用或API调用。
6. 仓外证据缺失、换身或部分发布后仍生成正式推荐。

## 控制措施

- 固定commit/tree/archive/license/manifest并对证据做SHA-256绑定。
- 结论分为架构参考、可执行短名单和正式集成推荐；未知证据只允许`deferred/evidence-gap`。
- 候选专用空白环境不继承供应商变量；所有进程有时间、输出、PID和清理上限。
- 容器默认禁用；逐候选批准后才允许固定digest、`network none`、只读根和无共享卷执行。
- 商业候选只消费官方公开资料，不执行代码、不注册、不试用。
- 资格目录事务发布；失败不产生可被普通verify当作成功的摘要。

## 回退

逆序revert R18七个提交即可移除R18代码和文档；Git回退不删除仓外候选与证据，需按对应执行清单单独处理。
