# ADR 0018：R17只建立第二版选型基础

## 决策

R17采用“仓外可执行资格、仓内来源锁与脱敏结论”的隔离模式。候选只输出推荐、备选、延后或拒绝及切换条件，不接入Creator、Godot产品场景或Runtime。

## 原因

第二版候选横跨Godot插件、记忆平台和社会模拟框架。仅凭文档无法证明兼容性，直接集成又会在权威合同确定前形成依赖惯性。固定checkout和统一证据门可以在不改变产品链的情况下取得更可靠的选择依据。

## 后果

- R17可能得出“当前无候选可推荐”的有效结论。
- 后续轮次仍需在实际合同下验证推荐项；切换只按R17记录的触发条件进行。
- 任何正式vendoring、生产依赖或容器化服务需在后续轮次重新审批。
