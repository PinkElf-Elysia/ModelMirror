# 古代人生普通聊天中的地图 · 离线预览

从 studio 的普通古代卡聊天入口打开帝王命书，选明朝崇祯。在独立预览中，宿主按开局命中明朝世界书，按玩家的本轮输入匹配自定义条目，再把京师新到的文书和本轮允许查询的工具交给本地模拟叙事器。普通聊天的操作编号、发送接口、存档及读档沿用原路径。预览仅监听本机。

地图启用时，模拟请求保留最近配置深度内的对话。查询续答沿用首次请求已经装配好的系统消息和玩家输入，附上同编号的工具结果。世界书与地图回答里的地点重名时，工具返回不会再次触发世界书。工具请求、工具结果和原始模拟输出按请求编号保存在独立数据目录的 `archive-chat/ancient/offline/atlas-offline-evidence`。宿主先保存本轮候选检查点，普通故事提交核对正文摘要和上一检查点后，一起保存本轮正文与地图。渲染和重新打开会话读取已提交回合的检查点。

## 复验

从 `experiments/ai-rpg-engine` 运行以下命令。验收脚本为每次运行创建新的临时目录，输出目录名和样例会话编号。参数中的旧宿主应选用已有朝代世界书且尚未接入地图的版本。

```text
node ancient-card/frontier/ordinary-acceptance.mjs
node ancient-card/frontier/ordinary-legacy-check.mjs <原普通卡工作树的 studio/server.mjs>
node --test ancient-card/routes.test.mjs ancient-card/real-host.test.mjs ancient-card/frontier/story-map.test.mjs ancient-card/frontier/place-register.test.mjs ancient-card/frontier/place-register-pair.test.mjs
node ancient-card/frontier/ordinary-preview.mjs <本轮输出的 map-on 目录> <空闲端口>
```

进入该端口的 `/rpg-app/ancient/chat/`。浏览器复验运行 `ancient-card/frontier/browser-check.mjs`，指定 `FRONTIER_PORT` 和本机 `PLAYWRIGHT_MODULE`，并将 `ANCIENT_ORDINARY_CHAT`、`ANCIENT_PLACE_REGISTER`、`ANCIENT_STORY_MAP` 设为 1。这些浏览器脚本参数只选择验收路径，正常 studio 启动使用原有配置。

## 离线模拟与浏览器验收

- 同一命书、配置和九次玩家输入分别经过地图开启与关闭的普通聊天接口。开启时，核准后续写朝议一次直接生成。重启后询问东番，第一次请求查图，第二次请求按京师已知的三项登记续答。对照的输入、模拟输出及分项字节在运行目录的 `comparison.json` 中。
- 模拟茶事正文特意夹带未经登记的宁锦塘报。下一回合的查询请求能看见该段历史，工具却返回零份宁远文书。追问结束时已知记录与之前一致。这一项验证正文无法自行成为凭据，真实模型的文学表达和服从程度仍需另行验证。
- 浏览器由普通卡命书实际生成开局，经自由输入、拟旨、签发、送达、核对、确认、朝议、茶事、查图与读档续问共 13 回合。最后打开地图，核对大员、鸡笼与岛内各社。此前朝代世界书版本创建的旧存档亦能在新宿主续玩，维持普通模式。
- 上述九回合对照和浏览器操作使用本地模拟生成。下列真实批次使用独立存档和选定路由。


## 开局与续轮的地图增量

有地图绑定的普通会话在采用最终文本前统一校验尾部的地图增量。合规传闻关联本轮请求，仅登记为未经核实的转述。能够从正文完整分开的无效增量只剔除尾块，原始回复随请求证据保留，并记录拒绝原因。新生成的尾块残缺、重复或边界不清时，该回复不能提交。读取旧会话的助手历史时只将协议标记之前的正文投影给下一轮，不据旧标记补登记。

运行 `node --test ancient-card/frontier/ordinary-delta.test.mjs` 验证首轮和续轮。设置 `ANCIENT_OPENING_EVIDENCE` 为已保存的真实开局批次目录后，会复用该次原始开局正文，并从旧存档副本验证读档续写。

增量引文只在首个状态面板之前的剧情正文取证。可识别有说话者的直接引语和完整的具名转述句。短引文须对应完整话句；登记保留原文出处和同次发言的限定语。未获支持时，普通聊天保留正文及面板，地图不增加传闻。旧存档按已有检查点读取。

## 核卷与剧情续写

在启用地图的崇祯普通聊天里，玩家可以直接输入 `/查卷 宁远`，也可以用自然语言提问。命令直接读取本档。自然语言下，模型选择 `query_map` 并用 `use: documents` 核卷，宿主将所选地点截至当前时刻送达京师的记录按传闻、旨意、接收回执、已核准交割分别列示。单个查询省略用途也按核卷处理。只有传闻的地点仍会显示“尚无接收回执”。查无记录只能说明这一刻卷中无据。

核卷答复是可读的独立回合，并直接作为该回合的聊天历史。读档后紧接的剧情请求带有宿主保存的核卷时点、守方与依据编号，后到消息按自己的送达时点生效。核卷回合使用短答，不生成原卡的长正文和六组面板。需要人物反应、剧情或行动时，模型可选 `use: scene`，继续使用原有工具续答、面板及确认流程。原始供应商消息与本地查询结果分别随请求留存。

本次用此前实测的原始工具调用离线回放，覆盖空卷、只有传闻、真实回执、异地回执、尚未送达、多地查询及读档续谈。可用 `node --test ancient-card/frontier/register-evidence.test.mjs` 运行。重放真实失败输入时，先将 `ANCIENT_OPENING_EVIDENCE`、`ANCIENT_QUERY_EVIDENCE` 分别指向上表第二、第三批次的 real-01 目录。该回放的供应商调用数为零。随后单独执行同档同问的一次真实路由补测，见上表第四行。该样本覆盖自然语言选择核卷；通用路由命中率和自由剧情的事实一致性仍待更多样本验证。旧历史按原样保存。


### 最终验收与证据

核卷补测在 `.rpg03-work/ordinary-docket-gemini/` 下保存了完整模拟和真实批次。派发前比对消息、工具表、工具选择策略和参数。一次真实请求共 16,776 token（输入 16,600、输出 176），桥接耗时 5.907 秒。原始流、实际输入、宿主采用结果、前后登记、派发审计与凭据清理记录分别在 `real-01/` 内；原始材料仅在本地保留。模拟显式选取 documents，真实模型也显式选取了该用途。该回合没有第二次模型续写。

合并前离线检查覆盖 15 项古代卡路由、宿主、事件、普通聊天及读档回归；模拟地图开关各走九回合。普通配置默认关闭该实验，回退时使用旧入口，独立验收存档按绑定版本保留。模型在自由剧情中可能补写无据官报、漂移年份或偏离篇幅，本轮仅就上述样本作出结论。
