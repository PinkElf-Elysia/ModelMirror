# 古代卡地图剧情回合（独立离线预览）

在 card-replica 目录运行 `npm.cmd run build -- --outDir ../.rpg03-work/story-map-dist`。在引擎目录用 PowerShell 启动：

```powershell
$env:ANCIENT_STORY_MAP='1'
$env:FRONTIER_PORT='19192'
node ancient-card/frontier/server.mjs
```

从崇祯命书开局，通过聊天工具配置用户系统词和世界书。未配置时仅取上一对剧情消息；配置时沿用现有配置深度，超出窗口后单独保留命书。宿主在世界书匹配之后附上京师新收到的事件。一次回合只装配一次；二次请求只追加原生工具调用和对应结果。此预览暂不支持助手预填充。

确认交割后输入“接着写朝议”，再闲谈一轮、询问“东番现在各归谁？”。状态只从存档的已确认事件取得。离线模拟另支持输入“记下传闻：商人说鸡笼换了旗，尚待核实。”：正文可附一条地点增量，宿主校验地点及引用，保存为未核转述并关联本回合，不改守方。此结构校验不能验证传闻真伪。

运行 `node --test ancient-card/frontier/story-map.test.mjs` 核验已配置的实际发送信封与工具续答。浏览器验收使用相同端口，另设 ANCIENT_PLACE_REGISTER=1 和 PLAYWRIGHT_MODULE，然后运行 ancient-card/frontier/browser-check.mjs。本模式复用古代卡聊天界面、自定义配置中间件和世界书引擎，以独立存档、确定性生成器运行。


## 朝议输出上限实测与玩家验收

崇祯命书会话在本地核准大员交割后，玩家输入「接着写朝议。」。宿主附入京师已收到的交割记录，保留自定义系统词、世界书配置及原生工具自动选择。此前另一次读档查询用「东番」触发「青册」并调用地图工具；下表两次测试的玩家输入均为直接续写。用于比较的地图说明已经修订为无新增传闻时只省略地图增量，同时要求正文后按原顺序写完六组面板。

两次真实请求均经 OpenRouter 的 Google AI Studio 标准端点，模型为 `google/gemini-3.8-flash`。8192 实测前先完成本地模拟派发；收尾时再次比较两份已保存的供应商请求，唯一变化为 `max_tokens`。每批各派发一次，均无工具调用、自动重试或备用切换。

### 世界状态与后续优化

两次测试的交割均已由本地玩家确认。续写前后大员登记为明、鸡笼为西班牙、岛内各社自治，均无新增交割。8192 样本的「世界风云」补写了宁锦游骑、请发冬衣的兵部塘报及市井流言。这些细节随正文进入聊天历史，宿主没有相应送达凭据，也没有据此写入地图。后续应验证在读档、总结和再次询问时，能否持续区分有凭据的获报、人物转述及叙事补写。本轮仅登记此项。
