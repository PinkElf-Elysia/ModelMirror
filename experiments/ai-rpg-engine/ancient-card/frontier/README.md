## 玩家验收

在本机预览的古代人生开局页选择「帝王之路 → 明 → 崇祯帝朱由检」。命书带入原卡聊天输入框后可编辑，点击发送才创建第一回合。地点固定为北京、山海关、宁远、锦州。开局登记与关报取自探索线场景，接防和交割为本档推演。

1. 在聊天中问「京师现在能确认宁远的情形吗？」。京师只能引用上次登记，宁远属明。
2. 发送「推进至关报抵京」，再问同一句。京师能引用营中欠饷鼓噪的关报，失城仍未核实。
3. 发送「请依据关报拟定宁远城防移交之旨。」和「确认这份旨意」。拟旨和用印均延续原有登记。
4. 发送「推进至接防回执送达」「请依据接防回执核对宁远交割。」，再发送「确认这份交割」。只有最后的确认将宁远从明改为后金。待确认时也可以撤回提案。
5. 关闭页面，由开局页的会话历史重开原存档，再问「接上次，告诉我宁远现在归谁。」。此时才展开地图，与聊天正文、京师边务簿对照，三者应显示宁远归后金，另外三地属明。

上述操作都可在普通聊天框中发送。边务簿下方的建议可一键带入草稿，再由玩家发送。递报时点按本档操作推进。

## 运行边界与来源

- 主线工作基线 `e4a3c448` 包含已合并的 R10（#512）。四节点与原生查询、行动提案来自探索线 [PR #514](https://github.com/PinkElf-Elysia/ModelMirror/pull/514) 的 `a2c773a4`，同路径的 `world.mjs`、`agent.mjs` 逐字复用。预览使用自己的会话宿主。
- 开局沿用原版表单、命书、聊天输入与会话历史。每次模拟生成均经古代卡 `assemble` 组装作者系统词、历史回合、玩家原话，追加本档职责与可见性约定。查询原生消息和工具结果仅在当轮续答中传递。系统词 SHA-256 为 `4a7891e458fdd2a418e1e9de2f1fac5a962b68cf995a251fa63f5cfbf01a001b`。
- 一个 `SessionRecords` 记录容纳正文、工具轨迹、发生时刻、每个接收方的送达时刻、提案和交割结果。模型只取得京师可知的材料。普通聊天通过受限工具查询或拟案；推进递送、批准、撤回由宿主处理。公开会话接口排除未送达文书与内部轨迹。
- 验收覆盖崇祯的京师视角。营中收报时间用于校验隔离。全国、持续模拟、通用人物运行及正式环境插件组合留待后续。离线叙事采用有限语句和确定性工具选择，证据只支持此链路的装配与一致性。

## 在独立工作树复验

工作目录为 `experiments/ai-rpg-engine`。先在此目录及其 `card-replica` 子目录安装各自锁定的依赖，在 `card-replica` 运行 `npm run build`。以下是 PowerShell 操作。

```powershell
node --test ancient-card/frontier/session.test.mjs ancient-card/routes.test.mjs ancient-card/real-host.test.mjs
$env:FRONTIER_PORT='18975'
node ancient-card/frontier/server.mjs
```

预览只监听 127.0.0.1，端口占用时会报错。存档保存在本独立工作树的 `experiments/ai-rpg-engine/.rpg03-work/ancient-frontier-v1`。浏览器验收在另一终端使用相同端口；设置 `PLAYWRIGHT_MODULE` 指向本机 Playwright 模块，运行 `node ancient-card/frontier/browser-check.mjs`。脚本实际填写原卡命书、发送十回合、关闭页面、从会话历史选回存档，续写后首次展开地图，输出可重开的验收地址。

四项 Node 检查通过（含原卡离线回归、存储重开、并发重复确认与过期拒绝），TypeScript 检查与 Vite 构建通过。上述离线验收使用模拟供应商。随后完成了三组 Gemini 真实查询与续答，交割由本地宿主确认。[首轮实测、证据与后续分工](../../../../docs/ai-rpg-experiment/harness/ANCIENT-FRONTIER-CLOSEOUT.md)
