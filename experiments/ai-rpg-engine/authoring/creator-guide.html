从设定到可以游玩的作品

做出你的第一张角色卡

先让人物和开局成立，再添加世界书、图片与互动。每个示例都对应工作台中的字段，可以直接用于本地练习。

保存、刷新预览和发布本地版本都不会调用模型。只有点击发送才进入调试；标有“离线演练”的入口使用固定回复，不产生模型费用。

从空白作品开始

  1. 新建作品点左上角文件夹图标 → 作品管理 → 新建空白作品，填写名称。基础设置中选择语言、男性向或女性向；标签与封面可以稍后补充。
  2. 写最小设定在基础设置的“提示词”填入下方示例。前后置词可以留空。
# 世界
雾港的灯塔昨夜熄灭，港口仍在正常生活。
# 角色
守塔人林舟谨慎、惜字如金。玩家是一位携带旧地图的旅人。
# 主持规则
描写玩家行动造成的可见变化。不要替玩家作出重大决定。
未证实的消息保留为说法，约定保留为计划。
# 回复要求
使用第二人称。先写现场，再给出人物反应，最后留下可继续行动的线索。
  1. 做一个开局在其他设置 → 开场白 → 编辑，添加“我站在雾港灯塔下，向守塔人展示旧地图。”并保存。右侧“开场与指令”可以选择它填入输入框。
  2. 保存并发布本地版本点顶部保存，再打开作品版本 → 发布当前草稿 → 发布版本。校验失败时按字段提示修正。
  3. 建立调试会话点右侧添加模型，选择作品版本，再选择剧情模型和它支持的参数。检查输入、模式和额度后手动发送。离线回复只用来检查流程，不能证明提示词效果。

手机上点顶部“预览”进入右侧工作区；关闭预览或按 Esc 返回编辑。离开前确认作品名称下显示“已保存”。

每段文字应该放在哪里

字段放什么发送方式
名称、标签、简介题材、玩法概述和整理信息不自动加入模型请求
详细介绍 / 开局页面玩家看到的介绍、角色表单、选择按钮页面不自动成为提示词；采用开局文字后才进入输入框
提示词世界观、角色、规则与回复格式作为系统提示词 system
前置词 / 后置词每轮都需要的短要求各装配一次，位于本轮 user 输入前后
世界书按关键词出现的具体设定命中后加入选定的提示词、前置词或后置词
内置 CSS模型回复的颜色、布局与动效只影响显示

示例：主提示词写“守塔人不知道信件作者”；前置词写玩家固定身份；后置词写“保留悬念，不替玩家决定”。玩家输入“我询问信件的来源”。不要把完整角色设定只写进简介，也不要把同一条要求在三个字段反复复制。

历史中的玩家输入不重复包裹前后置词。摘要和记忆属于启用插件后附加的历史资料；它们与作者设定分别保留。

让世界与角色容易执行

  • 世界：写清时间、地点、主要矛盾和日常规则。把只在特定地区用到的长设定移到世界书。
  • 角色：除外貌和性格外，补充知道什么、想要什么、与玩家的关系、说话方式。用一个短对话展示语气。
  • 玩法：说明行动会造成什么变化，以及哪些选择必须留给玩家。状态数值若由模型描述，不能当作已经接入确定性的规则引擎。
  • 输出：写明人称、场景重点、段落结构和大致篇幅。增加输出 token 上限只提高可用容量，不保证回复变长。

用 Markdown 标题划分世界、人物、规则、示例，保留有意义的空行。调试时每轮只改变一个要求，保留输入和原始回复，区分设定遗漏、模型内容与显示问题。

18 项工具怎么使用

编辑框保存的是源码。工具在当前选区或光标处插入文本；它们不会把提示词转换成另一份富文本，也不会自动删空行。

工具操作与结果
标题打开 H1–H6 菜单，选择级别；在光标前插入标题位置。
加粗、斜体、下划线、删除线先选文字再点击。未选择时插入成对标记，继续在中间输入。
无序列表、有序列表、引用为选中的行添加标记；长段落先按行整理。
换行插入换行标记，用于需要明确断行的位置。
行内代码、代码块区分一句中的代码与多行示例；示例中的标签不会因此变成可执行脚本。
表格在格子菜单选择行列；之后直接编辑生成的源码。
图片、链接在弹窗中填写或选择资源，确认才插入；取消 / Esc 保留原文。
清空需要确认，取消保留文字。清空后仍可撤销。
撤销、重做恢复本编辑框的文本操作；没有可恢复记录时按钮禁用。
全屏展开当前编辑框，Esc 退出。适合长提示词与开局源码。

中文输入法组词期间先完成输入，再点击工具。Ctrl / ⌘ + S 保存作品；弹窗尚在编辑时先确认或取消该弹窗。

让玩家填写角色与开局

把下面的小表单粘贴到基础设置 → 详细介绍 / 开局页面。点右侧开局页面 → 刷新，然后修改文字并点“使用这个开局”。工作台会显示待采用的内容；确认后填入输入框，仍由玩家发送。

<section class="harbor-opening">
  <h1>雾港来信</h1>
  <p>你带着一张旧地图，来到灯塔门前。</p>
  <label for="opening-text">你的开局</label>
  <textarea id="opening-text">我是旅人林岚。我向守塔人展示旧地图。</textarea>
  <button data-rpg-input-from="opening-text">使用这个开局</button>
  <details><summary>查看背景</summary><p>灯塔昨夜熄灭了。</p></details>
</section>

已有完整 HTML/CSS/JS 时，可以直接放入详细介绍；也可展开“独立开局源码”分别编辑。独立 HTML 非空时优先使用，不会与详细介绍拼成两个开局。

编写开局脚本与复制按钮

作者脚本可操作受限 DOM、表单、折叠与随机选项。宿主不向它开放网络、凭据、本地存储或模型调用。脚本错误会在预览诊断中说明。

rpg.setInput(text)、rpg.saveDraft(text)、rpg.copyText(text)提出文字交接，由玩家按钮触发并在工作台采用。静态按钮也可使用 data-rpg-input、data-rpg-copy 和相应的 -from 属性引用表单元素。

异步复制在玩家确认成功后才继续；取消应保留表单。预览最多运行十分钟，过期后手动刷新。模型回复中的脚本始终不执行。

按关键词补充设定

  1. 打开世界书设置 → 新增，给条目取名“灯塔”。输入关键词“灯塔”，按回车或添加。
  2. 选择用户和 AI、格式“或”、影响范围“提示词”。正文写“旧灯塔有一扇蓝色小门，守塔人保留着昨日的访客记录”。
  3. 在输入中提到灯塔，再核对匹配结果。没有命中时不应携带这条资料。
参数如何生效
插入顺序0–9999，小数值在前；同序按列表顺序，最后以稳定标识兜底。
扫描深度0 只看本轮输入。1–20 额外看相应数量的完整历史回合，再按用户 / AI 过滤；独立于实际发送窗口。
与 / 或“或”命中一个关键词即可；“与”需全部关键词出现，可分布在扫描范围内。字面匹配不区分大小写。
正则在隔离环境限时匹配；非法表达式或超时会报告问题，不执行源码。
触发概率关键词匹配后，决定条目本次是否生效。100 表示总是生效。
概率正文条目生效后按权重选一份正文。0 权重不参与；全为 0 时不能发布。

练习：三种天气

把正文切到“概率”，添加晴天、阴天、雨天，权重都填 1。点归一化得到 33.34、33.33、33.33，合计 100.00%；可撤销。权重决定三份正文的相对机会，与上方触发概率分开计算。

先匹配前置词、后置词的世界书，再匹配主提示词的世界书。条目不会互相触发，也不会扫描摘要和记忆。同一次发送的匹配和抽签结果保持不变，恢复记录时不会重新抽取。

图片、音乐与资源引用

打开创作图库上传图片、命名和分组；封面、桌面背景、手机背景与 CG 可复用图库图片。关闭“使用图库图片”后也可从本机选择。背景音乐上传 MP3，播放器支持播放、暂停与循环；浏览器可能要求先手动点击播放。

在源码中使用资源别名，例如 <img src="asset://harbor" alt="雾港码头">。别名必须对应当前作品的资源。可在更多 → 作品资源清单中核对别名、文件和缺失引用。

已有代码引用外部图片怎么办

先把有权使用的图片保存到本地图库并关联到作品。在更多 → 查看 / 编辑配置 JSON 中，设置 settings.presentation.imageMappings；不要在提示词中填本机绝对文件路径。

"presentation": {
  "scope": "standard",
  "imageMappings": [
    {"source": "https://example.invalid/harbor.png", "alias": "harbor"}
  ]
}

这是字段片段，不是完整作品包；合并到已有配置，保留其他字段。source 必须与源码 URL 精确一致，alias 必须是已上传资源。通用作品用 standard；依赖原站容器选择器的已有样式可使用 afengy 兼容作用域。预览不直接联网取图。

回复样式、折叠和普通 CG

模型回复可显示 Markdown、HTML/CSS 和静态 SVG。把结构示例写进主提示词，把样式放进其他设置 → 内置 CSS。用同一份完整原文在右侧“样式回放”检查，避免把内容缺失误判成样式丢失。

<section class="harbor-reply">
  <h2>灯塔门前</h2>
  <p>守塔人接过地图，指向码头的方向。</p>
  <details><summary>场景信息</summary><p>清晨，海雾尚未散去。</p></details>
</section>
.harbor-reply { color: #22394d; background: #eef4fa; padding: 20px; }
.harbor-reply p { line-height: 1.9; }
.harbor-reply summary { cursor: pointer; padding: 12px 0; }

纯 CSS 可实现弹幕、翻面与图片展开；回复不执行 JavaScript。样式不会修改模型原文或污染工作台。检查关闭美化、短回复、长回复和手机宽度时是否仍可阅读。

普通 CG 练习

  1. 其他设置 → CG → 新增，关键词填“码头”，区域映射选择聊天，选一张本地图片。
  2. 选择概率图片时给各图片设置权重；切到背景图片时，命中会切换聊天背景。
  3. 粘贴包含“码头”的完整回复，点生成本轮 CG 回放。刷新复用已有选图，不能用刷新反复抽图。

实际对话在完整回复保存后记录 CG 结果，刷新和分支回放复用它。手动样式回放与正式对话分开；临时回放记录保留十分钟，过期或重启需明确重新生成。普通 CG 只随剧情显示。

制作一张可以收藏的 CG

  1. 在常规图片下打开「设为特殊CG」，填写名称。可以单独选择在未解锁时显示名称、提供文字提示。
  2. 为条目设置触发关键词并选用本地图片。每部作品最多标记 20 项，切到概率模式会保留已有标记与名额。
  3. 发布这个作品版本后，玩家从「实际对话 → CG 画廊」查看进度。首次在已完成回合实际展示的图片可解锁，再点「查看」或「剧情回顾」。

新会话从锁定状态开始，分支继承分支点之前的收藏。编辑器回放、刷新、查看提示和回顾均不调用模型。

让角色与世界状态随剧情更新

基础设置 → 使用变量面板。先编辑数据骨架，再用面板皮肤设计显示效果，最后在变量提示词中说明哪些事件会改变状态。预览初始面板只渲染本地数据；保存后发布一个新版本，再建立会话。

1. 数据骨架：初始 JSON 对象

{"地点":"雾港码头","体力":80,"背包":["航海图"],"任务完成":false}

字段名可以使用中文。初始字段及其类型需要保留；null 表示暂未确定类型，空数组允许后续加入不同类型的元素，非空数组以首项约束每项，初始数组也需满足这个结构；不一致时会在预览或发布时提示。允许新增字段，但新增字段不会变成初始骨架的必填项。此为本地规则，不是 JSON Schema。

2. 面板皮肤：HTML、CSS 与 Handlebars

<style>.status { padding:16px; color:#183847; background:#f2f8fa; }</style>
<section class="status">
  <h2>{{地点}}</h2>
  <p>体力：{{体力}}</p>
  <ul>{{#each 背包}}<li>{{this}}</li>{{/each}}</ul>
  {{#if 任务完成}}任务已完成{{else}}任务进行中{{/if}}
  <button data-panel-copy="{{地点}}">复制地点</button>
</section>

支持嵌套字段、if / unless / each / with，以及 eq、ne、gt、gte、lt、lte、and、or、not。例如 {{#if (gt 体力 0)}}可以继续行走{{/if}}。普通插值会转义 HTML。模板结果仍经过隔离清理，不执行脚本，也不能访问网络或宿主存储。图片使用本地 asset://资源别名。

复制短文字使用 data-panel-copy="文字"；复制较长内容使用 data-panel-copy-from="节点id"，会读取同一面板内该节点的文本。复制成功时按钮短暂带有 data-copied，可用 CSS 表示成功。点击复制不会发送剧情。

3. 变量提示词：什么时候改变

巡查消耗 10 点体力。抵达灯塔后加入铜钥匙并完成任务。
只记录已发生的变化，尚未兑现的计划不改变状态。

每轮由宿主在本轮 user 消息末尾追加变量要求和当前状态，作者 system 保持原样。剧情模型同时返回剧情与一份 <variable_panel>完整 JSON 对象</variable_panel>。这份标签协议为本地约定；原站未公开的更新协议不作等同声明。

完整剧情落盘时校验并原子保存新状态；下一轮携带最后有效状态，独立于 M1 历史窗口。无变化不会增加状态版本。缺失、非法、超限或类型冲突会保留上一份状态并显示原因，不自动修复或额外调用模型。截断和未知结果不推进状态；恢复只核对原操作。

实际对话中查看对应回合的变量面板和“查看状态数据”。只有通过校验的变量标签会从展示副本中隐藏；原始回复始终保留，世界书、摘要和记忆继续读取原文。分支继承分支点状态，之后各自更新。

容量与版本

JSON 最多 64 KiB、2000 个值节点、16 层；模板最多 200000 个 Unicode 字符，变量提示词最多 20000 字。渲染受限于独立 Worker、超时、内存和输出容量。关闭面板保留源码；发布新版本仅影响新会话。真实状态更新随剧情调用完成；请核对变化是否符合已发生的事件，格式合法不等于内容一定正确。

开场、预设对话与快捷指令

  • 开场白：为不同路线提供可选开局，在页内编辑后保存。
  • 预设对话：保存提问、回答与可选开场白，供开局使用。折叠前确认当前内容。
  • 快捷指令：最多十项，把常用行动与短命令配对。选择后填入输入框，仍由玩家发送。
  • 下一步建议：开启后，把完整回复中的建议列表变成按钮，不需要额外模型调用。
<suggested_questions>
1. 展开旧地图
2. 询问守塔人昨夜的情况
3. 前往码头
</suggested_questions>

屏蔽词在发送前检查当前输入。显示正则只修改展示副本；摘要、记忆与世界书仍读原始历史。先用一个命中和一个不命中样例检查替换，非法或超时规则不能以部分结果冒充成功。

模型、参数与五个会话插件

选择模型后，只显示其实际支持的参数。温度与 Top P 调整输出变化程度；最大回复长度决定允许的上限；它们都不能保证某一种文风或篇幅。不支持的参数不会被悄悄忽略。

剧情、摘要、记忆各自选择模型。切换剧情模型不会连带更换另两项，也不会自动认证模型。模型暂不可用时，先核对控制面目录与资格。

插件用途与启用要点
模型选择器管理会话的剧情模型与参数。
历史窗口限制携带的历史回合。作品默认记忆长度是建议，采用时需会话授权。
自动总结较早历史变成摘要，保留最近一回合原文。
记忆宫殿从原始剧情整理可编辑条目，按关键词召回。人工条目默认保护。
分支存档从已完成的回合另开路线，继承当时快照，不继承后来的修订或会话授权。

让每轮都记得你的回复要求

  1. 在“会话调试”展开“持续要求”，填写需长期保持的视角、篇幅或功能开关。
  2. 点“保存要求”。之后每轮会携带当前内容；保存本身不调用模型。
  3. 需要改变时在这里更新。聊天输入不会自动改写此处；取消或 Esc 放弃尚未保存的编辑。

持续要求属于玩家要求，进入 user 消息，不修改作者主提示词。历史窗口裁掉早期对话后它仍会携带；已发送的请求与分支保留当时版本。清空后保存可停止携带。最多 8000 字；遇到冲突先刷新核对，遇到结果待核对先恢复原操作。

插件安装与会话启用是两步。先在会话插件中检查安装状态，再明确启用；自动总结和记忆宫殿需分别选择模型。一起启用时，会先生成总结，再整理记忆；完成后即可继续发送。

发送前核对本次预计调用上限和剩余额度，包含剧情及已启用插件的独立调用。创建作品、复制、发布和分支不会增加额度。生成效果以实际回复为准，可以在记录中检查并调整设定。

保存、发布与导出

本地发布会让作品自动出现在本机故事馆。保存草稿不会上架；再次发布更新同一入口，已有会话与旧版本保留。

  1. 先点“保存作品”，确认显示“已保存”。
  2. 点“作品版本”→“发布当前草稿”，核对后点“发布版本”。
  3. 关闭弹窗，点左上角“镜 · RPG”返回故事馆。新作品会显示发布版本号；也可点首页“刷新作品”。
  4. 点作品的“打开作品”进入固定版本的游玩页。配置模型与会话后再发送，不会自动生成剧情。

简介和封面可以稍后补充；没有封面的作品采用统一文字占位。上述发布只发生在本机，不会上传到外部网站。若从工作台直接地址进入，请回到原故事馆标签页；从故事馆打开工作台时会保留返回入口。

保存更新草稿。自动保存默认关闭，启用后每三分钟保存；编辑弹窗打开、内容冲突或结果待核对时暂停。

作品版本 → 发布当前草稿生成不可变的本地版本。更改草稿后需要发布新版本，并为新版本创建会话；已有会话继续使用原版本。这里的发布不会公开到外部网站。

导出配置下载结构化配置；更多 → 导出完整作品包包含资源，适合备份和迁移到另一份本地库。导出已保存内容，未保存修改要先保存，或使用“导出本页草稿备份”。

导入先展示校验问题，再选择新作品或替换当前草稿并确认。失败不覆盖原作品，未知字段会明确报告；不要把报错字段随意删除来强行导入。

遇到问题，先看哪里

改了提示词，回复却没有变化

检查内容是否写在提示词而非简介；保存后发布新版本，再在模型设置中选用新版本。旧会话保留旧版本是正常行为。离线演练无论如何修改提示词都使用固定回复。

图片丢失、CSS 不生效或折叠不动

先查看完整原文是否包含对应标签；检查资源别名、精确 URL 映射与作用域。开局 CSS 和回复内置 CSS 用在不同地方。展开预览诊断；不要依靠模型脚本实现回复中的交互。

世界书或 CG 没有触发

核对启用状态、扫描角色、关键词、与 / 或、扫描深度、触发概率及权重。CG 需要完整回复；正则不能以错误或超时结果继续。比较实际命中记录与原文，不用“看起来没变”代替核对。

显示“结果待核对”，能再发一次吗

先点恢复原操作或核对原操作。恢复查询原请求，不换编号重发。未确认结果仍保留记录并阻止重复派发；明确失败后再按提示处理。

显示“剧情请求未发出”，但额度减少了

这是发送前已确认失败，输入仍保留。打开“对话与记录”，在“未完成的剧情请求”中查看原因；展开“请求详情”可核对派发状态、诊断和原始输入。DNS 或连接预检错误需要先检查运行服务的网络设置，刷新页面只读取状态，不会重新发送。较早的记录可能只保留通用预检失败，页面不会替旧记录补写原因。

如果看到“模型服务拒绝了这次剧情请求（HTTP 403）”，打开请求详情核对状态。服务商给出具体原因时，页面会显示权限不足、内容策略、模型拒绝或安全规则。只有状态码时，请按发生时间到服务商的请求记录中排查。

已派发后失败、取消或结果未确认的请求仍计入额度；控制面明确确认未派发时，会保留失败回执并释放本次占用。未开始的后台任务会释放预留。只有查询不到记录还不足以释放额度，需继续核对原操作。较早的验收入口可能保留旧计数规则。记录中的“额度如何计数”可查看当前数值。

另一个标签保存了修改

先导出本页草稿备份，再选择载入服务器版本。直接重复保存不会强行覆盖另一标签。不要在尚未备份时刷新丢弃编辑。

发布前检查

把一部作品交给玩家前，按下面的顺序检查。

  1. 核对提示词、每轮前后置词、开局页面、回复样式、图片和音乐是否完整。
  2. 检查基本资料和媒体引用，确认所用素材可以使用。
  3. 试用世界书、开场白与快捷指令，核对每项设定出现的位置。
  4. 在桌面和手机预览表单、折叠栏、复制和输入按钮。
  5. 用完整回复检查图片、CG 与不同显示选项。
  6. 保存、刷新并发布本地版本。导出完整包后，可导入另一个本地库核对文本与素材。

预览确认的是显示与交互。正式游玩时，还应检查模型回复是否符合设定，并根据实际效果调整提示词。

作品可以呈现什么

你可以为作品配置开局页面、世界书、回复样式、CG 图片、音乐、变量面板和会话插件。特殊 CG 支持解锁记录、收藏画廊与剧情回顾；变量面板按设定的数据和模板显示角色状态。

离线预览使用固定样例，适合检查布局与操作。模型回复中的触发效果，需要在正式游玩时检查。
