# RPG05 输出格式方案评审与最小修复

本次授权：方案评审与最小修复。只处理 RPG05；不调用模型，不改 RPG04 提示词、合同或原始证据，不发布。

## 已核验问题

- 槽位5：合法JSON，但 informationModules[3] 用 fieldRef 替代 moduleRef。
- 槽位6：与槽位5的系统提示词、当前数据、输出合同、世界书和已提交历史相同；当前回合的独立ID不同。输出通过。不能把两次当成字节完全相同的请求或稳定性统计。
- 槽位7：缺少最后闭合括号。仅内存假设补齐后，memory.ltm 与 memory.saves 信息字段仍为 string，卡包要求 list。未保存修补输出或提交。
- state.rpg04.memory.ltm/saves 是 shortText；field.rpg04.memory.ltm/saves 是 list。它们是不同合同，名称相似可能引发模型混淆，因果尚未验证。不得按名称推断通用映射。
- 输出1450/1894 token，低于4096；冻结适配器成功要求stop、route_receipt、DONE。终止依据为代码条件和通过回执推断，没有逐事件原始SSE归档，不能声称供应商原始流已逐字验证。
- 现有请求是普通文本聊天；Schema放入上下文，适配器未发送response_format。模型原生结构化输出与该受控路由组合的支持情况尚未验证。

## 方案比较与决定

| 方案 | 结论 | 原因及边界 |
| --- | --- | --- |
| 自动补括号、字符串转数组 | 不采用 | 会改写模型输出，且补括号后仍有类型错误；掩盖真实验收失败 |
| 继续加token或重复派发 | 不作为修复 | 没有当前上限截断证据；单次重试成功不能证明稳定 |
| 私有证据分层诊断 | 本批实现 | 在RPG05封装内记录传输、JSON、卡包合同、回合绑定结果，不影响准入和正文 |
| 状态与展示的显式映射 | 设计候选，不接运行链 | 类型区别由资源声明确定，不能把同名字段自动互转；需要明确空值/多条记录/分行文本/有损转换策略。无可靠结构时不转换 |
| 受控结构化输出 | 优先后续评审 | 先确认官方模型与模镜/newAPI路由支持；若支持，为本轮卡包生成类型约束。完整JSON Schema不能未经兼容检查直接发送。仍须保留原始输出、既有合同和绑定校验 |
| 精简或重写提示词 | 不在本批 | 触及冻结RPG04提示词，需明确边界及版本审批；本轮不能悄悄改写 |

## 已实现最小修复

新增 ui-host/output-diagnostics.mjs，真实适配器写入私有 response.N 记录的 outputDiagnostics。原始 report、请求、账本 report hash 和提交规则不变。只保存代码、字段路径、hash、长度及证据等级，不复制正文进诊断。

JSON无法解析时终止该诊断层，不偷偷补齐后报告为可接受。传输失败不伪造JSON失败；绑定不一致单独标记。terminalEvidence 明确为 inferred，rawSseCaptured 为 false。诊断不经 publicOperation 返回页面，无界面布局改动。

测试包含缺括号、错误module键、两类list字段、绑定错配、传输失败、原始字节保持和真实封装证据落点；全部mock/offline。对历史真实响应的离线重放必须新建旁证文件，绝不改历史response、账本或原冻结清单。
