# GLM 用户提供优化版审查

## 证据边界

本材料分类为 `user_supplied_generated_revision`：用户粘贴了 GLM 生成的完整“优化版”和十一条修改清单，本代理未调用模型或核对原会话。它是模型基于先前材料作出的改写，不是原始卡片来源，也不能独立证明隐藏配置。本文只用它逆推候选模块、比较设计取舍，不照搬文本或数值。

## 主要删改与新增

- 删除 Unrestricted、CatnipDimension 等越权或元声明；将“无情执行端”改为流程执行者并保留淡个性。
- 增加晋升算法：E→D 首事件加 10%，后续节点加 5–15%，每回复不超过 15%，S 到 100% 结算。这是 GLM 新增规则，不能逆推为原版机制。
- 移除未定义的 t-pink；原材料中的 t-rainbow 使用仍不一致。
- NPC 情绪改为有铺垫才产生敬畏或敌意，禁止无端臣服、神化或绝望。“禁止替玩家决定”目前只在用户转述的批评答复中被提及，不能写成这份优化正文已经包含独立明文。
- 存档仅随玩家指令创建或更新；建议 E 改为欲望、野心或高风险方向；正文禁用面板术语。
- 保留 800–1200 字正文、约 1000 字推演、不得省略的全量静态状态、每回合五商品、STM 满 7 条压缩到 LTM、完整 HTML `details` 模板和 NPC 隐藏信息 popup。

## 主审评估

1. 要求顶部栏起手，同时要求思维链位于最顶端，输出顺序自相矛盾；任何强制思维链都不采用。
2. 声称改善 token 使用，但仍强制全量静态字段、约 1000 字推演、长正文、五商品和完整 HTML，缺少预算证据。
3. “推断玩家真实意图偏咸鱼且无恶意”可能替玩家定义意图；只能依据明确输入和可观察行为。
4. 晋升比例是生成版新增且会改变持久状态，不可逆推原版，也不进入通用核心硬编码。
5. NPC 秘密放入可折叠 HTML 只改变客户端展示，不构成模型侧保密；不可见信息必须在上下文装配前隔离。
6. NoMeta 并非全部无用；应允许明确的角色外查询、规则说明和无剧情推进的信息请求。
7. 维护已有存档与禁止主动创建存档并不冲突：宿主可保存玩家明确提交后的记录，不得擅自新建剧情存档。
8. “原版 60/40”或“保护 95%”没有度量定义、样本或评测，不能用于验收。
9. 系统冷静、克制的主持风格与 NPC 具有铺垫充分的情绪不矛盾；应分别约束叙事者和角色。

补充来源核对：末尾“正文FORBID: 面板原词/【】标记/属性术语”在更早的 DeepSeek 历史复述中已经出现。GLM 修改清单的“按本次新要求固化”不能证明该要求由它新增；原版重建保留历史末尾位置。见 RPG04_DEEPSEEK_ORIGINAL_TRANSCRIPT.json 的 tail_requirements。

## 后续自主优化候选

本节只记录后续 author-created 优化候选，不决定当前主 system 文本，也不属于原版系统提示词重建。

可考虑职责分层、静态资料与动态状态分离、条件化 NPC 反应、显式手动触发，以及叙事、信息、状态提案、不确定性和建议的结构化输出。应删除越权授权和无依据玩家意图推断；模型输出仍是待验证提案。

不直接采用固定等级算法、固定字数、固定五选项、积分/商店/死亡/继承等经济规则、强制思维链、每轮商店刷新或内建 STM→LTM 记忆引擎。它们只有在卡片明确声明且经过独立验收时才可作为卡片机制；可替换记忆继续属于可选插件。

世界书与文风的基本形式、代表正文和装配方式仍无充分样例，本材料不能关闭 04B1 的该证据缺口。
