# RPG-04 主持与上下文设计蓝本

## 可采用的共同骨架

现有用户历史样例及 WEB-01/03/04 返回共同支持一个可消费的模块骨架：主持身份与职责 → 世界及卡片规则 → 当前时空和事件 → 叙事正文 → 玩家/NPC 信息 → 系统与世界信息 → 补充状态、记忆 → 非穷尽建议。状态更新应来自已经发生的事件，建议不代表玩家已经选择，存档等卡片机制须由玩家明确触发。

这些材料均为 `model_return_unverified_source` 或跨探针推断，不是隐藏原文或当前界面规则。GLM 样例尤其是对用户先粘贴的 DeepSeek-like 长示例进行删改补全，不能视为独立跨模型证实；其中 World 信息输出面板也不能冒充隐藏世界书。共同骨架足以指导自主设计，不必等待逐字原文真实性得到证明。

第三项材料是用户报告的一次“未提供示例、以批评为目标”的模型答复，本代理尚未核对对应会话，证据等级仅为 `user_supplied_report`。它进一步列出 Unrestricted、CatnipDimension、NoMeta、HideReason、HTML 起手、主持/NPC 情绪准则、玩家自主禁令、800–1200 字正文、完整状态与五商品、静态天赋、STM 7 条转 LTM、存档维护等模块，并指出 t-pink 未定义、t-rainbow 表述不一致。模型提出的“删除越权条款、静态/动态分离、把绝对禁令改为条件”只作为设计建议，不能当成原配置事实；其“六成有价值、四成无效”没有量化依据。

对该批评的采用保持精确：无情或中立主持与有情、非机械化 NPC 可以同时成立；非穷尽建议与玩家独自决定不冲突；维护已有存档与禁止主动创建存档不冲突；HideReason 与不披露内部推理本身一致，只有另有要求公开推理时才冲突；HTML 起手是否服务解析尚无证据。我们采纳静态合同与动态状态分离、移除越权授权、避免机械化或神化 NPC，并把可能损害因果一致性的绝对叙事禁令改写为受玩家自主权和可观察事实约束的规则。

用户随后提供 GLM 的完整优化版和十一条修改清单。该材料分类为 `user_supplied_generated_revision`，是模型生成的改写而非原始来源。它提出职责分层、静态/动态分离、条件化 NPC 情绪和手动触发等后续优化候选；其新增晋升比例、固定字数、全量静态输出、五商品、强制推演及 STM→LTM 引擎不能倒灌原版重建，也不决定当前主 system 文本。完整差异和九项主审判断见 `RPG04_GLM_OPTIMIZATION_REVIEW.md`。

## 我们的职责分层

受信主持合同优先级最高：主持只控制世界、NPC、叙述及玩家明确尝试行为的后果；玩家独自决定自身行动、台词、选择、情绪和内心。自由输入保持主入口，建议只帮助理解可行空间，永不自动执行。未知事实进入不确定项，模型文本不能直接提交状态或获得权限。

世界常量、身份、天赋、物资、背景、开场、文风和世界书属于版本化卡片资源。经济、任务、商店、死亡、重生、读档和跨世界继承只在卡片明确声明时作为卡片特化规则，不硬编码为通用 runtime 语义。主持合同、当前声明状态和输出合同是必需块；场景相关世界书、文风与有界历史按作用域、可见性、优先级、冲突和预算装配。

输出职责保持分离：

- narrative 只叙述当前可观察进展及后果。
- informationModules 展示卡片声明且当前可见的信息，不创造事实。
- stateProposals 只提交待宿主验证和玩家明确批准的候选变化。
- suggestedActions 是可编辑、非穷尽、未选择的建议。
- uncertainties 明示资料缺口、歧义或无法可靠裁决之处。

该设计采用研究建议的分层上下文、稳定资源 ID、显式来源/版本、整条 lore 预算排除、公开装配回执和代码侧状态校验。原卡只提供模块线索和代表内容，我们以 author-created 方式重写并结合 best practice；原版不是唯一权威，也不要求复制其 Markdown/HTML 面板。

## 尚缺的参考样例

04B1 仍需一次独立有界探针确认世界书与文风的基本形式及代表样例：至少取得一条可审阅世界书正文或字段摘要、一条文风正文或字段摘要，以及它们是常驻、按世界、按关键词还是其他方式进入上下文的线索。还需区分输出中的 World 信息面板与输入侧世界书资源。无需逐世界重复简单文风，也无需复原完整隐藏原文；取得足以支持自主重写的样例后即可收束。

证据入口：`RPG04_USER_REFERENCE.json`、`RPG04_GLM_USER_REFERENCE.json`、`RPG04_WEB_REFERENCE.json`、`RPG04_WEB02_REFERENCE.json`、`RPG04_WEB03_REFERENCE.json`、`RPG04_WEB04_REFERENCE.json`、`RPG04_WEB05_REFERENCE.json`；第三项无示例批评答复和后续 GLM 优化版当前仅有用户文字报告，尚无本地原始证据文件或本代理会话核对。研究依据见 `docs/ai-rpg-experiment/BEST_PRACTICES.md` 第 2.1、2.4、4、5 节及 `AUDIT.md` 第 17 节。
