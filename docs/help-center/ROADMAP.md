# 用户帮助中心分轮路线

帮助中心采用小步 PR 建设。每轮从上一轮合并后的最新 `main` 重新建立基线，不维护长期堆叠分支。

## 第一轮：框架与第一次成功

建立 `/help`、搜索、五个任务区域、文章与一级索引统一阅读界面、找不到页面、桌面与移动入口、内容治理和 PR 门禁。用“找到能看图片的模型并进入发送前输入区”完成两次真实重放。

停止条件：导航被挤压、移动端遮挡、真实步骤不能重放、截图或基线能力不可信时，只保留治理与证据，不以页面壳交付。

## 第二轮：模型选择与安全聊天

补全模型市场筛选、比较、状态、价格、聊天输入、文件能力边界和常见失败恢复。只有获得独立费用与凭据授权时，才增加真实调用证据。

## 第三轮：Agent 与 Workflow

围绕”重复角色”和”固定多步骤任务”分别建立首次成功教程、选择指南、编辑与恢复路径，并明确经典 Workflow 与实验入口的边界。

**进度**：已完成 `create-repeatable-agent` 与 `build-first-workflow` 两篇首次成功教程的起草（基于源码核对真实界面，配图位以待预览验证的 PENDING 占位）。**尚未完成**：隔离预览重放、真实截图、verifiedCommit 回填、编辑与恢复路径教程。合入前必须完成真实预览证据。

## 第四轮：RAG、文件与知识工作

覆盖资料准备、知识库入口、文件限制、索引与检索可用性、数据安全和失败恢复。测试数据与用户真实资料完全隔离。

## 第五轮：MCP、Skill、Runtime 与设置

解释工具、技能、运行状态和服务连接之间的关系；为需要配置、安装或权限的路径建立普通用户与管理员分层说明。

## 第六轮：质量与持续维护

基于真实搜索词和支持问题补齐交叉入口、搜索质量、内容陈旧检查、截图更新规则和可访问性回归。CMS、用户反馈、分析和多语言是否进入范围，另行评估后再决定。

每轮都必须满足：面向非技术背景、简洁直接、真实预览操作、按需可视化、完整范例、明确费用与数据边界、可独立回退。
