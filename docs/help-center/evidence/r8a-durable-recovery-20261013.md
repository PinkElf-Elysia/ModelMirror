## 可见操作

1. 从 Runtime 的“自定义工作流”进入画布；在新合成草稿中删除默认 Agent，
   加入“挂起等待”。通过画布连接输入、等待与输出，输出变量为 `user_input`。
2. 保存草稿，选择“运行”，输入合成文本并运行。等待为 60 秒。
3. 在等待已登记后重启独立后端容器，选择“继续跟踪”，不重新运行。
   第一次重连恰逢启动窗口而报错；就绪后再次跟踪完成。
4. 核对三节点完成及最终交付。持久 task 不变，输入与输出各完成一次。
5. 再次运行并在等待中选择“取消原运行”，页面显示“已取消”。
   重启并超过原唤醒时间后，持久终态仍为 cancelled，无 output 事件。

## 教程重放与反例

- 更新恢复步骤后重新加载已保存草稿，清空页面运行状态，按
  “原页面 -> 运行 -> 继续跟踪 -> 取消原运行”步骤重放。正式内容独立为
  `recover-workflow-run.md`，旧故障文章链接到此，不混用旧截图基线。
- 一次 60 秒等待在点击取消前已经完成。服务端和页面保留真实完成结果，没有
  将已完成执行改为取消；此记录不计作取消验收通过。后续以 5 分钟等待窗口复核。
- 重放复现：顶部已取消，但原节点仍显示运行中；持久状态正确，属前端投影缺口。
  三项针对性红测覆盖 timer 投影、重放取消多出虚假运行卡、取消确认仍显示重试。
  初次测试编辑曾将取消断言放入相似的完成用例，纠正位置后重新红测三项；
  不把该测试编辑失误归因于生产行为。
- 修复仅在 `WorkflowRun` 投影原有事件/服务端取消回执，不新增 SSE，不伪造
  服务端事件历史。未完成卡片转为“已取消”，已完成、失败与跳过卡片保持原状态；
  定时挂起显示“等待恢复”。完成先到的取消请求继续同步实际完成结果。
- 重建并刷新后再次按教程重放：先见“等待恢复”，继续跟踪仍指向原任务，
  取消后任务及等待卡均显示“已取消”；输入保持完成，输出未执行。
- 正式独立文章完成后，从帮助首页的“解决问题”找到教程，核对两张截图均实际
  加载为 1000x562；再在全新页签打开已保存草稿，清空运行页面状态，按五步
  教程复做跟踪与取消。任务 `aa8e8bc6e1e04ec3ab01d00b97f74e22` 为 cancelled、
  4 个有序事件，任务与等待卡片均已取消，无最终交付。
