# 用户帮助中心写作与维护规则

用户帮助中心面向非技术背景用户，目标是帮助用户完成真实任务，而不是罗列产品功能。正式用户内容、截图和维护证据分别放在固定位置：

- `client/src/content/help-center/`：唯一的用户可见内容源，包含 Markdown 正文和类型化目录元数据。
- `client/public/help-center/<baseline>/`：从对应基线预览生成的用户可见截图。
- `docs/help-center/evidence/`：实操记录、验证范围和未验证边界。
- `docs/help-center/ROADMAP.md`：分轮路线与每轮停止条件。

## 信息架构

首页始终按用户任务组织：第一次使用、按目标找指南、按模块浏览、解决问题、安全、费用与数据。`tutorial`、`how-to`、`explanation`、`reference` 只作为写作与维护标签，不要求用户先理解文档方法论。

首页只呈现帮助用户决定下一步所需的入口，不完整展开目录。一级索引、模块和二级功能均应可点击；进入任一页面后，使用统一的左侧分级目录和右侧正文阅读界面。

一级模块页是该模块的总目录，不再增加“模块概览”一类伪二级索引。二级索引只收录独立用户任务、稳定页面、页面一级页签或必须单独说明的实验/受限边界；节点、模型、工具、配置项和流程内部步骤属于三级内容，按后续轮次补充。首轮事实清单见 [`evidence/secondary-index-audit-d4bd6b8d.md`](./evidence/secondary-index-audit-d4bd6b8d.md)。

每篇文章元数据必须包含：slug、标题、摘要、分类、内容类型、对象、预计时间、关键词、相关产品路由、验证 commit、验证日期。

## 文章标准

所有文章都要包含完成结果、适用对象、开始前条件、连贯的真实范例、常见问题、限制和下一步。

所有用户文案遵守三项原则：

1. 面向非技术背景：先说明用户要完成什么，再解释必要术语。
2. 简洁明了：一段只表达一个重点，使用当前界面中的名称，删除项目过程、实现方式和无助于操作的修饰语。
3. 可实际验证：涉及入口、按钮、状态和结果时，以最新隔离预览中的可见操作为准；截图只用于帮助定位关键界面。

- Tutorial 和 How-to 涉及操作，必须使用 5–8 个编号步骤；一步只做一个主要动作，并说明关键步骤应该看到什么。
- Explanation 和 Reference 解释判断方法或提供速查，不为了格式伪造操作步骤。
- 第一次出现专业词时立即用白话解释，不把开发者文档直接搬给普通用户。
- 用户正文不写“首轮验收”“当前实现”“本轮基线”等项目管理语言。验证 commit、日期和未验证边界分别放在文章元数据、限制段和实操证据中。
- 标题优先使用用户目标或页面名称；避免口号、拟人化修辞和不能帮助用户做决定的概括。
- 说明“已验证”“未验证”和“可能变化”的边界，不把入口可打开写成真实调用可用。
- 内部链接使用产品路由；外部链接明确标识。Markdown 不允许原始 HTML。

## 真实操作证据

撰写操作内容前，必须从最新 `origin/main` 建立隔离预览，用应用内预览器清空状态后完成任务。源码只帮助确认实现边界，不能代替可见操作。

实操记录至少包括：视口、入口、前置条件、每步可见文案、预期结果、实际结果、易混淆点、恢复方法、付费与数据边界。写完后再次清空状态，只根据教程重放；任何按钮名称、顺序或结果无法复现，都要修正文档或停止交付。

## 截图规则

- 只在入口隐蔽、选项易混或状态难解释时使用截图。
- 使用真实 PNG、描述性文件名和有效替代文本；目标宽度 750–1000px，单张不超过 250KB。
- 裁去无关界面，但保留足够上下文让用户定位。
- 不包含凭据、Token、真实用户数据、内部地址、通知或无关标签页。
- 导航或布局变化要用相同视口的基线图与候选图并排检查。

## 维护门禁

任何影响用户体验的改动，都要在同一 PR 更新受影响文章与截图，并完整填写 PR 模板中的 `Help Center Impact`。只有能具体证明用户可见合同、步骤、截图、术语和预期结果都没有变化时，才可以填写 `None`。

写作方法参考 [Diátaxis 内容类型](https://diataxis.fr/start-here/)、[GOV.UK 用户需求](https://guidance.publishing.service.gov.uk/writing-to-gov-uk-standards/plan-manage-content/identify-user-needs/)、[Microsoft 操作步骤规范](https://learn.microsoft.com/en-us/style-guide/procedures-instructions/writing-step-by-step-instructions)和 [GitHub 截图规范](https://docs.github.com/en/contributing/writing-for-github-docs/creating-screenshots)，但这些方法不会作为用户首页分类直接暴露。
