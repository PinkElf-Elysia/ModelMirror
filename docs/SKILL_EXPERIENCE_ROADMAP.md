# Skill 体验治理与后续路线图

最后更新日期：2026-08-02
状态：体验治理进行中；目录扩张冻结

## 1. 当前阶段目标

当前阶段不追求继续增加 Skill 数量，而是把已有目录变成用户能看懂、能筛选、知道如何安装的资源库。范围固定为：

- 手工精选条目。
- `anbeime/skill` 已生成目录。
- `VoltAgent/awesome-agent-skills` 已生成索引。

在本阶段验收完成前，不增加新的 Skill 目录，不直接接入 SkillHub 或其他外部市场目录。外部页面只可作为现有条目的来源说明，不能借此绕过安装源核验。

## 2. 已落地的体验基线

### 2.1 中文说明

- 市场主说明统一使用清晰中文，优先回答“这个 Skill 能帮我做什么”。
- 上游英文原文保留为 `sourceDescription`，用于搜索、审计和追溯，不作为卡片主文案。
- 中文生成规则按具体能力匹配；匹配不到时才使用所属大类的兜底说明。

### 2.2 稳定分类

目录统一收敛为 10 个用户任务大类：

1. AI 与智能体
2. 开发与测试
3. 数据与研究
4. 自动化与集成
5. 设计与多媒体
6. 内容与办公
7. 营销与增长
8. 产品与协作
9. 安全与运维
10. 商业与专业服务

分类下拉框显示每类数量。同步源自己的细分类仍保留在原始快照中，但不再直接占用用户筛选项。

### 2.3 安装状态

每个市场条目必须属于以下一种状态：

| 状态 | 含义 | 页面动作 |
| --- | --- | --- |
| 可一键安装 | 已核对 GitHub 仓库和包含 `SKILL.md` 的子目录 | 调用模镜安装接口 |
| 有安装说明 | 来源页提供外部安装命令，但模镜尚未核对可 sparse checkout 的子目录 | 查看来源页并手动安装 |
| 待核验来源 | 已定位 GitHub 仓库，尚未确定具体 Skill 子目录 | 查看仓库并进入后续审计批次 |
| 仅资料参考 | 产品页、规范页或其他不能证明为 Skill 目录的资料 | 只查看资料 |

“没有 `installSource`”不再等同于同一种模糊状态。

当前聚合去重后的 1,244 项中：725 项可一键安装、358 项有外部安装说明、152 项待核验 GitHub 子目录或来源失配、9 项仅作资料参考。

### 后续批次

建议按未核验规模和用户价值排序：

1. 继续处理高频 `officialskills.sh` 发布者，优先选择目录结构稳定的单仓多 Skill 项目。
2. GitHub 仓库根链接，优先核验真实 SkillSet 和单仓多 Skill 项目。
3. 非 GitHub 外部页面，仅在能证明安装包结构、版本和来源时升级状态。

每批必须记录：来源 URL、仓库、固定提交或核验日期、`SKILL.md` 路径、重复项、安全注意事项。路径不存在、仓库归档或说明与内容不一致时，不开放一键安装。

## 4. 暂缓功能

以下功能只进入规划，本阶段不实现界面、API 或存储模型。

### 4.1 用户上传技能

目标流程：上传压缩包或选择目录 → 解压到隔离暂存区 → 防目录穿越检查 → 校验 `SKILL.md` frontmatter → 展示脚本、依赖和凭据风险 → 用户确认后安装。

上线门槛：

- 限制文件类型、体积、目录深度和文件数量。
- 禁止上传阶段执行任何脚本。
- 检查符号链接、绝对路径、隐藏凭据和可疑二进制文件。
- 校验失败时保留可读报告，不把内容写入已安装目录。

### 4.2 按需求寻找 Skill

目标流程：用户描述任务 → 提取目标、输入输出和工具约束 → 在本地索引中召回候选 → 解释匹配原因、安装状态和风险 → 用户自行选择。

上线门槛：

- 优先搜索现有目录，不把功能变成外部市场抓取入口。
- 结果必须说明“为什么匹配”，不能只按名称相似度排序。
- 推荐不代表自动安装，安装仍需显式确认。
- 无合适结果时明确告知缺口，不伪造 Skill。

### 4.3 使用 skill-creator 创建 Skill

目标流程遵循 Skill 生命周期：需求访谈 → 生成小写连字符名称 → `init_skill.py` 建立草稿 → 编写精简 `SKILL.md` 和必要资源 → 准备真实测试提示 → `quick_validate.py` 校验 → 人工审阅 → 显式安装或发布。

上线门槛：

- 草稿必须与已安装目录隔离，创建完成不自动启用。
- frontmatter 至少包含明确的 `name` 和触发场景完整的 `description`。
- 大段参考资料进入 `references/`，重复或确定性操作优先进入 `scripts/`。
- 校验结果、测试样例和版本差异必须在用户确认前可见。
- 发布到共享市场属于独立权限动作，不能与“保存草稿”合并。

## 5. 进入下一阶段的验收条件

- 现有市场卡片主说明不再出现纯英文介绍。
- 所有条目都有且只有一个稳定分类和一个安装状态。
- 分类下拉框不再出现仅 1–2 项的碎片类别。
- 每个新增一键安装源都能追溯到包含 `SKILL.md` 的实际目录。
- 路线图中的三个暂缓功能没有以半成品入口混入当前主路径。

可重复运行 `node scripts/audit-skill-experience.mjs` 检查以上中文说明、分类、安装状态和批次数量约束。

## 6. 回退

体验策略集中在 `client/src/data/skillCatalogPolicy.ts`。若分类或中文说明规则出现明显误判，可回退该策略文件和市场页面展示，不需要删除原始生成目录，也不会影响已安装 Skill 或后端安装记录。
