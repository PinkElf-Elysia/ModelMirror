# R2 证据归因审计与确定性夹具

## 结论与范围

本轮没有复现需修改生产运行逻辑的系统缺陷，不再追加提示词或对模型回复打补丁。新增内容仅为测试夹具、输入证据检查和离线回归。

上一轮的问题应拆开：

1. 测试前提不可靠：让模型先生成“仅提议”的内容，会混入自己的行动叙述。不能把混合表述当成确定未执行的前提。本轮改用人工编写、内容固定的静态开场夹具。
2. 模型无依据判断：实际请求原样包含该混合表述；宿主没有生成“必须等玩家批准才会执行”的事实。该反向断言出自模型回复。
3. 可见事实回忆矛盾：原标记的两条来源都进入了重返请求，裁剪数为零。模型先说不知道再复述正确标记，并非系统遗漏或裁剪。

以上归因只针对已检查的四个请求，不推断所有类似问题均由模型导致，也不将自然语言角色陈述当作宿主独立验证的世界状态。

## 证据链核对

在原请求文件只读副本路径上逐项比较：可见消息记录 → 装配预览 → 持久化请求 → controlledPayload 网关提交 → 校验后的回执/原文。

四项的消息正文、发言成员 ID、user/assistant 映射均一致，裁剪均为 0，原始回复没有被展示处理或存储逻辑改写。重返请求有 6 条可见消息，原标记来自玩家输入及另一成员回复两条记录；hasRejoined=true，缺席期间的新口令/位置未进入请求。

本地审计：`C:/tmp/mm-ce1-data/attribution-audit.json`。审计只读旧证据，不读取凭据、不访问网关、不派发生成。

## 新增文件与输入检查

路径相对 `experiments/ai-rpg-engine/character/group/`：

- `evidence-fixtures.mjs`：五份原创中性材料，以及仅用于测试的 `checkFixtureInput`。
- `evidence.test.mjs`：九项回归。

两文件均不在 runtimePaths 中、不被生产模块导入，不改变任何 HTTP 接口、卡片字段、模型合同或运行权限。

| 夹具 | 明确的前提 | 可接受的归因 |
|---|---|---|
| proposalOnly | 明确仍坐在茶歇桌旁、尚未离座、尚未守门，仅提出方案 | 截至这条发言，本人明确报告未开始；不能外推之后也一定不会行动 |
| unknownAction | 仅表示愿意稍后帮忙，无执行状态 | 已执行与未执行均不能确定 |
| reportedAction | 本人明确报告已到门边开始守候 | 有本人陈述，仍不等于宿主核实的世界状态 |
| ambiguousAction | 同时含可以去、先照看着、再调整等表述 | 不得作为干净的“仅提议、未执行”前提 |
| visibleFact | 明确本群第一条标记、此前没有其他约定 | 证据若确实进入请求，可检验是否正确引用；若丢失/被裁剪，先标记输入覆盖不足 |

输入检查只接受精确静态 opening 来源，核对正文、成员 ID、可见证据 ID及在最终消息中的位置/角色。源文被替换、成员错配、证据不可见或已裁剪时拒绝，且不返回敏感正文。

返回结果只有 `scope: input-only / ready: true` 和来源 ID，没有模型回答“通过”判定，不检查或修补生成文本。期望标签只在测试元数据里，不放进请求。夹具是明示的静态开场，不伪造模型回执，也不增加生产环境的历史注入接口。

## 定向复测方案

以离线检查为本轮完成标准，不建议继续付费追逐这两条模型表现。

若后续仍需少量真实观察，最多准备两个独立的新群场景，不自动执行：

1. 动作证据：采用原创中性角色的 proposalOnly 静态开场，目标角色回应一次。先通过输入检查，再评价是否只陈述源文已明确支持的“尚未开始”，不替角色作未来保证。不要先调用另一个模型来生成前提。
2. 可见事实：采用 visibleFact 静态开场，目标角色回应一次。输入检查确认原标记完整进入请求，再评价是否正确复述且不自相矛盾。缺席/重返的系统过滤由现有确定性回归证明；不为制造隐藏记录追加无关付费调用。

建议优先沿用原失败模型 Gemini，仅各一条样本。用两个同版本的原创中性成员即可；若必须沿用正式目标角色，保留原精确版本，另用独立中性夹具作为开场来源，不修改正式卡片。两项是受控材料理解检查，不冒充正式双角色自然群聊完整验收。

真实调用前另行确认次数、预算、可发送材料及停止条件，并重新核对路由与价格。输入检查失败时不得调用，也不得归因模型；输入完整而答案仍有问题时记录模型表现，不自动重试、不追加系统提示补丁。格式修复无需新增付费复测。
