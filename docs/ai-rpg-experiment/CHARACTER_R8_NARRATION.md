# R8 交付点 3 · 显式旁白与轮次回看

在本地夹具宿主中，新群可以保存玩家撰写的场景旁白。群聊页的“回看轮次”按时间倒序展示每轮已入史的玩家消息、约定的成员顺序、每一步的状态和已入史的回复。每页最多五轮。

## 旁白归属与持久化

- 群拥有固定的旁白身份。旁白来源为 `manual-narration`，关联操作 ID 和实际记录的玩家实例。浏览器只能提交正文、操作 ID 和两个预期修订；不能指定作者、发言实例或收件人。
- 新群的旁白和原群事件共用一次存储 CAS。旁白修订独立递增。普通群修订决定这条旁白位于哪两条消息之间，也决定发布时谁在场。并发冲突须重新核对，同一个操作的重复确认只保留一条。
- 旁白先经过在场范围过滤，再进入目标成员上下文。迟入者与缺席者看不到对应的内容、消息 ID 或来源。它以独立发言者的引用材料进入上下文。旁白写入只记录文本，没有模型派发、世界状态结算或费用预留。
- 轮次进行中和请求结果未知时锁定旁白写入。回看只读；刷新后若有回执到达，回看会同步群状态，下一轮仍需玩家重新预览和启动。
- 旧群沿用原消息、身份与绑定。新宿主仅对核验过的两份旧群运行描述符接受精确兼容。恢复只读时保留账本字节，旧手动发送和请求恢复继续沿用原接口。

## 离线验收

| 检查 | 证据 |
|---|---|
| 归属、无派发、预算与世界关联 | 群快照逐字段对照；重复、冲突和伪造来源均有断言。 |
| 成员范围 | 同名角色、后来加入、离场和重入；对照成员视图、预览和实际夹具请求，隐藏旁白及引用均被过滤。 |
| 轮次页面 | Chromium 1100 与 390 像素分别走通写旁白、预览、首步派发时停止、刷新、回看，再启动完整三成员轮次。两轮分别保存一条玩家消息；四个模拟回执对应四条已完成回复。 |
| 存档 | 从 R8 交付点 2 的源码生成旧群副本。恢复时账本哈希相同，手动续聊后消息由三条增至五条，源副本哈希相同。另一个旧群页面副本走通手动发送、只接话、刷新，消息由五条增至八条。归档基线的单聊与群聊续聊、篡改和源码漂移检查继续执行。 |
