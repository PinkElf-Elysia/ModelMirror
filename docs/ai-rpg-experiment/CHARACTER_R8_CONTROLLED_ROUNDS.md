# 受控群聊的串行轮次

## 如何试用

在群聊页展开「发言顺序预览」，预览成员与每一步的费用上界，再输入本轮玩家消息并启动。同一轮的第一步保存玩家消息，后续成员以接话方式回应。轮次回看显示启动时确认的费用上界。刷新后由用户选择是否继续。

可从实验目录运行 `node character/group/controlled-round-preview.mjs <独立空目录>`，按照终端输出的本机地址打开中性示例。示例只使用同机模拟网关，使用单独的模拟预算和合成回执。再次使用相同的示例目录时复用保存的模拟网关端口。

## 受控宿主接口

`character/group/controlled-workspace.mjs` 的 `startRoundWorkspace(options)` 在完整的单聊、群聊、分支和共享预算宿主就绪后接入轮次。默认关闭。开启时，宿主须提供以下依据。

- `roundPolicy` 指定现有任务授权 ID、整轮调用数及金额上限，以及经核实的完整成员模型配置哈希。
- `priceEvidence(modelId)` 提供与模型配置一致的价格修订、推理费用覆盖证明和到期时间。每步重新核对路由就绪状态和参数。估价覆盖允许的整个输入窗口及预留输出，金额以微美元向上取整。
- 预览返回整轮及逐成员报价，启动须提交对应哈希。群、顺序、成员配置、政策及价格修订均参与绑定。预览和启动均不占用额度。
- 实际派发复用手动群聊的受控宿主。核对目标成员和群预算后，经原账本对来源及任务余额逐步裁定。同一共享预算在其他入口消耗时，后续步骤可能被拒绝。回执与金额记录仍归原请求。
- 受控轮次使用独立存储 scope `character-controlled-rounds-v1`。归档保留用户确认的报价、请求对应关系及停止原因。原 R8 夹具轮次继续使用原格式。

## 停止、恢复和计费

取得派发权前收到停止时关闭该步尚未派发的意图。已取得派发权时允许原请求取得回执，随后不再请求下一成员。刷新及重启仅恢复状态。结果未知时继续占用次数和金额，人工核对仅查询原请求。供应商取消、实际计费及退款须分别凭供应商证据核实。

## 离线验收与保留事项

新增回归位于 `character/group/controlled-rounds.test.mjs`。覆盖共用预算、两种成员模型、整轮及逐步费用检查、派发前后停止、重复操作、价格或可用性变化、重启及查询原回执；页面使用中性群验证桌面整轮和窄屏停止、刷新、回看。首次窄屏断言假设停止时已派发，测试随后改为先读取服务端步骤状态再点击停止。

历史 R4c ①的人工采纳及精确端点、②的精确端点和刷新后实时增量沿用原待证记录。④仅证实宿主停止读取，供应商最终计费待证，保留 US$0.018990 预留。六个旧世界存档场景、Provider 审计及真机设备延期沿用原记录。后续真实验收的三次回执、串行结果及首步停止待证边界见[四项收口记录](./CHARACTER_ROADMAP_CLOSEOUT.md)。
