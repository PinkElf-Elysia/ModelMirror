# R8 交付点 2 · 用户启动一轮串行发言

基线为主线 `0d0a909a` 加已验收的十个交付点 1 文件。新宿主只在独立群聊的 fixture 模式注册串行发言，真实模型、语音、自动旁白均未接入。

## 从预览到回复

玩家先确认发言预览。固定顺序使用单独的本轮玩家正文；提及模式使用刚预览的同一份提及草稿。宿主重新读取群修订，计算并冻结 1–3 个去重的在场实例。只有第一步提交玩家正文，后续成员以接话方式读取各自可见的最新历史。其他角色的回复不能扩大本轮名单。已有手动群聊、角色版本、群权限和消息合同继续由原宿主核验。

- `round-start` 保存确认的名单和正文；启动操作 ID、上一轮 ID 及群修订用于核对重复或过期提交。
- `round-step` 每次只接受轮次 ID、预期步号和群修订。每一步调用原群宿主，以固定请求操作 ID 原子追加必要的玩家消息和请求预留。群调用数、群费用上限、任务共享上限仍由同一群账本核验。下一步要求上一步已采纳完整回执。
- `round-stop` 持久保存停止决定，与下一步争用同一派发顺序锁。已进入模拟供应商的请求可单独等待或核对原回执；其结果不能启动后续成员。原群 GET 读取轮次，原 `recover` 只查指定请求。
- 轮次使用独立 CAS 记录。进度由群账本中匹配的请求及回执推得，分支不复制待执行队列。点击开始的标签页逐步推进；刷新、页面卸载、切换群或重启不授予推进权，需要玩家明确“继续剩余发言”。失联、部分输出和未知状态均不视作完成。回退可关闭轮次宿主，保留轮次记录、群账本和证据。

## 验收

| 检查 | 结果 |
|---|---|
| 保存与归属 | 3 位同名实例的桌面群完成 3 次模拟派发，每人 1 条、玩家共 1 条。重复提及、回复正文包含新提及、双重启动和竞争同一步均未增加名单或重复入史。 |
| 每步预算 | 群次数、共享次数、群金额分别只能支持一步时，第二步均在派发前停止。余额为一次的独立窄屏群实际只产生 1 次派发。 |
| 停止 | 首步前停止，原群记录逐字段相同。首位处理中停止，当前回执仍可采用，待发成员零派发。成员离场或收到失败回执后后续步骤被拒绝。 |
| 刷新与重启 | Chromium 刷新后停在第一步；明确点击继续后才完成剩余两步。另用独立 OS 子进程在模拟回执落盘、群宿主尚未采纳时中断；重启保留预留，读取原群零派发，停止后重复核对仅向夹具查询一次，原回复只入史一次。 |
| 未知结果 | 原请求查不到结果时继续占用 1 次及非零金额；重启、停止和查无记录均不退款。夹具后来提供有效原回执后才按该回执结算。 |
| 页面与门禁 | 在 1100px 与 390px 验证完整一轮、中途停止、刷新继续和额度中止，没有外部请求。群聊目录测试覆盖宿主、来源漂移、版本、预算、恢复及两代页面。 |
