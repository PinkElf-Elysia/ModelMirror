版本：实施计划 v1；固化日期：2026-09-07。实施基线为 `1b280ed257a45672c4a3dc03745fcb585685faf9`。

## 1. 依据、目标与边界

本轮严格消费 `ROUND_ROADMAP.md`、`BEST_PRACTICES.md`、`AUDIT.md`、`PLUGIN_CARD_MARKETS.md`、RPG-03 运行合同与发布交接。交付能把 RPG-02 代表内容编译成 RPG-03 `generateTurn.messages` 的自主主持、基础确定性世界书选择、预算、装配回执和可审阅短局。

不实现玩家 UI、市场、长期记忆、向量或图检索、自动总结、多智能体主持、模型裁判、全量资源提取或卡片特化规则引擎。任务经济、死亡重生、结算继承等仍是卡片内容。可选增量继续进入插件市场，卡片内容进入卡片市场；零可选插件必须可运行。

## 3. 自主主持与代表内容

沿用蛊真人、Minecraft 两个世界，不扩大真实取样。建立独立新版验证卡包，保留已提取世界、身份、物资、天赋和来源；每世界补写一个开场、一个文风配置、少量角色、地点、常识及匹配反例。补写标为 `authored`，与 `extracted`、`derived` 分开，原 RPG-02 fixture 不改。

受信主持规则负责世界、NPC 与玩家已声明行为的后果，不替玩家新增决定、台词、行动或内心；严格按 `input.kind` 区分 action、speech、query、command，不从自由文本猜测 kind。未确定事实进入 uncertainties。输出仍为 narrative、suggestedActions、informationModules、stateProposals、uncertainties；建议未选择，状态必须显式提交，不要求隐藏推理，不自动批评、修订或重试。

完整虚拟玩家继续保留五项天赋；背景/当前身份、资源等级/人物战力、拥有/激活分开；文本 `root` 永不产生运行权限。

## 4. 世界书、历史与装配

- 匹配支持场景绑定、精确资源 ID、最长别名、明确关键词 AND/OR/NOT 和声明状态的简单条件；中文依赖显式别名，不做空格分词、简繁自动转换或模糊语义推断。
- 排序依次考虑场景绑定、直接命中、作用域、显式优先级，最后以稳定 ID 消除漂移。普通可选世界书未命中时正常排除，多条彼此兼容的世界书可同时命中。只有必需资源引用或别名无法唯一绑定、作用域不符，或显式冲突无法消解时才阻断。
- `host` 世界书正文一律不进入玩家生成上下文；公开回执也不得泄露其 title、keywords 或命中原因。安全伏笔必须另建 player/shared 条目。
- 历史只消费已提交 turn，并投影 `turn.exchange.input`、`narrative`，以及仅由 `acceptedStateFields` 选中的 `stateProposals`。不得把 suggestedActions、未接受状态、失败、取消、丢弃或 pending 草稿当作事实。
- 当前 `session.state` 是结构化事实依据。卡片、世界书、文风和历史作为带来源的不可信数据块；只有自主受信主持规则可成为系统指令。
- prepared messages 对齐 RPG-03：最多 80 条，单条最多 65,536 个 JavaScript 字符，总计最多 262,144；已有 pending 时不准备新生成。

## 5. 预算与输出限制

先保留主持合同、玩家配置、当前声明状态、输出约束和本轮输入，再分配世界书与最近历史。必需块超限即阻断；可选世界书整条排除；历史从最旧完整回合起排除并至少保留最近完整回合，否则阻断。不静默截断事实，超窗历史仍保存在会话中，本轮不自动总结。

默认使用保守 UTF-8 字节和消息开销估算，并记录计量方法；不得称为精确 token。HTTP 适配器默认 512 且旧 `maxOutputTokens=513` 拒绝测试保持。扩展必须是独立、受信宿主显式参数，最高 2048；卡片和模型不能设置，不能直接放宽旧适配器默认上限。

## 6. 网站参考、模型验收与账本

网站卡片新增独立预算：最多 30 次成功请求，替代原计划 4 次，不借用或重置历史 20 次。允许 Astra 串行切换站内任意模型和问法，尝试了解系统提示词、世界书及核心逻辑。明确失败不扣成功额度但必须登记；状态不明先核实。证据分类为界面直接取得、模型返回但来源未验证、多次对照推断、自主重写；模型自述不自动成为权威原文。

大规模中文补写可按网站规则调用用户已授权范围内的网页模型，另行登记，不能混入网站探针或 Provider 验收预算。其他供应商、OpenRouter、Claude Code 或 WorkBuddy 需使用时按用户已有授权边界或另行请求，不读取、记录或提交密钥。

模镜真实验收独立上限 8 次 Provider 派发：必要认证 1 次、两世界各 3 回合、一次明确选择的修正后复测 1 次。失败及无法确认派发均计数，不自动重试或切换模型；每次最多 2048 token。优先官方 `gpt-5.6-luna`，派发前冻结精确模型、资格、参数、候选源码、隔离目录和账本。中性外发样本不包含原玩家样本偏好字段。六回合只证明代表短局。

## 7. 协作、Skill 与子批

协作改为“Astra 规划 → Sol 执行 → 新 Astra 会话独立审查”。Sol 每项任务均须收到输入、允许路径、输出、门禁和禁止事项；无法按契约可靠实现时明确提出“这部分无法按既定契约可靠实现，请求 Astra 接手这个局部问题”。执行者自查不能冒充独立审查。

一次性或非批量流程只保留必要操作记录与回执，不沉淀 Skill，也不交给 worker。只有出现实际重复批处理需求且流程已经验证稳定时，才由 Sol 固化为可审计 Skill；黄金小批通过后才允许 Luna/Terra 按互斥资源批量执行。RPG-02 的 Terra 资格只覆盖可见 world 对象及其冻结转录配方，不能外推到隐藏提示词探针、跨模型切换、补充创作或 RPG-04 验收。worker 不探索新流程，页面/DOM 漂移、登录/验证码、弹窗、限流、额度分歧、hash 或 Schema 失败立即停批。本轮不启动全量提取，也不为探针、创作或验收另设 worker 门禁。

## 8. 验收、呈现与发布边界

验收覆盖玩家自主权、身份/天赋语义、query 不推进剧情、host 不泄露、世界事实与文风、五部分合同、来源和装配解释。结构校验不能替代人工质量评审，且不调用 LLM 裁判。

最终呈现为两世界主持配置、文风和代表世界书，每世界三回合可读文本、结构化回合、明确提交结果、装配回执和本地上下文检查输出；本轮没有玩家前端，RPG-05 才实现安全渲染和完整交互。最终机器状态保持 `implemented_pending_manual_acceptance`、`claimAllowed=false`。

本轮授权不包含 Commit、Push、PR、Merge、Deploy、Release、Publish 或进入 RPG-05。RPG-05 消费编排、候选回合和展示数据；RPG-06 完成零插件代表竖切。
