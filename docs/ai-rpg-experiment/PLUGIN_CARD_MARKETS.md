# “一切可选皆插件”与插件/卡片双市场

版本 v1；依据用户 2026-09-04 最新决定。该原则约束第一版后的所有增量设计，也反向限制第一版核心范围。

“一切皆插件”在本项目中的准确含义是：**所有非必要、可替换、可独立启停的功能、模块和优化包都作为插件；安全、治理和插件装载本身留在极薄核心。** 卡片及其内容资源进入卡片市场，不与可执行能力混装。

## 1. 三层结构

| 层 | 负责什么 | 不负责什么 |
|---|---|---|
| 必要运行核心 | 卡片包加载与基础校验、基础提示词/世界书装配、模镜模型与会话适配、生成/流式/取消/错误、基础安全渲染、最小运行状态与回执、插件宿主和权限边界 | 不内置向量/图检索、记忆宫殿、自动总结、复杂规则、扩展 UI、模型裁判或市场内容 |
| 插件市场 | 所有可选增量功能、模块、优化策略和工具；用户选择安装、授权、启用、停用与卸载 | 不接管模镜凭据、路由、预算、长期记忆治理或核心安全策略 |
| 卡片市场 | 角色卡、世界、身份、天赋、背景、文风、世界书、开场、示例对话、卡片私有提示词和声明式扩展数据 | 默认不执行代码，不把跨卡运行能力伪装成卡片内容 |

核心必须在 **零可选插件** 时完成基础 AI RPG 运行。插件市场和卡片市场是两个逻辑域；它们可以复用模镜既有市场外壳，但目录、包类型、权限和安装语义不能混淆。

## 2. 必要核心允许清单

第一版核心只保留：

1. 规范化卡片包和代表资源的读取、校验、版本与来源记录。
2. 基础确定性世界书匹配、可见性过滤、token 预算与上下文编译。
3. 模镜 model ID、路由、凭据、预算、取消、会话和调用回执的受控接口。
4. 配置/导入卡片 → 进入场景 → 玩家输入 → 生成 → 呈现 → 继续下一回合。
5. 安全 Markdown/结构化信息呈现、基础错误恢复和最小运行状态。
6. 插件宿主的最低合同：发现、兼容性检查、能力/权限声明、启停、失败隔离和版本锁定。

插件市场页面、在线安装、推荐算法、评分、付费、发布者签名和 UGC 治理不属于第一版。第一版可以定义并验证最小插件合同，但不预装可选功能插件。

## 3. 插件市场

以下能力一律作为插件候选，不进入必要核心：

| 插件类别 | 例子 |
|---|---|
| 检索与上下文 | 向量检索、GraphRAG/知识图谱、重排、长上下文优化、动态预算策略 |
| 记忆 | 记忆宫殿、自动总结、语义记忆、时态关系记忆、NPC 视角记忆 |
| 玩法与规则 | 通用任务/经济、分支存档、死亡复活、跨世界继承、随机/骰子、DDA、NPC 模拟 |
| 提示词与优化包 | 跨卡主持策略、文风增强、候选生成/批评/修订、特定模型适配优化 |
| UI 与媒体 | 扩展状态面板、地图、时间线、富媒体、主题、3D/空间呈现 |
| 评测与运营 | 长局回归、模型裁判、跨模型矩阵、成本/延迟分析、漂移监测 |
| 创作与转换 | 酒馆卡片转换器、批量清洗、字段映射、世界书拆分、质量审计和作者辅助 |

每个插件包至少声明稳定 ID、版本、兼容的核心版本、能力、所需权限、设置 schema、依赖、数据/网络范围、入口、迁移/卸载方式、来源、许可证和内容 hash。后续共享生态成熟时再增加发布者签名和透明记录。

即插即用必须满足：

- 用户明确选择；卡片不得静默安装、启用或升级插件。
- 安装前展示权限和数据去向；启用范围可限定到用户、工作区或单张卡片。
- 插件调用模型、embedding 或记忆时仍通过模镜治理接口，不能持有独立平台密钥或建立第二控制面。
- 缺失推荐插件时卡片应安全降级；确属必需插件时明确阻止启动并说明原因。
- 插件失败不得破坏核心会话或其他插件；停用、卸载和版本回退有可检查结果。
- 可复用行为放插件；与单张卡绑定的事实、文风和世界书留在卡片包。

## 4. 卡片市场

卡片市场的计划内容来源分为：

1. **用户提供的大量酒馆卡片资源转换**：保留原始包 hash、来源、原格式、转换器版本、字段映射、被丢弃/替换内容和生成后的卡片版本；不导入 Tavern 平台代码。
2. **我们协助编写的卡片**：直接使用本项目卡片 schema，记录作者、协作者、版本、资源和变更说明。
3. **未来 UGC**：作者自行创建和更新；后续补充草稿、预览、审核、举报、版本、下架与兼容治理。

卡片包可包含元数据、角色/玩家模板、世界与场景、身份、天赋、背景、文风、世界书、开场、示例对话、素材引用、卡片私有提示词，以及声明式的最小状态/信息模块。卡片包默认是数据：

- 脚本、任意 HTML、工具执行和网络访问不能藏在卡片内；需要执行能力时转为单独插件并经过权限授权。
- 卡片可以声明 requiredPlugins、recommendedPlugins 和无插件 fallback；安装仍由用户决定。
- 仅服务该卡片的规则优先保留为卡片声明；已被多个独立卡片验证为同一稳定能力后，才提炼为插件。
- 每张卡、世界书、素材和转换产物分别记录来源、版本、hash、许可/授权元数据和兼容范围；当前目标卡既有法律结论不在此重复审计。

## 5. 双市场协作

~~~mermaid
flowchart LR
  C[卡片市场\n内容与声明] --> H[必要运行核心]
  P[插件市场\n可选能力] --> H
  H --> M[模镜模型/会话/记忆治理]
  U[用户] -->|选择卡片| C
  U -->|选择并授权插件| P
~~~

安装卡片时可以列出推荐插件和能力差异，但不能自动安装。运行时由核心解析卡片声明、确认已授权插件、编译上下文并调用模镜；卡片和插件均不能越过核心权限边界。

“优化包”若改变跨卡检索、提示编译、模型调用、记忆、UI 或评测行为，归插件市场；只改变某张卡的世界书、文风、开场或人物设定，归卡片市场。

## 6. 分轮约束

- RPG-01 固化核心/插件/卡片分类规则和最小包合同。
- RPG-02 的代表资源按未来卡片市场包形态整理，但不建设市场。
- RPG-03 只实现插件就绪的最低宿主边界和必要运行框架，不安装可选插件。
- RPG-04 使用核心基础检索与上下文编译；向量/图检索、记忆宫殿和自动总结只保留插件接口。
- RPG-05 不为未来插件预建常驻一级 UI；插件以后通过受控插槽按需呈现。
- RPG-06 在零可选插件条件下验收核心竖切，并产出插件市场、卡片市场的后续入口。

后续每次提出功能时，先回答：它是否是所有卡片运行都必需？若不是，归插件；若只是内容，归卡片。不得以“常用”“效果更好”或“某张卡已有”为由塞回核心。
