## 配置、兼容性与尚未验证的边界

- 父服务只在 `RPG_S2S_ENABLED=true` 且服务端 `RPG_S2S_TOKEN` 满足至少 32 字符时启用。独立适配器由服务器注入 `baseURL/serviceToken/enabled/limit`；端点仅允许 HTTP loopback 或 Docker 内部 `server` 主机，无 URL 凭据、查询和自定义路径。真实值本批未配置、未查看、未写进仓库。
- adapter 的 `params` 是既有配置中的三个有效参数投影，不接受全量 UI 参数作为静默过滤。旧 unsupported 字段策略保留。额度默认 0，启用服务不产生额度；必须由后续明确授权配置。
- 当前只保存上游明确声明的有界顶层 `context_length/max_output_tokens/supported_parameters`，旧缓存不会自动补齐。兼容信息未知则不可选，没有用额外调用探测补全。
- 官方 OpenRouter 文档说明模型级 supported_parameters 是各端点的并集，top_provider 的限制也不能直接当作任意实际端点保证。因此本批不把 top_provider 反推为精确连接的容量证据；实际环境若缺足够信息，需由控制面提供可验证的兼容数据后才开放相应模型，RPG 不负责认证或配置。来源：[官方 Models schema](https://github.com/openrouterteam/docs/blob/main/openapi/openapi.yaml)。本批只查询公开文档，没有获取真实账户目录。
- 容量检查为 UTF-8 字节数加消息开销的保守准入估计，并非模型 tokenizer 的精确 token 数；不足时阻断，绝不截断正文。它不能代替真实模型兼容验收。
- 暂未把新适配器接到生产 `studio/server.mjs` 的聊天路径。B3 才落地核心选择持久化、每回合模型记录、版本绑定及分支继承；B4 才接已批准的极简 UI。现有真实路径、旧会话与分支运行 hash 保持不变。本批测试并不代表运行时切换或正式 UI 已验收。
- 目录真实性、实际可选模型数量、服务凭据部署、跨服务实际环境联通、模型输出质量和用户人工体验均未验证。无新 Provider 额度、无 Commit/Push/PR/共享栈更新。
