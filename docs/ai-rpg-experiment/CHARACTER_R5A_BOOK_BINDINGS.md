# R5a 独立角色书

工作台入口为 `/characters?books=1`。角色草稿可保存书目，角色版本可固定书目，玩家档案可保存推荐书。单聊和群聊可以在创建后进入选书确认页，也可从已有会话创建角色书分支。

## 持久化与可见性

独立书由宿主分配 ID。封存生成不可变版本，引用保存书 ID、版本 ID 和内容哈希。归档之后仍可读取已固定的版本。书库使用独立的 SessionRecords scope，带 CAS 和操作去重。创作页的普通封存操作通过持久化的本地发布意图，将角色书目与作品存储返回的精确版本关联。同一个发布意图只能确认一次。原始角色卡导出继续读取标准角色定义。

玩家档案推荐不会自动授予角色阅读权限。每个授权记录保存明确的成员实例 ID。选择“当前全部角色”时，由宿主将其展开为当时在场的成员。会话源修订发生变化时需重新核对。角色书分支固定来源处的成员边界、身份快照及角色版本。选择历史消息作为分叉点时，使用该位置的参与区间和已生效的授权。导入前已经存在的消息只继承当时固定的角色书目。更改读者、切换版本及解绑均生成子分支。父分支和兄弟分支可继续读取各自的快照。

## 决胜与装配

先从可见成员和消息中确定目标角色的扫描范围。相同独立书的有效版本按会话、角色、玩家的顺序选定；同层异版对同一读者产生冲突。跨来源同版扫描一次，各可见来源可在审阅时核对。卡内书始终随该角色的精确模板版本。异书同名、相同关键词或导入 ID 仍分别处理。

扫描深度、关键词、常驻、有界递归和单书预算沿用既有选择器。递归限于本书。多个来源竞争本次请求的角色书预算时，先按条目优先级，再按会话、角色、卡内、玩家，最后按绑定顺序和条目原序决定。接纳的条目按人设前后分区及插入顺序排列。预算挤出旧消息时，用最终保留的可见历史重算触发。仅有卡内书的旧分支沿用原装配器。显式启用新版的分支可运行卡内 V3 受限正则，详见 [V3 创作与运行](./CHARACTER_R5A_V3.md)。预览与离线宿主共用最终消息和请求哈希；精确重生成读取原请求保存的消息。

## 运行与排障

新增接口位于现有同源工作台的 `POST /rpg-app/api/authoring/characters/books`。作者侧书目、推荐和各成员绑定的确认视图供本机作者使用。指定成员的预览、上下文和请求诊断只返回该成员的可见内容。浏览器可以提交书版本、读者和输入；书正文由宿主按固定引用解析。审阅与确认使用同一修订和来源快照。缺失版本、哈希不符、同层异版及过期修订会阻止写入。

本交付的角色书分支使用 RevisionFixture，本地预览不需要服务商凭据。原入口与正式服务商的受控授权合同沿用原设置。故障后只核对同一个请求及回执，未知状态保持占用并冻结相关绑定；已派发请求不会因刷新而再发送。R4c 供应商未结费用不由本模块结算。

在独立目录中，以 `node --test --test-concurrency=1 "character/book-library/*.test.mjs"` 运行书库专项测试。从实验目录运行 `node character/book-library/preview.mjs <独立数据目录> <创作端口> <群聊端口>` 可启动只监听回环地址的中性预览。停止该进程后，书库和分支数据保存在原目录，既有工作台和会话可以继续使用。
