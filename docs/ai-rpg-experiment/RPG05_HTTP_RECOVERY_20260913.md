# RPG05 HTTP 500 恢复与质量复核（2026-09-13）

HTTP 链路完成恢复验证：只重启原隔离 newAPI 后，经实际 UI 连续完成两次 Luna 生成、结构校验及正式保存。角色扮演质量仍未通过，本轮自由开局候选未替换 18409 人工入口。

## 定位与处理

- 旧失败与本次新增额度的第 1 次，均对应 newAPI 连接官方 API 时的 TLS handshake timeout，分别约 10.09 秒与 10.14 秒。失败发生在收到模型正文之前；账本中的 unknown 保持原样，失败同样消耗授权。
- 核实渠道直连官方地址、没有渠道专用代理；未读取密钥或复制数据库。
- OpenSSL 及 Go 无凭据握手探测成功，不等于实际模型调用就绪，也不足以把错误归因于 Go 算法。Go 对照探针使用本机已有 1.26.5 镜像，实际 newAPI 编译版本为 1.26.1，不能声称完全同版本。
- 确认没有进行中的调用后，仅重启现有隔离 newAPI 容器。容器 ID、镜像、挂载和配置未变。18409 人工宿主与 18305 模镜路由未重启。
- 重启后两次真实调用成功，模型均为 gpt-5.6-luna，输出上限 4096，temperature=0，无自动重试、供应商切换或额度重置。未修改提示词、防截断协议、TLS 校验或超时。
- 已证实直接错误是 TLS 握手超时；更底层的瞬时网络或进程状态触发原因尚未证实。“重启后恢复”不能作为永不复发的保证。

公开源码核对发现，此版本使用默认 HTTP Transport 并采用 10 秒握手期限。来源：[newAPI 精确版本客户端](https://github.com/QuantumNous/new-api/blob/bc14c18f6024e79cba1c08d02cd007796e12d668/service/http_client.go)。Go 官方对 TLS 默认行为的说明只用于诊断假设，没有据此调整服务配置。[Go 1.26 说明](https://go.dev/doc/go1.26#crypto/tls)

## 质量结论与用户对照

首轮正文 626 字符。第二轮叙事字段 811 字符，其中推荐动作前正文 609 字符；推荐动作同时出现在正文和可编辑按钮中，不能把重复内容算作叙事提升。

当前仍有：蛊世界辨识度偏弱、商店面板声称缺少条件、管事离开与仍在门口的连续性不够自然。虽然欺压和对话冲突增加，尚未达到用户要求的拟人感、情感与真实感，因此停止后续派发并保留最后一次额度。

用户本轮补充了原站同角色、同开场、同世界的回复，模型名称未提供，且天赋与当前 UI 配置不同。它是用户提供的定性对照，不能证明差异由某一模型或某一句提示词单独导致，也未独立核验其原站运行过程。

对照中值得学习的是：把蛊材、空窍、蛊师地位与异人处境落实为具体事件；NPC 有自身利益和动机，威胁有现实后果；感官描写和人物反应共同推进场景。后续应定位这些能力在当前发送上下文中为何不足，避免只延长正文或再加验收话术。不得把赵烈、洗蛊窟等具体生成内容硬编码成新模板，也不照搬替玩家决定行动、内心或未声明权限的部分。已审计防截断协议仍不在修改范围。
