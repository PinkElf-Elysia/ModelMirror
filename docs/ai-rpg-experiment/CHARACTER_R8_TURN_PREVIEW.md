# R8 交付点 1 · 群聊发言顺序预览

在 `0d0a909a` 上扩展现有群聊页。折叠面板可在发送关闭的宿主中使用。玩家手动发送和接话仍用原来的回应者选择。受控语音继续延期。

## 规则与接口

`POST /api/groups/:id/turn-preview` 是只读计算。使用原有 loopback、同源、所有者 cookie 和 CSRF 校验。请求含 expectedRevision、mode、order、muted、text；宿主只从核验后的群视图取得成员并检查修订。order 须包含本群全部角色实例且无重复，muted 仅允许本群角色。预览响应只含 groupId、revision、逐成员 id／included／reason、count 和提及诊断。无持久化写操作、预算预留或生成调用。

- 固定顺序按玩家排列处理；提及模式只扫描本次预览草稿，最多 2000 个 UTF-16 单元，按首次显式提及去重。普通名字须完整匹配；同名、未知提及会阻止形成可用顺序。成员按钮插入 `@[序号]`，由宿主在该群修订的原始成员名单中解析到实例 ID。未解析的玩家输入仅用于本次诊断。
- 离场优先于静音。在场角色静音只影响规则选人；原有参与区间、手动回应者和手动发送草稿保持独立。
- 排序、静音、规则和预览草稿暂存在当前标签页，以群 ID 区分。刷新仅恢复设置。修改规则、切换群或收到新修订后，旧结果作废；过期请求返回冲突，迟到的响应无法覆盖新草稿。同源标签页用修订通知提示刷新，宿主在每次预览时独立核验。
- 后续有界轮次应由宿主重新求值并核验群修订、资格、预算与授权；浏览器呈现的名单没有派发权限。本交付点没有轮次启动、后台任务或旁白。

## 离线证据

- 执行 `node --test` 加群聊目录全部测试文件，共 58/58。覆盖 2/3 位角色、同名、重复提及、全员静音、缺席与重新加入、陈旧修订、异群 ID、无效参数、原宿主鉴权、重启与晚到响应。重复预览和读取后，真实中性群记录逐字段相同，包括预算、请求和历史。
- 独立 Chromium 在 1100px、390px 上走通固定排序、同名实例选择、刷新、跨标签页变更及离场／重新加入。网络观测只出现本机请求；预览操作只调用预览接口。浏览器手动修改在场状态的验收使用独立 QA 群。预览宿主未安装生成执行器，任务额度为零。
