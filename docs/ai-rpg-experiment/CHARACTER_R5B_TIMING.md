# R5b 交付点 3 · 延迟和周期触发

新建或派生角色书分支时，勾选“在新分支启用延迟和周期触发”。在 V3 卡内书或独立角色书的条目正文开头逐行写规则，再写知识正文。

| 规则 | 核对时点 |
|---|---|
| `@@activate_only_after 2` | 已有至少两条可见角色消息时，允许该条目参与匹配。 |
| `@@activate_only_every 2` | 可见角色消息条数为 0、2、4……时允许匹配。 |
| 两行同时声明 | 两项条件都须满足。周期从 0 起算。 |

两个参数均取十进制安全整数。延迟可为 0，周期从 1 起。无效声明、重复同类声明和回退链保留原文并跳过。满足时间条件后，还须满足关键词、正则、一次性、禁用状态和预算等已有规则。与一次性或条目扫描深度组合时，在该分支同时启用对应规则。书架可输入模拟的可见角色消息条数，实际续聊时仅宿主计算该值。

计数来自请求所属分支、目标成员可见的完整历史。群聊中本人和其他角色的可见发言、可见角色开场各计一条。玩家输入、缺席期间消息、未送达的私信、候选和未入史的部分结果均不计。窗口和容量裁剪影响关键词可见文本；计数仍来自完整可见历史。预览与刷新只读。请求完成并采用为正式回复后，下一次预览才看到增加的条数。精确重生成复用原请求。派生到玩家输入和派生到随后的角色回复，二者计数可相差一条。

分支策略为 `visible-character-messages/1`，独立于扫描深度和一次性策略。继承点早于启用时刻的子分支需显式启用。旧分支继续走原装配；兼容读取绑定已核验的精确运行指纹。回退时停止专用预览，保留独立数据目录。

在实验目录运行 `node --test character/book-library/timing.test.mjs`。本地演示可用 `node character/book-library/timing-preview.mjs <独立目录> 0 0`。从初始渡口开场输入“报时”，先预览，再生成一次离线夹具回复。再次预览“报时”即可看到第二条可见角色消息使两项条件同时满足。

格式依据来自[固定版本的 CCv3 装饰器规范](https://github.com/kwaroran/character-card-spec-v3/blob/f3a86af019fbd99f788f7a1155f399655b34ab35/SPEC_V3.md#activate_only_after)。
