## 发现、修复及限制

本批修复了比较占位导致未知提示、采用后预览残留提示、关闭面板后宿主状态不跟进、旧记录关闭时覆盖候选草稿、未派发候选仍显示“等待完成”、候选预检期间可编辑造成配置错位等问题。

完整保留运行过程中的失败：

- 一次临时服务通过 stdin 的 `node --input-type=module` 启动，Worker 继承该标志，错误表现为展示资源限制。改用普通 .mjs 入口重开同一数据目录后恢复；没有改宽展示限制。
- 六卡重开时发现插件注册表 `owner.lock` 尚不支持自动回收已死亡进程。仅对本批临时目录中已证明所属 PID 死亡的两份锁做保留式改名，未删除账本。**因此不能把此次结果写成“六卡异常退出后全自动恢复通过”；这个 C1 生命周期缺口仍须补齐。**
- 构建过程一次回调可选参数类型不匹配，已修正并重新通过。Vite 既有动态/静态混用导入警告保留。

下一子批仍需：

1. “设为后续剧情配置”的权限、配置和双端交互。
2. 更多模型/高级参数、跨模型预设冲突、停止词与思考参数的完整 UI 矩阵；大量旧记录入口及更全面移动键盘验收。
3. 六卡插件 owner 锁的异常退出自动恢复，不能用手工归档临时锁替代产品恢复。
4. 最终另行授权真实供应商验收、完整插件组合、实际费用与取消能力；本批不新增这些授权。
