# P2-C2 聊天参数会话与冻结请求

## 任务卡（实现前）

- 本批目标：在通用作品的正式 JointSessionHost 中接入聊天参数插件，持久保存剧情／摘要／记忆覆盖，并通过既有受控传输捕获实际三用途请求。只做离线验证。
- 工作区 C:/tmp/modelmirror-rpg-generation-chat-parameters；沿用 P2-C1 累积候选。18662、18664 仍使用原工作区，源码、进程、会话、配置与额度不改。
- 创作原生宿主保持默认行为。新增宿主选项只用于新聊天合同会话；旧记录不静默迁移。参数覆盖独立于默认模型，应用不能选择其他模型。关闭插件保留覆盖，下一批请求使用默认配置；能力或模型失配明确阻断。
- 参数写入在正式会话队列内做操作 ID、会话／模型／参数／用途 revision 校验。原子保存配置、解析结果和插件回执。重放原操作只查回执，不重复验证或写入。
- 每次发送冻结参数授权、配置 revision 及各用途选择 hash；正式剧情、M2（含压缩）、M3 从同一冻结快照取实际参数。派发前在同一个插件队列内联合检查，避免嵌套锁；已派发任务按原记录收束。
- 本批不增加 HTTP/UI 入口，也不宣称六张旧卡固定参数管线已完成。参数分支继承另批接入，当前新聊天合同明确阻断分支，防止丢失配置或误继承授权。
- 文件范围：chat-parameters.mjs、joint-session.mjs、joint-session-state.mjs、summary-state.mjs、memory-state.mjs、summary-jobs.mjs、memory-jobs.mjs、runtime-plugins.mjs、history-control.mjs、plugins/host.mjs、generation-session.test.mjs、本文。超过五个是因为同一冻结参数合同必须同时经过正式记录、三用途来源校验、联合权限门禁与恢复诊断；不扩展到前端或六卡旧管线。
- 验收：三用途实际 wire 参数与默认值；授权／用途／模型隔离；停用回退与重新启用；多标签 CAS、重复操作、保存失败／提交后未知、能力变化、派发前撤权、派发后停用、重启按原 ID 核对；原创作零插件路径回归。
- 回退：关闭新聊天合同选项，保留独立目录中的会话与请求记录，已派发记录仍用原宿主核对。无迁移、依赖、真实模型调用、认证、额度变更、共享部署或 Git 发布。

## 接线合同与范围

- 候选宿主以 `JointSessionHost.open({chatParameters:true,...})` 显式选择新聊天合同，配套 `createAuthoringHistoryControl({generationParameters:true,...})` 提供受信包。默认均关闭；现有原生创作调用不需要参数插件。
- `models.current` 保存三个用途的默认模型及其控制面默认参数；`generationParameters` 保存三用途覆盖、逐用途 revision、全局 revision、原操作、控制面解析及插件回执。切换模型不重写覆盖；不兼容时可查看旧配置，发送阻断，须明确重设或清除覆盖。
- `parameterCatalog(sessionId,purpose)` 需参数插件授权，只返回该用途已选模型的能力。`configureParameters` 使用正式宿主锁，接受操作 ID、会话／模型／参数／用途预期 revision 与 P1 类型化选择；不接受任意供应商字段或可信解析结果。`choice:null` 清除当前覆盖，历史不删除。
- 参数插件不能选择模型。聊天中的默认模型选择仍由模型选择／摘要／记忆权限分别控制；默认配置只接受控制面默认意图，不能用原生配置接口绕过参数权限。已有默认模型配置后，即使停用模型选择插件，参数插件仍可独立调整参数。
- 聊天发送与预计额度请求须携带 `expectedParameterAuthorizationRevision`，来自当前会话读取的参数授权；其他标签页停用或重新授权后，旧发送先阻断，重新读取后才按新配置发送。原生创作意图保持原格式。
- 每个正式 run 保存参数 revision、授权版本和三用途选择 hash。剧情、摘要、压缩、记忆的完整请求继续保存实际参数意图、控制面解析、供应商字段和请求 hash。历史校验重新推导冻结选择，不能在重启后用新设置改写旧任务。
- 插件 registry 同一队列联合检查上下文与参数授权，在实际网络开始前完成；不会嵌套占用两次队列。参数停用不会撤销已经派发的结果，但会阻止该轮尚未派发的后续阶段；恢复只核对原任务，不自动启动余下阶段。
- 本批没有 HTTP 或界面入口，没有修改六卡旧参数管线。聊天新合同的分支继承尚未接线，显式返回 `CHAT_PARAMETER_BRANCH_UNAVAILABLE`，能力声明为 `branchExecution:false`；现有原生作品分支不受此限制。六卡、HTTP、参数面板、预设操作及聊天分支仍为后续门禁。

## 验证结果

核心回归 **343 项通过，0 失败、0 跳过**；其中正式参数会话 49 项含本批新增 17 项，原生三用途与分支 194 项、插件 71 项、旧卡片宿主 29 项。单独执行的 17 项聊天检查和贯通探针是重复验证，不重复计数。所有控制面、供应商和凭据均为本地测试夹具；没有真实生成、认证或额度写入。

| 日志 | 结果与证明范围 |
| --- | --- |
| native-final.log | 49/49；正式会话全部参数测试，包含 17 项聊天测试。命令中的负向筛选未排除这些聊天用例，按实际报告记数 |
| context-final.log | 194/194；原生 M1/M2/M3、分支、存储故障、进程退出及未知恢复 |
| plugin-regression.log | 71/71；受信包、权限、安装、逐会话授权及联合守卫 |
| legacy-final.log | 29/29；旧宿主默认参数、选择、分支、授权与 HTTP 路径 |
| chat-final.log | 17/17；单独聊天回归，与 49 项中的用例重复 |

三用途捕获使用真实宿主和 ControlledProvider，经本地 HTTP 假控制面调用实际 Python 参数解析器；不是直接模拟一个派发返回值。两轮捕获依次为剧情、记忆、剧情、摘要、压缩、记忆；逐份核对实际供应商字段、参数意图、解析 hash、回执和正式原文。摘要压缩继承摘要参数，不借用剧情或记忆参数。

保存前／提交后故障、多标签 CAS、原操作重放、能力漂移、参数提案后撤权、派发前撤权、在途停用、未知剧情／记忆的重启核对均覆盖。未知恢复期间即使控制面能力目录不可用，也只核对原请求，不重新生成。默认模型变化后保留原覆盖并明确阻断，显式清除后才用新默认值。

核心回归后的收尾只修正 `readiness.branchExecution` 为新聊天合同下 false，补上聊天／原生两种状态断言并恢复未改动行的原换行；最终三用途与分支定向复测 **3/3 通过**，见 closeout-regression.log，属于重复验证，不增加 343 项总数。核心版本 hash 与最终版本 hash 分开保留，未把不同源码的回执混成同一份证据。

18662、18664 的 7 项页面／作品／会话 GET 均为 200，响应 hash 与 P2-C1 结束时完全一致，三个原会话 revision 仍为 6、1、0。原工作区 319 个源码 hash 全部不变。没有重启原进程、刷新容器或修改原会话、资源和账本。

保留首次测试日志：`native-regression.log` 的 25 项失败来自运行中修改候选源码触发 `OFFLINE_FILES_CHANGED_RESTART_REQUIRED`；未关闭此保护，已停止改码与测试并行。`session-regression.log` 为 44 通过、1 失败，失败是新测试把同步非法输入拒绝写成异步断言；已改为精确的 `assert.throws`。`context-regression.log` 在新增授权版本边界前主动停止，属于未完成检查，不计通过总数。最终日志单独保存。
