## 参数合同（P1 实施）

能力 v2 由控制面提供，按模型、路由、用途、能力 revision 绑定，含字段 ID、值类型、默认策略、范围/枚举、列表边界、required、互斥及依赖条件。供应商 wireName 仅在服务端可信映射中。不得接受任意 passthrough 字段。

- 基础：temperature、topP、maxOutputTokens。
- 高级：topK、frequencyPenalty、presencePenalty、stop、seed、thinking.enabled、thinking.effort、thinking.budgetTokens，按模型实际声明展示；不推断支持。
- 值来源分别记录 default / explicit。未知默认值显示“由供应商决定”，不伪造数值。required 字段若无受信默认则要求填写。
- provider default 可为省略字段或显式受信默认；冻结请求须同时保存解析策略、有效字段及 hash。
- 互斥/依赖采用有界声明式条件，不允许源码、函数或任意表达式；能力不明、改变、预设过期均阻断，保存用户草稿供核对。
- 剧情、摘要、记忆分别保存 revision；compression 使用摘要用途配置，但仍具有独立任务 ID。
- 日常应用只影响当前会话；明确操作另存预设/作品推荐。作品推荐只进新发布版本，旧会话不改；导出不含凭据、资格、额度或插件授权。
- 按用途与模型保存预设。跨模型应用展示不兼容项，用户处理前不能应用。
- 更换剧情模型不改变摘要/记忆模型；参数插件只改参数覆盖，不赋予摘要/记忆的启用权限。
- 保存/预检/预设操作零调用；应用前展示下一轮实际模型、参数来源和生效用途。

## 对比合同（C1 实施）

1. 检查上下文 revision、授权、模型资格、能力、容量及整个最坏任务清单。
2. 为同一 batchId 依次建立本地和控制面原子额度预留；两层确认前不能派发。某层失败则释放可证明未派发的预留；预留状态未知先核对。
3. 必要的 M2 发送前补齐只一次，独立 ID；之后冻结原始输入、历史、持续要求、变量快照、摘要、M3 召回、世界书判定和公共消息 hash。
4. 公共上下文不能为小模型静默裁剪；所有候选分别容量校验。pre-M2 结果改变容量时重新预检，剩余候选未派发则不耗其次数，已完成 M2 仍记账。
5. 排队最多四份，同时最多两份。每候选保留能力与配置 revision、独立 operationId、实际模型/参数、请求 hash、原文、回执、终态。公共消息 hash 相同，包含模型参数的请求 hash 可以不同。
6. 候选落盘不推进正式历史、变量、CG、M2/M3。预览只运行现有隔离展示，不运行模型脚本。
7. 采用以 expectedContextRevision + adoption operationId 原子 CAS，一批只能一次。候选进度 revision 不导致合法采用失败。
8. 正式采用记录先落盘，再按持久步骤推进正式回复、变量、CG、M2 → M3。每步幂等 checkpoint；重启只继续未完成步骤，不重新生成。
9. 可提前采用已完成候选。其余任务和后台收束前下一轮阻断；采用不自动取消。停止其余候选仅停止队列，已派发按取消能力核对。
10. 放弃批次保留记录，输入回草稿；若草稿已改变，展示可恢复输入，不覆盖新草稿。活动请求仍须收束。
11. 迟到候选只补记录，不进入正式剧情；已撤销授权的结果不可采用。已提交的采用不回滚历史。故障/未知不自动重试、认证、换路由或模型。
12. 浏览旧对比只读。采用后的其他候选需走已有显式分支流程，不新增自动分支。
13. 导出作品不含会话对比记录或账本；分支只继承分支点正式状态，不带父路线未采用候选进入上下文。

### 费用清单

N 个候选 + 发送前 M2 0–2 次 + 采用后 M2 0–2 次 + M3 0–1 次。上限 N+5（N≤4，即最多9），按具体任务清单缩减；首次/无待整理历史遵循既有规则。原型可通过演示条件看到 2/3/5/7 等上限，不作为真实余额。

未派发部分释放；已派发、失败、取消和未知保留调用记录，费用按回执记，缺失显示“暂无费用数据”。明确被控制面拒绝且证明未派发的操作不冒充供应商调用。刷新不会新增预留。

### 接口分层（路径族提案，P1/C1 再落具体路由）

- 控制面：能力目录 v2、参数预检；候选批次的额度预留/确认/释放/核对。模型网络调用只由控制面发出。
- 宿主：三用途参数配置/预设/作品推荐；比较批次 preflight、create、read、stop、reconcile、adopt、discard。
- 创作 /rpg-app/api/authoring 与卡片 session 路由调用同一参数服务和比较协调器，禁止复制一套执行逻辑。
- 写操作统一 operationId、expectedRevision；采用另外绑定 expectedContextRevision，后台进度单独 candidateRevision。
- 新数据采用版本化旁路记录，旧会话不静默迁移或改写冻结请求。遇到不兼容旧合同提供明确的新会话路径。
