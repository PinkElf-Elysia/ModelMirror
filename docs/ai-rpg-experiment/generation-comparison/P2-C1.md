## 验证结果

最终候选工作区实际执行通过 **112 项，0 失败、0 跳过**：插件回归 71 项（含本批新增 22 项），旧聊天/创作宿主回归 41 项。新增测试的卡片对象是宿主投影样例，只证明授权兼容门禁，不能证明六卡请求或界面已完成接线。

- 新插件受信包与权限、artifact/manifest hash 绑定；旧八插件声明及默认目录未增加新入口。
- 安装与逐会话授权分离；新会话/分支不继承授权，重装不恢复授权，旧启用操作重放不会重新授权。
- 宿主已验证的参数配置 hash、用途、会话和参数 revision 与提案绑定；不同用途和伪造提案不可交换。三用途提交回调验证其他用途原样保留。
- 忙碌/未知请求阻断配置与重新启用，仍允许停用；迟到提案和变更后的授权不能提交。
- 派发前检查使用冻结的授权、会话和参数 revision。已开始的异步结果不占住授权队列，停用后仍能收束原结果；没有自动重试。
- 提交回调失败会消费票据；回调已落盘但响应未知时，宿主记录保留。插件不再次执行回调；正式会话的原操作恢复仍由后续宿主接线实现。

## 后续宿主接线合同

1. 完成参数持久化和受控请求适配后才使用 loadReviewedPlugins({generationParameters:true})。会话投影须明确 generationParametersCompatible=true 和非负 parameterRevision；仅出现在 compatibleCards 中不能通过授权。
2. “生成参数”不具有 session.model.select。读取能力时宿主仅返回当前用途已选模型；保存时由宿主验证 profile 与该模型一致，使用控制面的 P1 v2 预检/解析，不接受供应商 URL、凭据、任意字段或前端自报的可信解析结果。
3. 在正式会话锁内验证操作 ID、会话/参数/用途 revision 后，由宿主计算 configurationHash，内容至少绑定原操作、会话、用途、所选模型、参数意图与控制面解析。宿主验证票据的用途和 hash 后，通过 commitResult 原子保存参数及原操作回执；票据只可提交一次，不能充当持久回执。
4. parameterAuthorization 区分明确停用与失配/未知授权。停用时使用宿主的实际默认配置，保留覆盖和历史；失配/未知必须阻断。创建、复制、发布或安装均不增加额度。
5. 请求冻结和落盘后、实际网络派发前，在同一宿主会话锁内调用 startParameterDispatch，传入那一刻的会话、参数及授权 revision。start 回调必须同步开始受控派发并返回 response promise；不能先排队再自行绕过检查。已派发结果按原请求收束，参数插件停用不取消或重写它。
6. registry 全局队列只围住最终授权检查、原子提交或同步派发开始，不在生成完成前持续持锁。宿主必须沿用自己的会话锁，不能把这个保护当作完整会话事务。

上述是后续接线约束。本子批没有改造原卡片的固定参数管线，也未给聊天用户显示或启用此插件；不得将这批授权测试称为六卡参数功能完成。
