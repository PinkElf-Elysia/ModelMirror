# R8 群聊发言与旁白收口

三个交付点已完成人工验收。本轮组合基线为 `0d0a909a06d1337415b604154bd4f87a3926c8e4`（PR #529 合并结果）。独立检出的干净主线与 R8 实施基线相同。验收只使用本地中性夹具和确定性回执。

| 交付点 | 玩家能做什么 | 宿主保证 |
|---|---|---|
| [发言顺序预览](./CHARACTER_R8_TURN_PREVIEW.md) | 选固定顺序或按玩家显式提及排序，核对静音、离场和同名实例 | 预览不写消息、不预留额度。群修订变化后须重新预览。 |
| [用户启动一轮](./CHARACTER_R8_SERIAL_ROUND.md) | 确认后串行发言，处理中可停止，刷新后可查看或明确继续 | 每轮一条玩家消息，每个合格成员最多回应一次。每步重新核验群预算和共享预算。结果未知保留原请求及预留。 |
| [显式旁白与回看](./CHARACTER_R8_NARRATION.md) | 在启用旁白的新群记录场景，查看历史轮次的原消息、发言实例和完成状态 | 旁白具有独立身份及手动来源，仅发布时在场成员可见，保存不派发、不计费、不写世界事件。回看只读。 |

串行执行与新群旁白限本机 fixture 宿主。旧手动群聊保留原入口。群账本负责玩家消息、派发及回执；轮次记录负责冻结顺序和停止决定。旧群恢复继续校验精确运行描述符。停止后，在途请求仍可结算，后续成员不会再获派发。

## 失败、修复与待验

- 两个历史世界基线 `a6563a9b`、`3fffd5b4` 的 Offline、Summary、Joint 共六个场景，干净主线与组合版本均在恢复时分别报 `AUTHORING_RUNTIME_BINDING_MISMATCH`、`OFFLINE_SESSION_CORRUPT`、`JOINT_SESSION_CORRUPT`。这六个场景的续聊与后续篡改断言仍待验。历史测试文件报告四个失败项，其中一个汇总了三个场景。
- Provider 静态审计首次显示两个 R8 模块的登记已过期。复核浏览器同源请求和群宿主派发路径后，仅更新这两个模块的精确指纹。最终仍失败，输出与本轮干净主线的 1,053 行诊断逐字节相同。没有调整检测器。
- 交付点 2 首次浏览器验收过早读取异步状态，改为核对持久化终态；首次行尾检查及修正有记录。交付点 3 首次桌面验收发现回看已取得回执、发言面板仍等待，修正同步后两种宽度通过。首次父前端构建缺少 card-replica 的锁定依赖，离线补齐后通过。
- 本轮帮助门禁首次发现截图宽度不合要求，帮助内容测试首次发现三张原有截图尚未登记为历史基线。按桌面、窄屏原始布局重新拍摄，并登记三个确切旧路径；保留首次日志，最终门禁通过。[R7 原有失败与中断说明](./CHARACTER_R7_ACCEPTANCE.md)继续有效。
- 真机软键盘、触控、系统返回、原生文件选择器取消，以及 Safari、设备解码和扬声器仍待验。受控语音延后。R4c ①人工采纳及精确端点、②处理中刷新后的实时增量及精确端点待证。④仅证实宿主停止读取，供应商最终计费待证，保留 **US$0.018990** 未结预留。未运行全仓 CI 或真实模型、语音服务验收。
