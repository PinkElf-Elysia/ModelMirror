## 冻结的产品行为
插件 rpg.history-window，首版精确版本候选 1.0.0，策略 rpg.history-window/1。
服务实例安装、会话授权独立；默认未安装、未启用。只兼容 M1 新运行版本会话。
启用默认最近 3 个完整历史回合，整数 1–50；一回合是一条 user 和对应 assistant，当前输入不计。
开局角色资料开关默认关闭；关闭时不补入。打开且首轮不在窗口时，在最早保留 user 的开头补入一次：

    开局角色资料（原始快照）
{characterText}

{原 user 内容}

characterText 逐字来自服务端原始快照；不是当前状态，不自动更新。只改本次请求副本。
卡内 Long/Short Memory 是 assistant 原文的一部分，整条携带，不识别、提取或单独注入。
完整历史永久保留；关闭或卸载恢复完整历史，不补资料。保存、启停均不调用模型。
未安装或停用时配置默认值/保留值均只是待用设置，不代表生效。

## 装配边界
首轮由真实会话完成进度 T=0 判定，沿用 system → 角色资料+玩家输入，无前后置词。
续轮为同一 system → 最近 min(T,N) 完整回合 → 本轮既有前置词+输入+后置词。
历史 user 已装配过，逐字复用。世界书继续按既有策略运行，不改变扫描范围、规则或默认关闭状态。
模型参数、已批准作者文本及已授权的历史单句删除保持基线，不在本轮重审或改写。
容量不足由控制面拒绝，不自动缩窗、重试、换模型或修改输出上限。
ASSEMBLY-EXAMPLES.json 使用占位作者文本和虚构角色，仅用于冻结合同；不冒充宿主请求验证。

## 宿主与接口合同
GET/POST /rpg-app/earth/api/sessions/:id/history-window。
POST 严格接受 operationId、expectedSessionRevision、expectedConfigRevision、turns、includeInitialCharacter。
GET 返回 compatible/reason、授权状态、保存配置及 revision、当前 effectivePolicy 和 historyPolicyRevision。
新版本发送必须带 expectedHistoryPolicyRevision；生效 revision 必须覆盖配置和授权有效状态变化，不能只比较数字窗口。
服务端冻结选中回合 ID/范围、有效策略、配置 revision、授权依据、是否补入、最终请求 hash；不进入模型消息。
派发前在同一会话并发边界重验授权及 revision。明确停用走全历史；未知权限不能静默换装配。
保存、发送、模型切换、分支共用并发边界；pending、未知请求或未知设置操作阻止修改。
operationId 相同且载荷相同恢复已有结果；同 ID 不同载荷拒绝。未知保存先按相同 ID 查询恢复，不换 ID 重放。
保留现有同源校验、原子提交与可恢复操作记录；插件无网络/模型派发/任意文件接口。

## 分支与版本
M1 独立运行版本绑定装配器及策略版本；零插件路径与基线消息一致。
旧会话可读，明确提示不兼容，不升级或追认版本。
分支完整继承截至节点的历史；待用窗口配置来自分支点回合记录，不取父路线当前配置。
分支未继承插件授权，生效全历史。继续使用窗口须在子路线主动启用。
所有路线沿用同一服务端预算；模型切换、重装、新会话不新增预算。
停用/卸载撤权但保留配置和原始历史；重装需重新授权。

## 分批门禁与验收
- B0：本合同、装配示例、市场/会话/设置桌面与 390px 手机原型；用户批准后进入 B1。
- B1：纯策略、生命周期、配置存储、新运行绑定；离线验证后单独交付确认。
- B2：假 Provider 捕获真实宿主请求，逐字验证窗口及关闭路径、分支/模型切换/撤权/失败恢复；用户确认。
- B3：正式 UI、帮助、生命周期键盘手机重放、原插件/Studio/地球卡测试、两处生产构建；用户确认。
- B4：另行额度内真实历史超过窗口的续玩；装配证据和卡内记忆质量分开报告，每份用户审阅。
每批围绕一个目标，尽量最多五个受版本控制文件；B0 原型与证据可拆成两个小批。
必要边界：T<N/T=N/T>N、N=1/50、非法值/未知字段、开关/首轮进出、零插件字节一致、不改历史/原文、未完成回合排除、父子隔离、重复/冲突/撤权/落盘失败/未知恢复。
