## 长期目标
插件化大世界 RPG Harness：作者组合世界内容、规则、人物、模型运行策略和交互表现，创建可运行、保存、恢复、回放的 AI 原生 RPG。世界包为可复用模板，存档为独立实例；游玩操作与明确创作改写分离。
状态／工具层负责确定查询、校验和结算；调度层负责上下文、预算和恢复；叙事层依据确认事件表达人物和剧情。
单／多模型、单／多阶段、固定工作流／自主工具调用、单／多角色是四个独立维度，数量不是成功指标。

## 长期路线
| 阶段 | 目标及门槛 |
|---|---|
| S0＋S1 首轮 | 单卡商店、权威状态、可靠叙事、恢复和兼容；完整场景和实测正文／成本证据 |
| S1 后续 | 第二题材验证同一能力复用，再增加检定／旅行；查询和模型分工按收益启用 |
| 作者与世界包 | 多个实际需求稳定后形成模板、内容／规则／表现预设、作者配置和版本管理 |
| S2 | 角色模板与实例、身份／目标／语气、私有记忆和可知范围；先验证单人对话的人设与记忆稳定 |
| S3 | 少量角色依自身目标和认知主动行动，由宿主裁定；验证多视角、合理冲突合作，胜过结构化单模型基线 |
| S4 以后 | 离场演化、模拟时间与分级调度、势力、导演、地图和战斗；逐项验证因果、可玩性、恢复、费用 |
| 更后期 | 在玩中创作小说的分支工作区、外部 SDK、第三方隔离、自然语言生成插件及社区分发，另行立项 |

世界事实、角色认知和玩家所见分开；未来角色提出意图，宿主裁定提交。秘密在上下文组装时隔离，不能先给全局秘密再要求保密。自主性不等于无视玩家指令，无因随机事件不作为涌现证据。

## Harness 方向与本轮边界
**本轮落实**：动作／表现分离，内容／规则分离，字段唯一维护，操作／状态／规则版本关联，按用途上下文，规则与供应商解耦，现有插件注册和生命周期，原稿与运行适配分离，资产保留及明确改写。
**仅记录设计**：借鉴服务接口与实现分离、按作用域组合、插件生命周期；不迁移到 DeepSeek Harness，不引入依赖。没有当前调用方的接口不造空实现。
**后续实现**：第二卡、完整经济／地图／战斗、角色私有记忆、通用编译器／动作编辑器／依赖解析器、热升级迁移平台、市场与第三方代码。
