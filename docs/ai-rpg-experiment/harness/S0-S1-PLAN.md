唯一维护方：交易／改写宿主维护银行卡、三商品数量与库存；叙事只维护原卡未接管内容；总结与记忆只能写各自历史资料；显示正则和 CSS 只影响投影。模型快照、正文、世界书和插件文本均不是交易提交来源。

`界面／解析 → 明确动作 → 纯规则 → 宿主授权与 CAS → 回执／面板 → 叙事 → 已启用记忆阶段`。
纯规则模块没有 IO 或供应商调用。余额、背包、库存、事件、回执与待叙事同记录提交，正文按 eventId 幂等投影。

## 玩家路径
1. 旧地球 OL 聊天选择“交互商店”，或进入独立示例。
2. 示例初值 100 元；旧会话余额留空，由玩家核对确认。受管商品持有量也需确认，不从文本猜账。
3. 启用创建独立分支，保留来源 ID／revision／hash，原会话不写入。复制有效 Mod／自定义配置及总结、记忆快照；开关逐分支明确确认。
4. 点购买两个面包，先得到余额 100→88 元、面包 +2、库存 2→0 回执；模型随后叙事。明确短指令“买两个面包”走同一规则，只有歧义输入增加解析。
5. 失败购买显示原因、无扣款，无需叙事调用。未知请求必须核对原 ID，不能换 ID 绕过。
6. 明确叙事失败可以仅重试叙事或只留回执结束。正文已成功而记忆失败，只恢复记忆；也可保留已完成正文并明确标记记忆未完成。
7. 改写须提供原因并展示前后状态，产生新事件；检查点创建新分支恢复相应资产和记忆。停用停止新动作，保留资产、阅读与恢复。

首次启用的有效结构化账户适配尚无旧卡统一字段来源；当前不冒充“已验证快照”，旧数据使用明确的 `user-confirmed` 来源。已有结构化模板不等于可以直接信任的数值账本。

## 恢复及限制
- 同操作号同请求返回原结果；同号异请求拒绝。不同操作竞争同 revision 只有一个成功。
- 存储结果未知先核对提交标记；未落盘时要求重新确认，不自动创建新操作。进程测试覆盖提交后退出再重开，不据此承诺任意断电持久性。
- 每阶段一个主模型和可选一个备用；明确失败、可安全重试、费用额度允许才自动切换一次；未知不切换。手动恢复也不清零已有费用，最多三次。
- 每个分支额外有 100 次阶段调用保护、1000 个操作记录保护。达到上限明确阻止继续，不静默截断历史。
- 已冻结阶段配置不能在未完成回合里改写；模型不可用需核对，明确失败可结束该轮后配置。未派发的本地装配错误可重新装配重试。
- 显式余额矛盾可确定检测并阻止采用；不宣称识别所有自然语言逻辑冲突。
- 自定义配置作为启用时快照：前／后置词、世界书、Mod、历史／仅显示正则、受限 CSS 与背景已接入。预填明确拒绝，不静默忽略；任意语义冲突仍需人审。
- 总结沿用 v2 小总结与二十条合并规则：下一回合叙事前合并满二十条，正文后生成小总结与记忆。记忆召回包含继承的最后对话及本分支回合；私有角色记忆不在本轮。
- 商店分支暂不提供旧候选对比面板；旧会话仍可对比，旧生成／采用接口不能接受商店分支 ID。已完成交易不会作为候选生成副作用再次运行。
- 商店前端当前是完整正文返回模式。受控供应商桥复用现有 S2S 回执，但该接口未暴露实报 token／费用和首字时间；未知费用保守占用预留，不能记为免费。真实测量前还需补齐供应商用量与流式时间证据接口。
- 本轮独立界面支持商店与记忆开关快照，不搬运旧聊天的全部插件编辑面板。
