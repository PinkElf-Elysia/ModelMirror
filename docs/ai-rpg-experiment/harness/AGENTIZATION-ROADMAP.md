## 目标与阅读顺序

最终目标是插件化大世界 RPG Harness：作者组合世界内容、规则、人物、运行策略及表现，玩家在其中行动，经历可以形成可追溯、可分支的小说素材与 AI 原生游戏。世界模板与运行实例分开，游玩与明确创作改写分开。

当前阶段在角色卡工作树和多 Agent 集成之前独立推进，完成可运行、可扩展的 Agent 化链路。角色工作未完成不阻塞本阶段；不复制、不修改、不要求提前合并其实现。

链路：输入或界面动作 → 任务与上下文 → 模型判断／工具执行 → 宿主校验计算与统一提交 → 世界状态和事件 → 正文与表现 → 保存、恢复及分支。

## 已确认业务结论

- Agent 化是职责与调用调度拆分，不以模型、阶段、工具或角色数量作为成果。单／多模型、单／多阶段、固定流程／自主工具调用、单／多角色分别评估。
- 程序执行可确定查询、计算、校验和结算；模型理解歧义、提出语义变化与行动、表达人物和剧情。模型判断通过类型校验不等于客观正确。
- 声明规则默认约束结果；明确改写记录原因、前后状态与事件。正文、记忆、总结、地图、正则均不能成为另一份权威账本。
- 一张卡是适配器及验证载体，既不是框架本身，也不是把全卡打磨完才能推进的前置条件。每轮交付能力、适配与兼容证据。
- 原始素材保留，生效适配独立版本；旧会话不静默迁移。停用不删状态，不悄悄交回模型维护权。
- 普通回合不强制增加模型调用。未知结果先核对；自动备用须预配置模型、费用上限和明确安全失败条件，不重做已完成操作。
- 延迟、费用及正文收益用证据评估；没有真实对照不宣称下降。原有流程为相同行为增加的调用仍计入优化成本，不能全部算成新玩法。
- 原型范围适度：不因小量叙事误差持续增加补丁、全文审查模型或大规模实测。保留必要的幂等、版本和恢复保障。

## 独立 Agent 化阶段：建议五轮加整体收口

| 轮次 | 可运行交付 | 验收及后继条件 |
| --- | --- | --- |
| 第三轮：公共运行核心与卡片适配边界 | 从状态 v1／工具 v2 形成公共记录、回合执行、查询承载和适配端口；修仙＋一个原创非修仙测试配置使用同一核心 | 不复制第二套宿主；不在核心分支判断题材；旧模式不变；完整离线闭环。见具体计划 |
| 第四轮：上下文与生成职责分配 | 按任务装配材料，区分内容、规则、状态、叙事和展示，取消重复计算／面板输出职责 | 两个适配实例的上下文来源可查；世界书原语义保留；测量负担，实际正文效果另经授权 |
| 第五轮：工具登记与受限行动链路 | 内部只读、确定性计算及变更提议能力登记；执行权限、输入输出、限制和结果来源真正参与运行 | 模型按需选工具；普通交流可不调用；写入统一裁定；用测试工具验证，不扩地图等产品 |
| 第六轮：任务与模型策略 | 固定流程与受限循环组合，阶段模型、独立只读并行、累计预算、明确失败备用和恢复 | 一个业务动作可切换策略；已完成工具不重跑；同状态冲突写入不并行落账；费用可累计 |
| 第七轮：扩展与未来参与者接口 | 测试参与者的实例标识、任务归属、可读投影、观察与行动来源；模块启停及版本边界 | 无角色工作树依赖也能验证不同视图、同一提交出口；不是实际角色人设或私有记忆效果验收 |
| 整体收口 | 串联直接生成、查询、计算、提交、续轮、恢复和分支；整理接入说明与证据矩阵 | 至少两个不同状态结构复用链路；新增内部能力不复制核心；可交给角色侧接续，不宣称生产就绪 |

这是顺序与交付安排，不是固定日程。可按实际依赖拆分小批，不因轮数把未完成项藏进“以后”。不恢复已暂停的 RAG 工作。

## 本阶段完成与明确留后

本阶段完成：可信宿主下的可组合运行机制、独立实例和版本绑定、原生工具承载、受控调度、状态和事件一致性、表现接口及离线接入示例。由实际使用方验证复用，不建设只有接口没有使用方的空包。

后续正式角色对接：核对角色侧届时的精确版本，将模板／实例、观察、查询授权、行动提议与记忆归属接入。共享世界引用不自动赋予读写权限；不预定角色卡格式等同于运行结构。共享记忆、导入与分支策略继续待决。

后续 S3：少量角色有目标和认知边界，主动提出行动，宿主裁定冲突与合作，叙事层组织多视角。手动群聊不等于此能力。涌现须有原因和后果，不用无因随机事件或拒绝玩家指令冒充自主性。

后续 S4+：离场演化、世界时间、势力、导演，以及地图、战斗等逐项验证；世界包与作者预设在共同需求稳定后形成。

更后期：小说编辑与创作分支工作区、AI 原生游戏作者工具、外部 SDK、第三方隔离与社区分发，分别立项。借鉴接口与实现分离的原则，不据此迁移到外部 Harness 或引入依赖。
