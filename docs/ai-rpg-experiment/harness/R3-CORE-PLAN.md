## 2. 复用策略与实现形态

实现审计见 [R3-IMPLEMENTATION-AUDIT](R3-IMPLEMENTATION-AUDIT.md)。直接复用 SessionRecords、现有安全模板渲染、原生消息续传语义、计量与供应商受控边界；不要复制文件存储、重新建设模型网关或把状态塞进商店记录。

建议新增 agent-core 作为当前本地状态链的内部模块，不替换历史 runtime 包，也不添加 npm exports 或发布软件包。所有适配器由仓库内可信静态代码导入：浏览器只选预登记 ID，不能提供模块路径、任意 JSON Schema、脚本或计算表达式。

依赖方向：preview／可信启动组合 → 公共 host／store → 注入的适配端口、供应商和 SessionRecords；具体适配器可使用公共纯数值助手。公共核心不得反向 import 修仙适配、原稿、example、panels 或修仙 definition。可信 composition 根可以静态 import 两个适配器。

旧 v1/v2 的加载、记录格式、源码和原始素材保持不变。新修仙适配允许读取旧的纯 schema／标签／装配／渲染作为版本固定资源；不能调用整个旧 Host 或 Store 来冒充公共执行。旧实现作为冻结兼容与差分参照，后续是否收敛代码另议。

## 3. 最小端口：只为本轮真实调用方建立

以下名称是工程提案，可随仓库风格微调；职责和验证条件固定。不创建通用 DSL 或万能 JSON 路径变更接口。

| 对象 | 最小内容与职责 | 明确不能做 |
| --- | --- | --- |
| 适配绑定 | adapterId/version、stateSchemaVersion、rulesVersion、sourceHash、effectiveContextHash、实际运行依赖 manifest 哈希 | 用作者版本字符串代替内容绑定；动态加载任意代码 |
| 状态端口 | validateInitial/validateState；typed proposals → evaluate 得到 nextState、changes 与 diagnostics；静态字段维护责任表 | 直接写存档或调用供应商；允许正文任意覆盖路径 |
| 查询端口 | 一个只读查询声明、参数校验和对冻结状态的查询；返回版本、范围、未知／无匹配／截断说明 | 通过参数指定别的会话、文件路径；绕过状态权限 |
| 内容端口 | assembleContext、decodeReply、最终正文与变化的历史／记忆投影；修仙继续原有插件装配语义 | 工具结果当新用户输入；隐式重触发 Mod、世界书或正则 |
| 表现端口 | 初始化字段和说明、开场、状态／事件面板、安全正文投影 | 模型 HTML 成为权威状态；适配脚本任意操作浏览器 |
| 公共记录／回合 | 初始化确认、操作编号和请求哈希、revision/stateRevision、冻结上下文与阶段、回执、最终提交、查询恢复、改写、分支 | 认定模型的语义变化一定正确；自行推导题材规则 |
| 供应商端口 | generate/lookup；完成、明确失败、未知三类；保留工具 ID 和不透明 metadata，统计次数与用量 | 自动重试、改路由配置或借新会话扩额度 |

公共记录保留统一信封，state 是由指定适配器严格校验的有限 JSON 数据，不强迫所有卡共用 profile/items/relations 顶层。每次读写均核对适配绑定；大小、深度、类型和记录容量仍有上限。

变化记录包含可显示字段引用、前后值、原因、authority（规则计算／模型判断／用户改写）；字段引用用于追溯，不作为任意写路径。保存 eventId、operationId、stateRevision 与正文关联，为以后表现和创作出口留真实来源。

第三轮只有当前世界叙事者，不新增角色权限体系或 actor 数据库。参与者接口第七轮验证；此处不将“能读整个状态”宣称为认知隔离。

## 4. 数值原语与规则边界

共同需要的纯助手限于：安全整数增减、上下限处理、未知初值拒绝及实际变化记录。下限不足拒绝与上限钳位由显式规则选择，不能统一偷偷钳到零；非负库存、关系上下限、是否允许负数由适配规则指定。

原语必须在新修仙适配和灯塔配置中都被调用；固定初值、账户名、关系区间、数量单位、标签、装备槽、允许事件类别均不在核心。

修仙新适配保留第一轮字段责任与第二轮 strictRelations／quantityOnly 的含义；同名防重仅为该适配策略。锚定字段不能经模型增量改写；定性变化仍是模型判断；灵石不自动兑换；不增加经验曲线或恢复公式。

不要只把旧 applyOperations 原样藏在适配器里，再给另一配置建立一套完全独立数值计算。新适配的数值分支应使用公共助手，修仙语义分支按已有规则迁接；冻结旧函数作为对照而不是改写旧逻辑。相关合法、拒绝、上下限样例要求新旧状态与实际变化一致。

## 6. 回合、持久化与兼容

回合：读取并冻结状态 → 适配器组装 → 模拟供应商直接回复或查询 → 公共核心核验工具协议 → 适配器只读查询 → 关闭工具的续写 → 解码 typed proposals → 规则求值 → 一次 CAS 提交正文、有效状态、变化事件和操作回执。

- 公共核心掌握提交出口；适配器返回候选不能自行落账。结果校验失败整批拒绝，不过滤坏操作后偷偷提交其余变化。
- 本轮沿用最终正文＋状态同时提交；不把商店“先结算后叙事”的另一模式混进来。
- 同 operationId 同请求返回原结果，异内容拒绝；过期 revision 拒绝；查询只读不增加 stateRevision。空增量依旧能形成完成回合，stateRevision 的推进保持既有本地状态语义，不另造业务判断。
- 未知结果只 lookup；工具结果保存后恢复不重新生成查询请求。已完成最终提交后刷新／重复采用不能再结算。无自动重试或备用。
- 改写只在可操作状态执行，原因必填；绑定状态版本，旧结果不能覆盖。检查点分支包含匹配的状态、事件与正文；投影失败不触发供应商或再次结算。
- 新记录独立 format/scope 和目录，不修改 SessionRecords 的全局语义。新模式只接新开局／显式确认的测试初值，不建设旧存档导入迁移工具。既有 v1/v2 原会话继续走旧宿主。
- 基线旧模式字节与行为回归：缺适配或版本不匹配不猜测转换，不靠放宽指纹继续写；保留文件，不删除数据来回退。
- 本轮的静态适配端口是可信代码边界，不是第三方代码安全隔离。
