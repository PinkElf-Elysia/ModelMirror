## 本次交付和路线替代

本轮验证“世界动作提交 → 角色获准观察 → 指定角色响应 → 下一轮与恢复”。公共任务记录区分世界行动与角色响应的所有者、来源、冻结请求和回执；角色只读授权投影，不能直接写世界。实际承载为已有修仙数值适配器和原创成年角色林舟，第二个同模板实例仅作隔离对照。

这不是优化修仙文风、实现自动 NPC 或重建角色聊天工作台。角色卡作为内容定义，世界关联与观察授权由可信宿主的新桥接记录保存，不把世界引用塞入旧角色合同的 null 字段。

本次已经批准的公共任务／角色观察计划替代长期表中旧“第六轮任务与模型策略”的本轮安排。阶段模型、并行只读、累计真实预算、备用切换仍是未完成事项，下一轮需按实际依赖制定计划，不能因 R6 编号完成而视为完成。

## 实施前接口检查

- R5：复用 ActionHost/ActionStore 的执行、规则计算、事件、原操作回执、待叙事和恢复；不复制数值引擎。
- 角色：复用 AuthoringStore 的不可变 workId/versionId、verifyConfiguration，以及 character/context.mjs 的开场、宏、示例、角色书和历史装配。
- 原生工具：复用 actions/protocol.mjs 和 transport.mjs 的消息解析、续传、SSE 分片与元数据保留；角色只注册单个只读 query_local_state。
- 存储：复用 SessionRecords 的单目录所有权、CAS、提交标记和核对。世界与桥接是两条记录，不能宣称分布式原子事务。
- 不复用 owner 原始 read()/完整世界 query 作为角色视图，不改旧 CharacterSessionHost、GroupHost、预算合同或真实网关。
- 角色 R3a 与探索 E3 当前未在本轮基线；仅检查交接，不复制未提交文件。最新协调依据见 R6-HANDOFF。

## 分批及验收

| 批次 | 交付 | 离线验收 |
|---|---|---|
| A | 版本绑定、角色夹具、世界观察投影、只读查询 | 看见消耗不等于知道余量；未授权与未知对象不泄露存在性；工具结果不重新触发角色书 |
| B | 公共任务记录和两个所有者的薄适配 | 世界回执唯一；角色正文不入世界账本；任务有稳定顺序、来源、阶段和回执 |
| C | 指定角色响应和最多一次查询后的续写 | 一个角色实例自己的历史、版本、授权；另一实例不收到观察或私有历史 |
| D | 独立页面和恢复 | 创建→确认行动→观察→回应→续轮；重复点击、刷新、进程中断、回执丢失不重执行 |
| E | 回归、证据与交接 | R3–R5 与已复用角色接口回归；桌面/窄屏；真实效果与模拟证据分开 |

原型角色任务最多两次离线生成；普通交流一次。无真实派发入口、费用预留或自动备用。公共记录引用所有者回执，不建立第二本预算账；以后接入真实供应商前必须另行限定适配、预算与原回执恢复。

## 字段及权限责任

| 内容 | 维护方 | 角色权限 |
|---|---|---|
| 数量、世界状态与已确认事件 | 原 R5 宿主 | 不写入 |
| 角色模板/版本 | 已合并作品存储 | 固定引用，不用草稿替换 |
| 世界/分支/角色实例/观察授权 | R6 可信桥接 | 参数不能自报其他实例或权限 |
| 观察 | 白名单投影，从已确认事件产生；按事件 ID 去重 | 仅见获准事实 |
| 余量 | 独立丹药登记授权 | 未授权时不能从服用两份推导剩余 |
| 玩家说法 | 角色历史中的 user 消息 | 是转述，不自动升级为确认事件 |
| 角色回复 | 角色响应回执和本实例历史 | 不成为事实或结算 |
| 真实计费 | 将来仍归原供应商调用所有者 | 本轮没有真实调用与计费账 |

阶段请求冻结观察、输入、模板/授权绑定和状态版本。查询续写保留原 assistant/tool 配对；旧版本完成的回复不采用为当前回应。已采用的历史回复保留版本，在页面标为历史，不删除事实或重写旧文本。

## 明确不做

不导入已有角色私有记忆，不定义长期共享记忆政策，不开发角色编辑器或 R3a 日常工作区。不实现 E3 执行动作映射、赠送、人物同意裁定、自动多角色、搜索、地图、骰子、模型并行/备用、SDK 或正式故事馆入口。

原型的自然语言输出为固定夹具；结构隔离与恢复测试通过不等于真实模型会持续守住人物认知或叙事一致性。也不将本地 loopback 所有者防护宣传为多人权限系统。
