# R5b 交付点 6 · 条目冷却

在 V3 卡内书或独立书的条目设置“冷却间隔（本角色入史回复数）”，封存书版；新建或派生角色书分支时勾选“启用条目冷却”。设置接受 0–1000 的整数，留空或 0 表示关闭。书架草稿试算展示初次匹配，当前会话的剩余间隔在分支预览中查看。

冷却间隔保存在条目的 `extensions["modelmirror.cooldown"]`。这是模镜可交换设置。[固定版本 CCv3 角色书字段](https://github.com/kwaroran/character-card-spec-v3/blob/f3a86af019fbd99f788f7a1155f399655b34ab35/SPEC_V3.md#lorebook-fields)允许扩展；[酒馆的 World Info 文档](https://docs.sillytavern.app/usage/core-concepts/worldinfo/)介绍了其冷却效果。本轮使用模镜的历史、成员和分支语义独立实现。第三方同名字段、扩展和源文按原样保留；V2 卡内书和旧分支沿用原装配。导出只携带间隔配置。剩余条数、回复定位及请求状态归会话。

## 计数与优先级

以间隔 2 为例：

| 时点 | 下次预览的剩余条数 |
|---|---|
| 首轮预览命中，或已派发但回复尚未入史 | 0 |
| 条目实际纳入最终请求，宿主采用完整回复入史 | 2 |
| 同一成员下一条完整回复入史，条目跳过 | 1 |
| 再一条完整回复入史，条目跳过 | 0，下轮可重新匹配 |
| 条目再次实际纳入且完整回复入史 | 重新从 2 开始 |

每个成员按自己的封存来源和条目位置计数。只读预览、刷新、玩家输入、其他成员发言、精确重生成候选、部分输出、失败与结果未知均不推进。恢复仅核对原请求，并在完整回复正式入史后计一次。预算裁掉的条目不启动冷却；冷却结束仅恢复匹配资格。

持续触发和冷却同时启用时，冷却暂时阻止纳入。首次持续触发的依据保留，解除后即使没有关键词也能再次匹配。分支从所选历史位置重建剩余条数。未获授权的书不返回诊断，换到新封存版本独立计数。旧版本继续使用精确运行指纹，无原地数据迁移。

## 离线复验

在实验目录运行 `node --test character/book-library/cooldown.test.mjs`。专用预览命令为 `node character/book-library/cooldown-preview.mjs <独立目录> 0 0`。在“渡口灯号簿”分支输入“点灯”，预览并生成一次离线回复；再输入“继续”，分别预览并生成两次离线回复，观察剩余条数从 2 变为 1、再变为 0。解除后，“窗边灯号”可凭既有的持续状态再次纳入。停止专用预览即可回到交付点 5 的原副本。
