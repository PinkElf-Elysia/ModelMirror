# R2 接口交接

角色生态独立完成；不依赖尚未完成的 Agent 化工作树。本轮没有为世界状态或多 Agent 创建运行接口。

## 接入顺序

1. 由可信宿主打开 AuthoringStore 和 GroupStore，提供冻结的模型目录与授权。先显式 reconcile，再接受用户操作。
2. 从作品存储核验精确 workId/versionId/configurationHash，创建成员实例。名称不是 ID；同模板可以有多个实例。
3. 用户明确选择发言成员。每次只有一个 targetId；发送 input 字符串，接话 input:null。浏览器不能自行传角色定义、玩家发言者身份、权限或模型回执。
4. 取得该成员过滤视图后装配。不能把 read() 的所有者原始状态或其他成员定义送给模型。只有参与期间历史、当前群场景和本成员资料可进入上下文。
5. 经 GroupHost 派发。它先原子记录意图与预算，再记录 claim，之后才接触受控 Provider。R1 的 fixture 消息入口不能用于保存模型结果。
6. 恢复只查询 requestId 对应原回执，核验请求、角色、模型与哈希后采纳一次。unknown/absent 不授予重发权限，不能释放其预留或解除锁定。

## 必须保持的边界

- 新群合同是独立 scope；既有单角色、世界及 R1 的读取/发送仍走原宿主。不将新的消息对象直接提交给旧模型合同。
- 群实例、成员实例、角色模板与版本彼此分开。模板更新不回写成员；成员模型变化不改旧请求。
- 成员离场与重新加入使用持久化序号区间。未来世界实例引用不等于状态读写授权；目前仅保留 null 边界。
- 消息点名和消息可见范围不是一回事。本轮 UI 只公开发送；未来私聊必须继续先过滤再返回，不能依靠提示词隐藏资料。
- 私有资料目前是宿主人工写入且明确归属成员的数据，不代表自动验证的知识权限。R2 没有自动记忆提取任务。
- 运行规则、预算、工具权限由宿主掌握。角色卡脚本、系统提示词、开场内容都不能改变这些权限。
- `GroupGateway` 只能配独立群 ControlledProvider；共享服务只新增显式群消息校验分支，没有降低旧合同要求。
- API 的本地 owner cookie 是单用户 loopback 防护，不是组织级 RBAC。若未来跨用户运行，必须重新设计认证授权，不能直接外网暴露。

## 角色创作与群目录接线

- `startAuthoringServer` 返回的 `works` 是已持有所有权锁的 `AuthoringStore`。同一个实例传给 `GroupStore.open` 和 `startGroupServer`；不要再次打开同目录、维护手工版本清单或独立关闭这个共享句柄。关闭顺序为群页面服务、GroupStore、创作宿主。
- 初始化前配置 `characterSettings.groupsUrl` 与 `charactersUrl`，仅允许对应 loopback 页面地址；后改 settings 不会改已初始化导航快照。导航 API 仅返回地址，不暴露存储句柄或权限。
- 群目录读取已封存角色版本；浏览器提交精确 `workId/versionId`，由可信存储核验。新版本不会替换已有群成员的绑定。跨端口顶层文档导航与跨源 API 访问分开，不能为导航放宽 API 检查。
- 角色草稿备份恢复后仍需显式保存。群创建草稿仅在当前标签页 sessionStorage 暂存，创建成功后清除；不是群记录，不作为授权输入。初次精确版本预选后消费链接，之后保留用户选择；引用失效时空选并阻止创建。
- 未发送聊天输入未增加刷新持久化；私有资料、正式角色素材及本地验收数据不得随代码或帮助截图发布。

最新前端证据见 [工作区 UI 验收](CHARACTER_WORKSPACE_UI_ACCEPTANCE.md)，共享接口细节见 [工作区流程](CHARACTER_WORKSPACE_FLOW.md)。最新主线组合与全历史存档矩阵没有在此 UI 收尾重跑；模型表现偏差也没有因系统回归通过而关闭。
