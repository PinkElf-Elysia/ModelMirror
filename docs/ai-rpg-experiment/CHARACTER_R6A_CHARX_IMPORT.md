## 持久化和资源归属

确认沿用角色创作 API 的 `POST /imports`，宿主核对检查所得 SHA-256，重新解包并检查包内引用。原件 SHA-256 决定本地作品创建操作的身份。重复选同一个文件会打开已有作品，保留作者后续编辑；两个包即使角色同名也分别登记。相同操作 ID 不能改用不同参数。

作品通过宿主已有的原子包导入接口创建。角色定义保留原始 V3 字段与未知扩展。包内图片通过路径指向内容；相同路径供多个用途时只占一份本地资产。宿主可直接管理的图片进入版本资产清单。超过单图 5 MiB 且在 CHARX 16 MiB 检查上限内的图片，保存于独立内容存储中，通过作品原件绑定、版本中的资源声明与内容哈希读取。角色库、创作页和单聊入口支持这种大图。通用作品目录仍遵循其原有封面大小限制。

旧角色文档的来源字段引用包中真实的 `card.json`。单独的、按作品核验的导入登记保存 CHARX 原件关联，创作页「下载导入时的原始文件」返回整个包。导入登记、原件和大图在作品对外可见前写入；提交中断后再次明确确认，只核对并完成原创建。现有作品、版本、会话及运行指纹合同沿用旧格式，无迁移。

- `GET /charx/resources?work=…&version=…` 根据目标快照返回可见资源清单；省略版本时查看草稿。
- `GET /charx/image?work=…&version=…&path=…&hash=…` 按作品归属与包内引用取图，可校验预期内容哈希。请求不接收本机路径或远程下载目标。
- `GET /source?work=…&version=…` 对已确认导入的 CHARX 提供逐字节原件。编辑版 JSON 或 PNG 延用既有导出能力，界面提示完整包内图片另存于原件中。
