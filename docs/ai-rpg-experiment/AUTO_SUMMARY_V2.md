# 自动总结 2.0 与记忆宫殿核对

原站简体中文说明于本轮从 [自动总结说明](https://afengy.cash/docs/auto-summary.html?lang=zh-Hans) 读取。两张用户截图分别用于核对总结面板和记忆条目面板。截图中的三国内容是例子，没有写入模型提示词。

## 三卡入口与旧档

地球 OL、神临凡尘、超级修仙大世界页面提供「自动总结 · 分轮记忆会话」，市场页也列出了这三个入口。用户从卡片复制角色档案后创建新版存档，随后在这个面板内游玩。旧宿主中的角色和会话继续从原界面打开，不迁移或改写旧版摘要、授权或历史回执。新版按浏览器保存会话索引，具体回合和摘要由宿主持久化。版本清单与实现位于 plugins/auto-summary-v2.*，插件 id 为 rpg.rolling-summary，版本 2.0.0。新版随宿主提供，旧插件市场的安装／卸载仍作用于旧版。

## 总结与上下文

每个启用回合在剧情完成后额外调用一次模型生成小总结。第 1 至 20 轮使用已生成的小总结。在发起下一轮时，若积满 20 条待汇总小总结，先用上一份大总结和这一批小总结合成新的大总结，再派发剧情。第 21、41 轮是连续启用时的前两个合并点。发送给剧情模型的近期内容取最近五条和全部尚未合入大总结的小总结的并集。面板只展示最近五条，回合原文独立保存。开局角色资料保留在上下文。关闭期间按原文续聊，再启用后，此前未生成小总结的回合仍按原文装配。

可以修改大／小总结、重新生成最近小总结和已存在的大总结。删除回合会移除该轮小总结；编辑、刷新有小总结的回复会重做该条。以上动作不会自动改动已生成的大总结。手动重生成大总结使用覆盖范围内仍存在的小总结，包含人工修订，避免把旧大总结中的已删除事实直接传回。刷新回复只使用该轮之前的对话，避免带入后来的摘要。

默认剧情模型为受控目录的 Gemini。总结模型可选当前卡允许的可用模型；神临凡尘、修仙卡的既有模型限制仍适用。可选同时挂载记忆宫殿。普通回合有剧情、小总结两笔调用，阶段合并另加一笔，开启记忆宫殿再加一笔。各阶段分别保留回执；派发后的未知结果阻止该操作被重复提交。

## 操作与回退

离线测试从 experiments/ai-rpg-engine 运行 `node --test studio/auto-summary-v2.test.mjs`。本机模拟模型预览走了真实 HTTP 路由、三个卡片适配器及浏览器的新建、发送、修改、刷新恢复路径。修仙卡另以真实 Gemini 连续验证两轮，共六次成功调用、零重试。第二轮实际包含首轮小总结与两条召回记忆。第 21、41 轮的合并证据来自离线测试。独立聊天页支持以会话地址恢复并继续行动。

生产运行需要 RPG 宿主可访问已有 S2S 控制面，并显式设置 RPG_SUMMARY_V2_DIR、RPG_SUMMARY_V2_CALL_LIMIT、RPG_CONTROL_URL 与 RPG_S2S_TOKEN。新版目录和每卡调用额度单独管理。授权额度为零时生成入口不可用。关闭新版调用可将其额度设为零并重启宿主；保留数据目录供恢复。没有变更共享部署。
