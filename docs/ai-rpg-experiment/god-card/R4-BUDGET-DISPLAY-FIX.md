## 原因与修复

服务器 `memory-budget.mjs` 返回 `remaining = max(0, limit - used - reserved)`。旧聊天组件只读取 remaining，并用 `remaining === 0` 显示“本卡额度已用完”。剧情和记忆任务预留最后两次额度时，即使尚未派发，也会误报消耗完毕。

聊天组件现在保存完整预算快照：只有有效的 used/limit 表明 used >= limit 时才显示耗尽；remaining 用于显示可用次数并保持原有发送门禁，reserved 单独显示为尚未计入已用的预留额度。缺少计数不推断耗尽。前台操作、后台任务、未确认操作或未释放预留期间，不提示下一次发送额度不足；空闲时仍提示不足，状态未知时明确要求核对。

| 快照（示例，不是当前账本） | 显示与门禁 |
| --- | --- |
| limit 9 / used 7 / reserved 2 / remaining 0 | 可用 0，已预留 2；不称用完；禁止新增发送 |
| limit 9 / used 8 / reserved 1 / remaining 0 | 可用 0，已预留 1；不称用完；禁止新增发送 |
| limit 9 / used 9 / reserved 0 / remaining 0 | 明确已用完；禁止发送 |
| limit 9 / used 8 / reserved 0 / remaining 1 | 可用 1；单次调用原门禁可放行，两次任务仍被原门禁阻止 |
| 只有 remaining 0，或状态不可读 | 不推断已用完；保持禁止发送 |
