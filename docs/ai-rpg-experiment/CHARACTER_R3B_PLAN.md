## 2. 现有实现约束

以下来自本次只读检查，决定采用追加修订与独立分支，不直接覆盖旧正文：

- `character/session.mjs` 校验完成回合的 raw 必须等于 operation.receipt.result.text，input 必须等于 intent.input；只接受完成回合，开场另存。手改 turns 或把编辑文本替换为回执原文会破坏真实性。
- `character/group/contracts.mjs` 从追加 events 重放消息、参与区间、请求与预算；正式模型消息来自核验 settle。R1 的只追加合同不能反向加入编辑语义。
- `character/group/gateway-transport.mjs` 已保存原请求 payload、网关 evidence 和 receipt；group host 的摘要只有 evidenceHash，不应把摘要当成完整原回执。
- `character/session.mjs` 有人工记忆编辑与召回；`plugins/memory-palace.mjs` 的模型来源可记录 sourceTurns/outputHash，但旧人工记忆不一定有消息依赖边界。不能假定所有旧记忆可精确回滚。
- 群聊存在按成员归属的 privateRecords；R2 不自动摘要或抽取记忆。R3b 不能借本轮顺带启动这些模型作业。
- `character/daily/workspace.mjs` 提供目录、玩家可见投影、TXT/MD 导出；单聊展示标识目前按消息位置构造，只适合稳定旧记录，不能直接作为新修订主键。

## 3. 功能范围与交互决断

范围覆盖现有单角色与 1 玩家、2–3 AI 的手动群聊；同一套来源规则，分别适配既有宿主。世界卡、R1 合同、多 Agent、自主发言、世界对接、Harness、分支合并、批量生成与自动择优均不纳入。

| 功能 | R3b 建议行为 | 不纳入 |
| --- | --- | --- |
| 消息编辑 | 本地所有者可编辑已完成玩家消息、角色回复及开场正文；保存产生人工修订和新分支，原记录不变 | 改发言者、权限、参与区间、原请求/回执；编辑部分或未知结果；删除历史 |
| 重新生成 | 对已有完成模型回复，以其生成前的有效历史、同一角色版本和身份重新请求一次；每次显式点击只发一次 | 自动重试、多候选批量请求、重生成静态开场、自动重演后续对话 |
| 候选回复 | 原回复也列为候选；新结果先保存为未采用候选，用户明确采用后才参与续聊 | 自动替换当前回复、把未选候选注入上下文、模型评分挑选 |
| 分支 | 从指定消息边界继续，拥有独立 ID、标题、后续历史；支持来源导航与分支列表 | 图形化大型树、合并、批量复制/删除、模板或玩家身份中途替换 |

具体语义：

1. 编辑任何已完成消息都显示“保存并从这里继续”，不隐式调用模型。编辑玩家第 N 条时，新路径只保留该条之前的前缀及修改后的玩家消息；旧回答与后续消息留在原分支。下一次发送/请求回复才消费调用。
2. 编辑角色回复保留原回复来源，新增 `manual-edit` 修订，界面显示“已手动编辑”。它可以作为人工确定的剧情进入新路径上下文，但不得显示为模型原始输出。展示渲染、字面换行处理不修改存储原文。
3. 重新生成使用目标回复**之前**的上下文，不包含旧回复、同槽其他候选或后续消息；原玩家消息只继承一次。群聊“接话”的重生成继续用宿主任务，不伪造玩家输入。静态开场只能编辑/分支，不提供“重新生成”。
4. 默认沿用原请求模型和参数；派发前重新核验路由资格、价格和授权。原模型不可用时阻断，不静默替换。用户可在明确显示差异后选择其他获准模型，作为独立候选记录；此选择不更改该成员后续默认模型。
5. 在末尾回复槽采用候选，追加选择事件，保留先前选择。若已有后续消息，采用另一候选必须创建新分支，后续内容不搬过去。单纯展开/切换“预览候选”不改变已采用项或上下文。
6. 显式分支点为“保留到此条完成消息之后”，开场之后也可分支；不复制分支点之后的消息和成员事件。分支不得把静态人物设定或候选文本当作已经发生的共同经历。
7. 单聊允许新路径停在一条尚无回复的玩家消息；新投影单独表示此状态，不能伪造完整回合给旧宿主校验。旧单聊仍保持原完整回合合同。
8. 准备/派发中/结果未知请求存在时，当前会话及相关分支族冻结编辑、采用、分支与新发送；仍可只读查看和核对原请求。失败/部分输出保留证据，不成为可采用的完成候选；不得用分支绕过未知请求。

## 4. 数据与持久化设计

建议新模块 `character/revisions/`、独立合同与 SessionRecords scope；名称在开工接口审查时固定。复用所有权锁、CAS、原子写及 reconcile，不做数据库迁移或批量升级。

| 对象 | 必须固定的数据与约束 |
| --- | --- |
| 来源快照 | 原宿主类型/ID/修订/运行描述符、版本绑定、验证后的前缀、内容哈希；来源必须经原宿主验证 |
| 分支族 | root/source 引用、修订、分支集合、请求意图、候选、选择及预算约束；族 ID 不等于玩家权限 |
| 分支 | parentBranchId、分支点消息及修订、前缀摘要、独立 branchId；不可循环；不会跟随父分支后续变化 |
| 消息与修订 | 稳定 messageId、revisionId、发言成员、正文、可见范围及 provenance；消息位置和角色名不是 ID |
| 回复槽与候选 | 目标成员、前驱历史摘要、生成任务、candidateId、requestId、状态；一个槽最多一个已采用候选 |
| 原证据 | 原请求、网关原响应 evidence、核验回执、原始输出文本和各自哈希；人工修订与显示文本独立 |
| 派生资料 | 所属分支/成员、来源消息修订及可见前缀哈希、有效/失效/待确认状态；不得越权关联 |

- 保存请求意图、候选状态、选择、分支历史和族预算预留尽量归同一族记录原子提交；operationId + expectedRevision + 意图摘要控制幂等。双标签、同 ID 异参数、跨族候选拒绝。
- 使用宿主生成的 ID；历史单聊 ID 由经核验的会话 ID、操作 ID/固定开场槽确定；继承消息保存原来源 ID，新修订和分支使用独立 ID。
- 旧存档首次进入此功能时，显式创建有来源的分支快照，不修改原文件。将所需不可变前缀及可用原证据封存到本族，后续读取不依赖父路径可写或父会话继续停在旧修订。去重不跨授权范围。
- 后续每次创建都核验来源版本与哈希；版本缺失、来源损坏、不可验证回执拒绝，不自动修补。旧记录缺少可验证生成前上下文时，可保留只读展示，但关闭该条精确重生成并显示原因。
- 目录元数据和族记录不是跨记录事务：族提交成功后目录更新失败，通过读取重建目录观察状态，不回滚消息或重放模型。
- 为记录大小、候选数量、分支数量、继承深度设置有界限制与明确错误；达到上限不删除旧候选/证据。实际值在开工按现有 SessionRecords 容量冻结并测试。

## 5. 原始响应、回执与恢复

- “原始响应”明确指现有受控传输可保留的网关 evidence、回执与原始 result.text，不声称能获得供应商隐藏推理或完整上游 HTTP 字节。
- 对既有请求不重写请求 ID、消息哈希、模型选择、回执、状态及成本依据；新候选使用全新请求 ID，绑定分支、回复槽、前驱哈希、目标成员、角色版本、身份快照和装配器版本。
- 重生成不是要求供应商复现同一随机输出。保持原生成前语义；若装配规则、模型参数或预算导致请求不同，在预览和证据中显示差异。容量不足时拒绝，不悄悄使用后续历史或不相关摘要。
- 浏览器只提交消息/候选引用与人工编辑正文；不能提交可信模型回复、回执、任意上下文、凭据或网关地址。编辑来源与 model-result 来源使用不同严格合同。
- 先持久化意图及预算预留，再取得派发所有权，再接触网关。已到回执但本地采用中断，用原请求幂等恢复；只追加一次候选，**恢复不自动采用候选**。
- 超时/未知保留占用与证据，刷新只读状态/查询原请求。查无记录不等于未派发；只有可信未派发证明才可关闭和释放。失败不自动补跑，显式新生成也须新授权范围内可用预算。
- 原文和来源详情仅返回当前本地所有者有权读取的安全投影；角色上下文与普通导出不包含完整网关 evidence、未采用候选、私有资料或凭据。

## 6. 身份、角色与群聊参与边界

- 新分支继承来源路径中已固定的玩家身份快照，包括 profileId/profileRevision/name/description/avatar；不读玩家档案最新值。静态头像资产按摘要保留，头像不进入模型内容。
- 角色绑定继承 workId/versionId/configurationHash；新草稿/封存版本不影响任何既有分支。采用新模板或换玩家身份不属于 R3b；另开新会话。
- 群场景、开场文本及参与成员状态按**分支点的事件边界**恢复；不能把原会话后来加入的成员或离场事件倒灌过去。重生成在原生成任务边界确定角色参与状态。
- 成员建立分支本地 ID 与来源 ID 的确定映射；参与区间沿继承序号映射。重新加入仍不补授缺席消息。同名实例、限定接收范围和点名分别保留，不借候选或分支扩大可见权限。
- 成员上下文先过滤其可见前缀，再选择已采用修订、角色书命中与有效私有资料；候选列表、来源诊断和未来成员名字也不能泄漏给不应看到的角色。
- 来源身份缺失时按旧合同呈现，不回填为当前档案。身份、版本或成员映射不能验证时，阻断续写。

## 7. 记忆、摘要与其他派生数据

核心规则：原资料不删除、不改写；只决定它能否参与新路径上下文。人工“保护”表示不可自动覆盖，不代表内容永远有效。

| 资料类别 | 继承和失效规则 |
| --- | --- |
| 角色定义、角色书静态条目、玩家身份 | 随固定版本/快照继承；不是聊天经历 |
| 角色书触发结果、上下文缓存 | 随有效消息修订重新确定性计算；不得复用原分支缓存 |
| 带完整来源依赖的记忆/摘要 | 仅当全部来源修订、可见范围、成员和有效前缀符合当前分支才可继承；任一变化即失效 |
| 旧摘要仅有覆盖区间 | 覆盖区间与当前前缀完全匹配才可采用；依赖被截断或改写则停用，不截取摘要冒充重新总结 |
| 旧人工记忆、无可靠边界的私有资料 | 保留原始证据，新分支默认待确认且不注入；人工确认后创建本分支独立有效修订 |
| 分支点之后产生的资料 | 不继承到当前有效上下文，不用原会话最新记忆替代分支点状态 |
| 未选候选、失败/部分/未知输出 | 不作为经历，不生成记忆，不进入总结、关键词扫描与后续模型历史 |

失效按依赖传递：修订消息 → 相关摘要/记忆 → 引用了它们的上下文缓存。即使只是标点编辑，也按摘要变化失效，不用相似度猜测“语义没变”。无依赖信息时保守停用，不能声称实现精确回滚。每个成员只看到自己的待确认资料。

R3b 不自动抽取或重建摘要/记忆，不新增隐含调用。页面展示“哪些资料暂未用于续聊、为何失效”；可查看原资料并人工确认/修订；若有效原历史加必需内容超出上下文，明确阻断或沿既有可解释裁剪规则处理，不暗中调用总结。

## 8. 预算与原路径兼容

- 编辑、采用已有候选、分支、切换查看不调用模型、不重复收费；新生成一次预留一次调用及保守金额，不按“最终采用数”计费。
- 所有候选、原会话和派生分支受同一任务授权及可追溯的族额度约束；新建分支不复制可消费额度、不释放原预留。已有花费、未知请求占用均保留。
- 原会话仍可走旧宿主，但启用族预算后，旧入口发送与分支发送必须通过同一授权协调入口，不能只在新页面计数。共享总授权仍独立生效，族额度只能收紧。
- 复用既有受控网关、预算及恢复边界；不另造可绕过授权的网关。跨族记录/既有预算账本无法原子提交时采用先持久化意图、幂等预留/claim/settle与恢复核对；中断不自动释放或重派。
- 当前群回执没有可靠实际美元账单时继续保守预留，不根据 token 猜造最终成本。价格无法确认、超额、授权拒绝均在派发前阻断。
- 实施时应以 mock 并发证明旧入口与多个分支无法重复消费；若无法用最小适配统一扣账，分支真实执行保持关闭，列为未完成门禁，不靠复制额度宣称完成。
- 旧单角色/世界合同、R1 只追加语义及原精确兼容条目保持。新修订合同不直接提交给网关：由可信宿主展开为其已支持的严格消息合同，旧校验不放宽。
- 共享宿主指纹涉及的必要变更先列接口与影响，新增本轮独立精确描述符规则，旧规则原样保留；未知版本/漂移/损坏继续拒绝，不改旧 runtimeHash 或伪造完整回合。

## 9. 页面与 API 设计

复用现有单聊/群聊页、目录和设计语言，不新建管理后台：

- 消息菜单：编辑、重新生成（仅符合条件的模型完成回复）、从这里继续、查看原文与来源；禁用项说明原因。
- 编辑弹层展示原文/修改稿及“旧后续留在原分支”的影响；取消不写入。离页、刷新、关闭保护延续 R3a，编辑草稿按会话/分支/消息/基础修订隔离；恢复时基础修订变化须提示冲突。
- 候选区域显示序号、模型、生成状态、当前采用项及“预览/采用”区别；新候选完成只提示，不抢占当前路径。移动端不依赖悬停或仅滑动操作，键盘焦点可达且可返回。
- 顶部显示当前分支、来源与返回入口；目录区分分支，URL 固定 branchId。刷新恢复选择、请求状态与草稿，不再派发。切换分支不丢失另一分支草稿。
- 普通 TXT/MD 导出只输出当前有效路径并标注人工编辑/分支来源；原始响应在来源详情单独查看。角色卡导出永远不读取会话修订、候选或私有记忆。

建议内部接口：inspectSource、forkAt、reviseMessage、listCandidates、prepareRegeneration、selectCandidate、readBranch、recoverRequest、reviewDerivedRecord；名称在实现时遵循仓库约定。写接口均带 operationId、expectedRevision 和明确来源引用，采用校验前驱哈希。HTTP 延用 loopback、Host/Origin、Cookie/CSRF、字段白名单及大小限制。族/成员/分支 ID 不是权限凭证。

## 11. 验收清单与命令

必须用中性夹具离线覆盖：

- 编辑玩家/角色/开场、末尾/历史消息；人工来源可区分，原文/请求/回执字节哈希不变，后续仍在原分支。
- 候选完成但未选、候选预览、末尾采用、历史采用产生分支；未选文本不进入历史、角色书、记忆、检索和普通导出。
- 重生成玩家输入一次、接话无伪玩家消息；原模型失效拒绝、显式模型差异记录；重复操作不多派发。
- 并发双标签、过期修订、同 ID 异参数、跨族/跨成员引用、原分支继续变化不污染已封存前缀。
- 源码漂移/版本缺失/篡改拒绝；旧单聊与世界历史基线、R1、R2、R3a 存档恢复与 mock 续聊。
- 分支点前后加入/离开/重入；同名实例、私有消息、隐藏来源、未来成员信息和成员记忆不泄漏。
- 更新档案/头像/角色模板后分支身份仍固定；分支点之后的设置及资料不倒灌。
- 有依赖资料正确失效，无依赖旧记忆默认停用；受保护资料不删除但仍能失效；未调用摘要/抽取。
- 预留前后、claim 前后、派发前后、回执保存/采用前后崩溃；未知冻结，查无记录不重派，重复回执不重复候选/收费。
- 原入口及各分支共用预算，未采用候选仍占用，分支不增额；无价格/无授权拒绝，真实授权为零。
