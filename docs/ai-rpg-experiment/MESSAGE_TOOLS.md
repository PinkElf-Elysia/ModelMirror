# RPG 消息工具

在使用新版 Studio 的环境中，打开 RPG 插件市场安装「消息工具」，再进入 Earth 或 God 对话，点击「插件」并为当前会话启用。命令行 Studio 默认登记该插件，嵌入式宿主可在 start 选项中传入 messageTools。部署时需要同时更新 RPG 服务端、共用卡片前端和模型控制面的 RPG 桥接器。

- 点击回复下的「复制回复」复制保存的原文。浏览器拒绝剪贴板访问时，可从原文窗口手动复制。
- 点击玩家消息后的「编辑输入」，修改后选择「保存并重新生成」。取消编辑不会提交。God 的首轮档案由卡片锁定，允许重新生成，修改档案须回到角色卡。
- 点击回复下的「重新生成」，会从该回合之前的历史新建分支，用原输入生成。编辑重发和重新生成均使用普通发送接口与现有预算，原对话及后续回合保留。分支中的插件授权单独管理。
- 真实会话中的「完整输出／流式输出」控制剧情显示时机。流式模式显示尚在生成的临时文本，完成后用持久化结果替换。设置保存在该浏览器的当前会话。查看进度、切换显示以及复制操作均不派发模型请求。

关闭会话授权或从市场卸载即可停用。运维可通过 RPG_MESSAGE_TOOLS_ENABLED=false 让命令行 Studio 停止登记此插件。现有运行时校验继续生效，对标记为不兼容的历史会话，请保留其原始数据及匹配的宿主版本。

离线验收从仓库根执行 node --test experiments/ai-rpg-engine/studio/message-tools.test.mjs。该测试使用延迟结束的本机上游，验证完成前读取到分片、按回合复制历史、重生成及操作幂等。控制面测试位于 server/tests/test_rpg_bridge.py 和 server/tests/test_rpg_message_progress.py。

Earth V2 受控剧情收到空正文或截断回复时，宿主核对发送时的模型选择、请求、回执与完整 SSE 后，将请求记为失败并显示原因。对旧的待确认请求，在对应分支点击「恢复记录」可用同一请求 ID 核对磁盘记录。恢复不发起模型调用。证据缺失或不一致时，请求继续保持待核对。
