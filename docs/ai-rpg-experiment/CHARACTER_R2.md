# R2 手动群聊

基线：0cb019df01642d71a5eef55eeee31d1086ab037d；远端 main 开工核对相同。R1 的 14 个未提交文件白名单复制并校验，原目录不变。

本轮新增 character/group 独立合同、存储、受控适配和页面；必要共享变更只做群合同校验注册。旧角色、世界与 R1 指纹依赖不修改。无数据迁移、新依赖、产品真实调用、部署或提交。

风险：持久化、loopback HTTP、请求与预算状态；实现按合同、存储、运行、页面分批，每批不超过五文件。任何未决派发只查询原请求，不自动补跑。回退为停止本轮预览并撤销新增入口，保留数据与证据。

验收：新增 Node 单元/故障/HTTP 测试；R1 与旧存档矩阵；受控网关 Windows/Linux mock；相关前端测试与两个构建；桌面和移动页面。正式素材只在本地，测试使用中性夹具。帮助中心既有两项失败与截图诊断单独记录。

## 实现与合同

新增 `modelmirror.rpg.character-group/1`，存储 scope 为 `character-groups-v1`。同一个 SessionRecords CAS 账本保存所有群组的事件、消息、成员、请求及任务预算。这样群级和任务级额度在同一提交中检查，不存在跨文件预算提交窗口。单目录最多 50 群，每群最多 3000 个事件，仍受现有 32 MiB 记录上限约束；这是本地首版容量边界，不是高并发服务。

成员复用 R1 的身份与 `[from,until)` 参与区间语义。初始 2–3 个角色、1 个固定玩家；整个群的角色实例总数最多 3，包括离场者。离场不删除实例；可重新加入，缺席期间历史不会补授。消息只追加，群场景固定，模板版本与成员模型分别绑定。切换模型只能选择宿主冻结目录中的条目，不改变角色或历史请求。

新实现位于 `character/group/`。旧 `character/conversation/`、单角色运行器、世界合同、精确兼容清单及其指纹依赖字节不变。新描述符覆盖群运行模块和传递依赖，源码漂移拒绝读取/写入，不更新旧存档中的哈希。旧存档没有迁移到群聊。

### 可信宿主 API

`GroupStore.open({directory,works,models,authorization,recoverDeadOwner,fault})` 要求真实 AuthoringStore。`authorization` 包含固定 ID、模式、调用次数及整数 microUSD 上限；默认 disabled、零额度。打开后必须显式 `recover()`。模型目录和授权变化会拒绝已有账本，不通过新建群组扩大授权。

| 方法 | 输入与语义 |
| --- | --- |
| create | operationId、expectedRevision:null、player/scene/members/opening/budget；作品引用由作品存储核验 |
| change | join/leave/rejoin/model/private；带 expectedRevision 的宿主写入；private 不暴露 HTTP |
| read / memberView / view | 依次为可信所有者原始状态、过滤成员视图、浏览器安全投影；不能混用 |
| preview | 只按指定在场成员装配；返回消息和来源清单，不调用模型；仅可信宿主使用 |
| prepare / claim / adopt | 分别持久化意图、取得派发所有权、采纳已核验回执；浏览器不能直接调用后两者 |
| closePrepared | 仅能关闭没有派发 claim 的请求，保留已经保存的玩家消息并释放预留 |

`GroupHost.send` 将 input 为字符串的玩家发送，或 input:null 的手动接话，映射为一次请求。相同操作只返回原结果。`GroupHost.recover` 只查询原请求，不重放 POST；已完成/失败直接返回原结果。恢复操作不会生成摘要、记忆或其他模型任务。

### HTTP 与页面

独立 loopback 服务 `/groups`，不替换旧宿主入口。`GET /api/bootstrap` 返回本地版本目录、模型显示项和群列表；`GET /api/groups/:id` 返回安全投影。写接口包括 `POST /api/groups` 和 `/:id/send|recover|close-prepared|join|leave|rejoin|model`。

服务核验固定 Host、同源 Origin、Sec-Fetch-Site、本地 HttpOnly/SameSite=Strict 所有者 cookie 和写入 CSRF。写请求上限 128 KiB。它是单用户本地工作台，不是多租户登录系统；成员 ID 不授予登录或运行权限。不存在 HTTP 提交完整提示词、指定网关、授予额度或写入模型回执的入口。

页面支持独立模型选择、公开发送/接话、参与状态、预算、请求状态、刷新、移动成员抽屉。输出采用等待回执后展示，未实现供应商 token 实时流。失败的部分输出独立标注，不成为历史。未决请求冻结成员、设置及新发送；仅准备但未派发的意图可以关闭。已经保存的玩家消息保留，后续应使用“接话”，不重新提交同一句。

## 上下文和预算

群场景替代目标卡 `scenario` 的运行位置，原卡不改。每次只使用目标定义、目标提示词、可见公共身份、过滤后历史、该成员人工私有资料和目标角色书。角色书位置、触发与预算复用独立规范实现；不扫描作者说明或示例。支持单人版既有宏和各提示词字段的 original 展开，不新增第三方宏、脚本或工具。

目标过去发言为 assistant；其他成员发言以 JSON 编码的成员身份和正文进入 user 材料。最终宿主接话指令单独标注，不写入玩家历史。示例独立，容量不足时先裁剪示例、再裁剪较早可见历史，进一步缩减角色书预算；至少保留最新可见消息，必需定义仍超限则拒绝。每个请求保存可见消息来源、裁剪原因、消息哈希、角色绑定和模型选择。

费用以整数 microUSD 预留。宿主必须提供经过核对、覆盖输入/输出及额外费用的价格上界；输入按 UTF-8 字节和保守 framing 预算计算，未知价格拒绝。模型输出上限与受控选择一致。共享网关仍再次校验路由与共享额度。

结果未知始终保留次数和金额，且阻止继续发送。当前网关没有美元账单回执，所以完成后也保守保留预留金额，不根据 token 数伪造实际支出；只有可靠结算证据可退差额，证明未派发的失败可释放预留。离线测试的零费用回执不证明真实价格或账单已验收。

新增线协议 `modelmirror.rpg.character-group-messages/1`，只允许 story 目的。首条 system、末条 user（可再接一条后置 system），中间允许 user/assistant 连续发言；不允许中途 system、工具、多模态对象或任意字段。未带新标记的旧角色/世界顺序规则不放宽。新受控适配复制自本仓库自己的实现，使用独立持久化命名空间；未引入第三方角色卡代码或新依赖。

## 本地启动和恢复

`node experiments/ai-rpg-engine/character/group/launch.mjs <独立数据目录> <loopback端口>`。

目录内 `host.json` 由可信宿主提供 models 和 authorization；作品存储在 works，群账本在 groups。fixture 模式使用确定性离线回复；controlled 模式还要求显式环境开关 `CHARACTER_GROUP_EXECUTION_ENABLED=true`、仅宿主持有的 `CHARACTER_GROUP_SERVICE_TOKEN` 和固定 loopback 网关地址。不能将这些变量发给浏览器或提交。

进程异常退出后，先核对进程已终止，再以 `--recover-dead-owner` 显式恢复目录所有权。启动只核对本地记录，不调用模型、不自动查询或重放未决请求。保存原数据与回执，禁止通过改授权 ID、存档哈希或清空目录解决异常。

本次预览目录与全部素材、会话、协作输出、失败日志位于仓库外。正式角色仅复制选定作品记录、版本和必要肖像资源；没有复制会话、记忆或令牌。原创蓝色大鱼仅存本地。测试夹具与实际角色表现明确分开。

## 后续边界

R2 不包含自动群聊、自动调度、批量回复、群摘要/记忆抽取、世界状态、Agent 协作、工具或 Harness。协作开发模型不属于产品运行成员。

下一轮真实模型验收必须单独冻结模型、调用次数、金额、材料和停止条件，并重新确认路由/价格。当前上线门禁、生产额度、实际计费、供应商流式行为及长期人物稳定性均未验收。创建 PR 前还需完成帮助中心正式文章与同基线截图门禁，本轮没有创建 PR。
