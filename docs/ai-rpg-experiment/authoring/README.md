# RPG 创作工作台

在本地从空白作品开始，录入开局、提示词、世界书和素材，可以保存草稿、制作固定版本、游玩，或把完整作品包交给另一个本地作品库导入。工作台使用同一套作品合同处理不同的卡片。

## 打开工作台

在已经安装仓库固定版本 Node 和 npm 的环境中，从仓库根目录运行以下命令。数据目录使用独立、可持久保存的本地路径。启动后终端会输出实际 URL。

```powershell
npm.cmd --prefix experiments/ai-rpg-engine ci
npm.cmd --prefix experiments/ai-rpg-engine run rpg:authoring -- --directory C:/rpg-data/works --port 19040
```

通过 `http://127.0.0.1:19040/` 打开作品管理，选择「空白作品」或「导入作品」。右上角的「创作指南」有可编辑的开局示例、提示词放置方法、世界书抽取示例，以及模型回复的展示规则。此启动模式支持本地编辑、发布和回放，模型配置显示为未启用。

要让 RPG 卡片库显示「创作工作台」，在启动或构建主前端的环境中设置 `VITE_RPG_AUTHORING_PORT=19040`。从 HTTP 的 `127.0.0.1` 访问主前端 `/rpg` 即可。浏览器通过顶层导航打开工作台。入口开关和创作服务可分别启停。

## 接入受控会话

需要真正选择模型、游玩发布版本和调试插件时，使用受控启动命令。操作人员应先配置后端的 RPG 服务身份、模型目录、资格、创作派发开关及授权预算。独立创作路由具有自己的连接、模型清单和控制面额度。宿主端通过 `RPG_S2S_TOKEN` 取得既有服务身份，`RPG_AUTHORING_CONTROL_ORIGIN` 默认指向 `http://127.0.0.1:8000`。服务令牌只在宿主环境中提供。

```powershell
npm.cmd --prefix experiments/ai-rpg-engine run rpg:authoring:controlled -- --directory C:/rpg-data --port 19040 --limit 0
```

示例的本地调用上限为零，适合空库接线验收。启动会读取受控目录。保存、刷新、本地发布及导入均不生成模型请求。实际发送须有匹配的模型能力、有效资格和足够的两层额度；首次配置本地账本时按已授权的上限填写 `--limit`。同一数据目录重启继续使用原上限。宿主将作品保存在 `works/`，另行保存会话、授权、展示、请求及账本。使用同一作品库由编辑模式切换时，先正常关闭原所有者。

剧情、摘要和记忆分别选择模型。五个接入本轮创作合同的插件为分支存档、模型选择、历史窗口、自动总结、记忆宫殿。安装与逐会话授权分开；停止、撤权、关闭页面、失败及未知操作按原操作号收束。下一次发送等待后台工作。M2 和 M3 同时启用时按 M2 → M3 执行，各自读取合同指定的来源。

## 创作与装配规则

| 创作区 | 可用功能 |
| --- | --- |
| 基础设置 | 作品资料、分组标签、五种语言、面向群体、桌面和手机图像、本地图库、BGM、手动保存及可选的三分钟自动保存。源码文字保留原空行与标签。18 项工具覆盖选区、撤销重做和全屏。 |
| 世界书 | 分类、排序、关键词或隔离正则、用户和 AI 角色筛选、与／或、影响范围、插入顺序、扫描深度、触发概率、加权正文及归一化。 |
| 开局与展示 | 作者 HTML/CSS/JS 在隔离的开局环境运行，只能经宿主交接输入；模型回复只作展示。作品版本管理 CSS、图片别名、Markdown、受限 SVG、折叠、动效及原文。 |
| 创作增强 | 开场白、预设对话、快捷回复、下一步建议、屏蔽词、展示用正则、普通 CG 的聊天插图与背景、BGM。建议和指令填入输入框，由玩家发送。 |
| 保存与交付 | 导出配置或含素材的作品包；导入先校验，再原子创建新草稿。已发布版本及其会话绑定固定。展示替换和 CG 回放保留原始历史。 |

主提示词进入单条 `system`。前后置词与本轮玩家原文进入 `user`。世界书按选定范围插入，前后置词的命中可供主提示词世界书再扫描一次。顺序 0–9999，按升序，同序按列表顺序再按稳定 ID。深度 0 只看当前玩家输入，1–20 额外扫描相应的完整历史回合；M1/M2 的实际发送窗口独立计算。百分比先判定条目是否生效，再按非负权重只取一份正文。归一化按最大余数法保留两位小数，等权三份为 33.34、33.33、33.33。这些概率和排序细节是可复现的本地约定。

记忆宫殿使用独立的原始回合、存储、召回及版本规则。新的整理请求把条目当前版本标为 `baseVersion`，便于模型逐项引用。宿主仍对整批提案作校验。保留的 v1 请求、原文与哈希继续按 v1 规则核对。历史读取每次重新检查所有者、记录摘要、绑定和插件授权；只有已通过的纯内容校验可以按同一记录摘要复用。

## 恢复与回退

结果待核对时，使用原会话中的恢复操作查询原请求。目录所有者异常退出后，可在确认旧进程已结束时用 `--recover-dead-owner` 接管原目录。恢复操作继续核对原 ID，留存失败及未确认的费用记录。已保存会话若绑定了不同的执行版本，使用相应版本和副本查阅。切勿改写记录哈希来强行打开。

关闭前端入口并停止自己启动的宿主即可撤回本地接入。保留作品、资源、版本、会话和账本。共享服务的降级须先保存升级后的数据，再在副本上核对旧请求和回执的可读性。验收范围、历史实测结果和待办见[验收记录](ACCEPTANCE.md)。
