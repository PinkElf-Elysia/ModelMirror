# R6a · 检查 CHARX 与保留原包

交付点 1 接在角色库和创作页的「导入角色卡」入口。选择文件先看角色名、包内路径、资源用途、字节数和图片尺寸。检查不会创建作品。点击「保留完整原包」后，可从角色库「保留的 CHARX 原包」下载检查过的原件。再次保留相同内容只登记一次，宿主重启后可继续下载。

| 检查结果 | 可使用的操作 |
|---|---|
| 图片包检查通过 | 查看清单，保留及下载原包。编辑导入与版本封存属于交付点 2。 |
| 仅可保留原包 | 对照缺失、歧义、动画、未引用文件及不支持的附件逐项核对。保留时保存全部原始字节。 |
| 文件损坏、路径或大小违规 | 显示诊断并拒绝留存。 |

## 交换边界

按 [CCv3 固定规范](https://github.com/kwaroran/character-card-spec-v3/blob/f3a86af019fbd99f788f7a1155f399655b34ab35/SPEC_V3.md#charx) 检查根目录的 `card.json`、V3.0 和大小写敏感的 `embeded://` 引用。相同包内文件可有多个用途。多肖像须能确定唯一主图。`ccdefault:` 显示为默认资源，HTTP(S) 引用只显示。文件内容始终留在本地。

静态 PNG、JPEG 和 WebP 检查容器、图像头与像素尺寸；此阶段不解码展示像素。APNG、动画 WebP、音视频和未识别附件只能随完整原包保留。图片像素解码、播放及编辑版导出不能由本阶段检查结果推断。

ZIP 接受普通单卷 Store 或 Deflate、目录、包注释和经过核验的数据描述符。按锁定的 yauzl 版本读取，独立校验本地头、中央目录、实际长度、CRC 与不重叠的文件区间。加密、ZIP64、链接、目录逃逸或冲突路径被拒绝。压缩包上限 32 MiB，最多 256 项，单项解压 16 MiB，累计 64 MiB，单张图片 4000 万像素，资源声明最多 2048 项。检查在内存中进行。

## 本地接口

沿用角色创作 API 的同源与请求头要求。

- `POST /imports/inspect` 对 CHARX 返回原件 SHA-256、角色名、分类、资源用途与诊断。可提交 `formatHint: "charx"` 识别扩展名正确但内容损坏的文件。
- `POST /charx/originals` 接收原文件、文件名和检查所得哈希。重新检查、核对哈希后按内容保存。重复保留幂等，保留清单最多 256 份。
- `GET /charx/originals` 列出此本地创作宿主中显式保留的包。`GET /charx/original?hash=…` 仅下载清单登记的原件。
- `POST /imports` 继续拒绝 CHARX 建立作品。原件存储与聊天、模型权限、作品版本分开，无数据迁移。

## 离线验收

基线 `f628bed3`。覆盖纯图片与混合包、主肖像、同图多用、缺失与歧义、尺寸与边界、异常压缩包、重复保留、宿主重启、逐字节下载、跨源拒绝，以及旧 JSON/PNG、会话、历史指纹与 R5c 组合回归。页面走查使用独立 Python ZIP 写入器生成的中文中性夹具，含 PNG、JPEG、WebP、流式数据描述符、包注释与远程引用。960px 和 390px 均从选文件走到刷新下载，未产生外部请求。

真实角色包、供应商行为和真机设备不在本交付点的验证结果内。已有设备延期和 R4c ①②待证沿用原记录。④仅证实宿主停止读取，供应商最终计费待证，US$0.018990 预留未结。回退时停止独立预览，原件与本轮数据可保留。
