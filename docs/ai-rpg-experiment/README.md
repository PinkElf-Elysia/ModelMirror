## 恢复时先确认
- 当前处于“RPG-01 已通过用户人工验收；RPG-02 至 RPG-06 未开始”。机器状态以模块 `docs/RPG01_STATUS.json` 为准。
- 首版核心链路是：角色卡/代表资源 → 内容编译 → 自主提示词与世界书上下文 → 模镜治理的模型调用 → 叙事和信息模块呈现 → 玩家继续交互。
- 首版以零可选插件运行，只保留必要核心与最小插件宿主合同；不交付插件市场、卡片市场、在线安装或预装增量插件。
- 第一版后，向量/图检索、记忆宫殿、自动总结及其他可选功能、模块和优化包统一进入插件市场；用户自主选择、授权和启停。其他卡片资源进入卡片市场，来源为用户提供的 Tavern 卡片转化、协助编写及未来 UGC。
- 模镜会话连续性属于运行框架；目标卡的命名存档、回退分支和读档规则属于卡片特化扩展，二者不能混为一套通用存档引擎。
- 任务经济、卡内存读档、死亡重生、结算继承可作为代表内容验证其“可表达、可显示、可继续”，不要求首版形成专用状态机、数据库表或独立 UI 子系统。
- RPG-01 已按 P0、01A 至 01F 小批实施并通过人工验收；只交付四种 `0.1.0` 数据格式、四个纯校验/就绪接口、代表 fixture 和隔离门禁。RPG-02 可另行制定计划，但尚未获得实施授权。
- 当前没有未结束的目标网站探针；各额度独立，以 PROBE_LEDGER.json 为准。
- 进入某轮后，按用户指令在该轮计划模式制定具体批次、任务与门禁，不能因路线列有能力就自动实施。
- 开始实现前重新检查真实代码、Git 状态、模镜接口和适用指令；本模块继续与矩阵绿洲父模块及历史实验引擎隔离。
## 防漂移更新规则
改变首版核心或卡片特化扩展边界，先更新 BASELINE；改变核心/插件/卡片归属时同步更新 PLUGIN_CARD_MARKETS；调整轮次更新 ROUND_ROADMAP；新增观察或推断修正更新 AUDIT；探针提交与终态先更新账本。研究建议只有被对应轮计划明确选中后才成为实施要求，可选能力不得静默回流内核。
新旧结论冲突时保留直接观察并记录范围纠偏，不静默把目标卡特化机制改写成通用 AI RPG 规则。文档哈希只证明本次快照完整性，不是运行验收证据。
RPG-01 的代码与唯一生产依赖 Ajv 8.20.0 位于隔离模块；传递依赖、许可证和 integrity 已登记。没有父仓运行代码、服务或数据迁移，没有模型调用或新探针。用户人工验收已关闭，并授权本轮收尾 Commit、Push 和 PR；Merge、Deploy、Release、Publish 仍未授权。初次审计快照和资源清单保持原样。
