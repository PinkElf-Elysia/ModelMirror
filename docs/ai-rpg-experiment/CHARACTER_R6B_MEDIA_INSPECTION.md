# R6b 交付点 1 · 核对角色包中的音视频

作者从角色库打开「导入角色卡」，可在清单查看包内路径、字节数、格式与每项用途。同一文件被多个声明引用时，会显示引用数及各自的名称。此阶段可保留完整原件；可建立作品的包仍限于通过 R6a 检查的静态图片包。

## 可识别的容器

| 格式 | 核对内容与范围 |
|---|---|
| WAV | 小端 RIFF/WAVE、标准 PCM、声道／采样率／位宽与块对齐关系、非空完整数据块。接受 8、16、24、32 位 PCM。 |
| MP3 | 至少两个连续的完整 MPEG Layer III 帧，允许可识别的首尾 ID3 标签；逐帧检查采样率、码率索引及长度。自由码率或无法判定边界的文件保留原件。 |
| MP4 | 常规非分片 MP4，至少一条视频轨；逐轨核对本地数据引用、样本声明、样本大小和分组、32／64 位块偏移，以及样本覆盖的本地媒体范围。本阶段支持标准样本大小表 stsz。 |

沿用单包 32 MiB、单文件 16 MiB、解压总量 64 MiB 和最多 256 个文件的限制。单文件的检查上限为 8192 个 WAVE 块、131072 个 MP3 帧，或 16384 个 MP4 块、262144 个媒体块偏移、1048576 个样本。超出范围时报告具体文件，结构合法的包仍可保留。压缩包自身损坏、越界等错误沿用 R6a 的拒绝规则。

沿用角色导入检查与原件保留接口。音视频文件在 members 清单中附带 media 字段，记录 kind、format、label、verified，以及核验失败时的 diagnostic。文件结构、后缀、声明及用途分别核对。含音视频的包返回 original-only，直接请求确认导入也会被拒绝。媒体内容不会发送到页面，远程 URI 仅作文本显示。「已识别容器」表示选定结构通过检查，可解码性和播放体验另行验收。

## 离线验收

基线为合并 PR #526 后的主线 ca0bb539。夹具「灯室放映员」含静态主肖像、PCM 提示音、两条声明共用的静音 MP3、四帧视频和一个远程引用。夹具、截图及本地记录独立保存。

| 检查 | 结果 |
|---|---|
| Windows 定向回归 | 25/25。覆盖容器边界、截断、伪装后缀、样本范围、外部数据引用、共享与缺失引用、R6a 检查和版本导出、旧会话和 V3 PNG。首次运行缺少父前端的 jsdom；按锁文件离线安装后通过。首次日志保留。 |
| 禁网 Linux | 11/11，工作树以只读方式挂载。 |
| 页面 | 独立 Chromium 的 960px、390px 均检查三类音视频，保留原包，刷新并下载。下载内容与输入逐字节相同。重启宿主后可读回原件，作品数为 0。浏览器未发起媒体或外部请求。 |
| 构建 | 父前端与聊天前端通过，父前端仍有主包体积提示。 |

人工验收时，选择中性夹具，在「包内文件与引用」中核对静音 MP3 的两个用途，再保存并下载原件。验收后进入交付点 2 的版本导入与导出，已有引用替换属于交付点 3。

本次为容器与创作页定向验证。全轮组合回归留在 R6b 收口。[R6a 验收记录](./CHARACTER_R6A_ACCEPTANCE.md)中的旧世界与 Provider 门禁、设备延期、R4c ①②待证项继续保留。④仅证实宿主停止读取，供应商最终用量和计费待证，US$0.018990 预留未结。回退时可停止本轮独立预览，保留原件和独立数据目录。
