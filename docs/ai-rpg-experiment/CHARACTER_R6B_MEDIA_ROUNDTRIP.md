# R6b 交付点 2 · 导入音视频角色包并按版本导出

交付点 1 已获用户验收。[检查器的格式范围与上限](./CHARACTER_R6B_MEDIA_INSPECTION.md)继续适用。交付点 2 基于主线 ca0bb539 的独立工作树，开始前逐文件核对了交付点 1 的四个累计文件及中性夹具。

## 作者流程

检查含本地 WAV、MP3、MP4 的 V3 CHARX，看到「音视频角色包检查通过」后确认导入。「角色包资源与引用」按卡中的声明顺序列出各项用途。图片可预览，音视频显示路径、类别和大小。创建版本后，在预览中选择「导出此版本的 CHARX」。只改人物描述再封存时，两个版本可分别导出，各自带上原有媒体。导入原件可单独下载。[操作指南](../../client/src/content/help-center/articles/exchange-character-charx.md)

## 接口和版本归属

- 检查结果新增可导入分类 `media`。纯图片仍返回 `images`，任何阻断诊断仍归为 `original-only`。确认时服务端重检原包和预期 SHA-256，浏览器仅提供已有导入合同中的意图参数。
- 音视频通过包内路径绑定大小、MIME 和内容 SHA-256，实际字节存入本地不可变内容存储。索引写入导入作品的固定归属记录，作品 ID 源自完整原包哈希。即使两个包只在某个声音的字节上有区别，也有各自的绑定。纯图片包沿用旧索引结构，既有记录无需迁移。
- 版本包含作品 ID 和固定的角色定义。解析资源时按作品归属与该版本的声明取数，复制作品沿宿主核验的复制来源继承绑定，导出逐项复核大小和内容哈希。重复引用的文件写入 ZIP 一次，各声明及未知字段分别保留。导出完成后再运行同一包检查器。
- 沿用现有检查、导入、资源清单、版本导出及原件接口。清单显示音频和视频条目；图片读取接口继续拒绝音视频。草稿替换音视频属于交付点 3。
