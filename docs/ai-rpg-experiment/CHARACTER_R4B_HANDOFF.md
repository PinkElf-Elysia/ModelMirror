# R4b 人工总结与记忆

实现基线 `95ce9a83`，提交候选在主线 `0ca55e8f` 上验证。玩家从现有 R4a 续聊分支建立资料副本。单聊、群聊、R3b 继续使用原有进入 R4a 的入口。角色版本、身份、场景、参与区间和历史来自宿主验证后的分支快照。复制分支时也固定当时的成员默认参数。用户操作见帮助中心「整理角色总结与记忆」。

## 运行入口

从 `experiments/ai-rpg-engine` 执行 `node character/long-context/launch.mjs <新数据目录> <起始端口> --manual-memory`。依次启动角色工作台、群聊、旧续写、R4a 和资料分支，均监听 loopback。离线启动器使用中性角色，在新群聊中准备有缺席和归队的集合地点示例。

受信宿主使用 `manual-memory/application.mjs` 的 `startMemoryWorkspace(options)`。它在已有 R4a 工作台上绑定相同的 coordinator、参数目录、回执 provider 和预算所有者。使用者从当前长对话页进入对应资料分支。原来源剩余额度仍由原宿主及共同账本核验。已派发但未知的请求冻结后续写入，恢复仅查询原回执。

## 存储、来源与可见性

R4b 独立使用 `character-manual-memory-v1` scope、`manual-memory-ledger/1` 记录及 `memory-context-plan/1` 计划。旧 R4a 的重放会重新执行当时的装配算法，因此 R4b 在独立存储和装配器中演进。R4a 描述符涉及的算法及旧账本保持原字节。页面静态资源、loopback HTTP 外壳和分页导航复用已有实现。

每条资料区分总结/记忆、对话经历/作者设定、公共/成员私有、固定/关键词。宿主为经历绑定消息 ID、精确修订、位置、发言者和当时的可见范围。公共经历须使用公开消息，并要求目标角色实际参加全部来源消息所在区间。公共作者设定适用于当前分支成员。已有来源不详的旧资料出现在本人待确认列表，可编辑为有明确来源的新修订后采纳。

草稿保存与采纳分开。纠错保留旧版本，直到采纳新版本。停用是保留记录的写操作。来源消息修订不符时，资料自动退出模型上下文。每个消息位置记录当时的资料修订边界，按消息位置分叉时只继承该时点已有的版本。编辑同一消息或切换候选后再核验依据。冻结请求保存其有效资料、采用/省略理由、消息修订、配置快照和实际 wire messages。

显式告知只允许来自可见、有效的公共经历。作者确认公开正文后，原子追加一条玩家消息。从这条消息得知信息的成员只能引用新消息。告知不会隐式采纳新资料或触发生成。

## 内部接口

本地玩家工作台由 cookie、同源、Host 和 CSRF 验证保护。这个页面的已授权使用者能够切换成员视角。模型请求只取该请求目标成员的投影。成员 ID 仅用于选择视角。

| 操作 | 合同 |
|---|---|
| 创建 | `POST /api/import` 使用 `kind=context, familyId, branchId` 引用。来源由 R4a store 读取并验证。 |
| 查看 | `GET /api/notes?family=…&branch=…&actor=…` 返回该视角下的资料和可选来源。搜索使用当前视图已有的记录；来源定位同时核对消息与修订。 |
| 草稿 | `POST /api/draft` 携带 familyId、operationId、expectedRevision 和 payload。payload 指定 branchId、actor、noteId（新建时为 null）、owner（公共为 null）、kind、content、origin、refs、mode、words。宿主核验所有来源，生成版本和位置。 |
| 采纳和停用 | `POST /api/adopt`、`/api/disable` 选择当前分支、成员和资料 ID。CAS 和幂等键与消息共用，改动进入同一记录。已有资料的 owner 固定。 |
| 告知 | `POST /api/tell` 额外提供确认公开的正文。重复请求返回既有结果。 |
| 预览、发送与恢复 | 沿用 preview、generate、context、recover 入口。预览哈希绑定修订及最终请求。精确重生成冻结旧上下文。 |

关键词采用 NFKC、小写和字面子串匹配。扫描本轮输入和窗口内最近四条目标可见消息。按命中不同词数、采纳顺序、稳定 ID 排序。固定资料与必需上下文一起参与容量保护，关键词条目只在剩余空间中整条加入。超限时预览显示原因，固定内容无法容纳时在派发前拒绝。

## 接入与验收约定

- 将已有任务授权、来源限额和预算守卫交给受信宿主。新资料分支继承来源与成员绑定，准备请求时重新核验修订和可见范围。已派发但结果未知的请求保留预留，恢复操作仅凭原回执结算。
- 以目标成员的资料面板、装配轨迹、冻结消息和实际回执判定隔离、召回与分支修订。模型是否复述了事实、回答是否冗长，另作行为观察。
- 逐笔核对模型、供应商、服务档位、用量和费用。服务档位无法与派发时的端点快照唯一对应时，可单独复算费用，精确端点保留待证。八项结论见[验收报告](./CHARACTER_R4B_ACCEPTANCE.md)。

停止独立预览即可退出本轮体验。新数据保留在独立目录。后续 R4c 如需自动提案，应通过显式采纳进入同一合同，须另行确认范围。
