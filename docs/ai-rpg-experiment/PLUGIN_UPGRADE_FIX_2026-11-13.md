# RPG 插件版本升级与错误提示修复

## 范围与契约

已安装的消息工具 1.0.0 与宿主提供的 1.1.0 不匹配时，原界面把失败折叠成“未完成启停”。旧版卸载还错误地发送当前包的哈希。本次增加显式升级接口和界面，分别显示已安装/可用版本、待升级筛选及最近 100 次版本记录。

升级必须同时匹配当前注册表 revision、原 installationId/版本/双哈希、目标版本/双哈希及完整权限。确认后原子写入；保留 installationId、每个会话的 active/cardId/resourceHash，刷新授权 epoch，使旧执行票据失效。权限清单在确认区展示。不会自动启用原先关闭的会话，也不删除设置、总结、记忆和聊天。失败不自动重放请求。

升级范围为当前服务提供的包。版本历史是审计记录，不存放旧可执行包，也不提供任意版本切换或一键降级。旧注册表不必先迁移；首次写入才记录版本历史。卸载使用实际已安装绑定，兼容失配安装。

忙碌/未核对请求、来源校验、并发冲突、包缺失、权限变化和保存失败分别给出安全错误码及中文建议，不显示内部堆栈或凭据。新旧聊天宿主、蓝色大肥鱼及 AI 女友均提供 upgrade 路由。

## 数据与兼容

主线已有会话通过精确冻结的宿主哈希映射兼容；原始会话字节和授权 resourceHash 不改写。创作版本也只兼容列出的前一宿主绑定。提示词、开局、未知哈希或资源篡改仍拒绝。

共享栈采用已部署镜像的修复覆盖层，沿用既有环境、卷、网络、端口和共享专用历史兼容映射；不替换其他服务、不并入后来新增卡片/商店功能。所有持久化数据先做私有备份。先在无网络、虚假凭据的完整副本验证，再部署共享栈。只读模型目录快照不属于模型生成调用。

## 离线验证

- Node 聚焦回归 46/46：升级、独立开关、持久化/重开、幂等、权限/版本冲突、包篡改、忙碌拒绝、旧注册表、保存失败、创作绑定及独立聊天入口。
- 前端版本管理回归 5/5；客户端和卡片生产构建通过。
- 完整副本 25 份会话兼容；七个安装区的消息工具 1.0.0 → 1.1.0，两个安装区因旧未核对请求暂缓。仅插件注册表与所有权锁变化，其他文件逐字节 SHA-256 相同；会话版本、轮次及原开关一致。
- 浏览器按帮助教程从全新合成安装重放：可升级 → 确认权限 → 升级成功 → 已安装/版本记录。真实模型调用 0。
- 已知基线问题：output-edits.test.mjs 的 exact committed main runtime 用例在未改动基线亦失败；未改动或放宽该断言。帮助截图全仓检查有 10 处其他文章既有问题，本次两张真实截图符合 PNG、宽度与体积要求。

## 回退

保留部署前精确镜像与私有卷备份。升级后的 registry 含版本历史，旧宿主不识别该字段；回退必须在停止对应宿主并确认期间无新写入后，同时恢复对应插件注册表备份与旧镜像。不得整卷覆盖当前会话，不能丢弃升级后的新增用户操作。若已有新写入，先导出并人工合并注册表。无需改动模型路由或调用额度。
