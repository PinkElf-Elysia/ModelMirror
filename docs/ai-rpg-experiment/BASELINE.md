版本 v3；依据同一任务内用户的最新明确要求。v2 纠正了目标卡特化附加机制的过度工程化倾向；v3 确立“所有可选增量皆插件”、必要核心/插件市场/卡片市场三层边界和零插件首版基线。分轮路线仍只是一阶段推进建议，不代表开发已启动。
## 1. 用户已确认的目标与边界
U01：制作独立的实验性 AI RPG 模块，为矩阵绿洲积累卡片合同、资源组织、提示词/世界书编排、模型适配、交互和验证经验。
U02：第一阶段用少量代表资源完成卡片主体的核心交互链路，以及模镜控制面下的基本运行空间和自有交互界面。
U03：不复刻目标卡片或平台 UI，不照搬 Tavern AGPL 项目；保留必要能力并按自身专业逻辑设计。
U04：先复制部分世界、天赋、身份及可取得的背景、文风和世界书资源用于验证；后续另行全量迁移和质量审计。
U05：不逆向完整隐藏提示词。通过已加载资源、正常电脑操作和授权探针理解核心逻辑，再自主设计提示词与上下文编排。
U06：模型目录、凭据、供应商、路由、预算、取消和调用策略由模镜管理；长期记忆同样归模镜治理，不建立第二控制面。
U07：记忆宫殿、自动总结和目标站模型管理等功能，只在第一阶段完成后选择性参考。
U08：沿用用户已经完成的目标卡法律审计；本目录只登记新研究候选的许可证边界。
U09：本次只修订总体分轮路线和固化文档。每轮的批次、具体任务与门禁留到进入该轮的计划模式制定。
U10：探针额度按授权阶段独立管理，不自动合并、借用或刷新；完整记录见 PROBE_LEDGER.json。
U11：文档路线不推定 Commit、Push、PR、Merge、Deploy、Publish 或耦合矩阵绿洲父模块的授权。
U12：best practice 研究分产品层和运行层，并可从论文、标准、开源实现、官方文档、公开产品机制和成熟创作者实践中交叉取证。
U13：研究候选不等于批准采用；真正复用前按组件和固定版本核查代码、依赖、数据、模型、权重、素材、遥测与服务条款。
U14：任务与回合内经济、目标卡命名存读档、死亡/复活/重生、离开/结算/跨世界继承是该卡通过提示词、世界书等实现的特化附加机制，不是 AI RPG 的通用公理或首版工程主轴。
U15：这些附加机制不设独立轮次，不在首版建设专用任务引擎、经济系统、分支存档引擎、死亡生命周期或跨世界结算平台。首版只需证明卡片资源和通用交互框架能够承载少量代表性表达。
U16：模镜会话历史、调用回执和必要的运行恢复属于框架可靠性；它们不自动升级为目标卡的命名存档、回退分支或跨世界继承规则。
U17：第一版后的所有非必要、可替换、可独立启停的功能、模块和优化包统一作为插件进入插件市场；向量/图检索、记忆宫殿、自动总结只是其中的明确例子。
U18：第一版必须在零可选插件下完成核心链路，只保留安全装载所需的最小插件宿主合同，不预装增量插件，也不把市场产品作为首版前置依赖。
U19：插件由用户自主选择、授权、安装、启用、停用和卸载；卡片可以声明必要/推荐插件及缺失时降级行为，但不能静默安装或越权启用。
U20：角色卡及其世界、身份、天赋、背景、文风、世界书、开场和示例等资源进入卡片市场；主要来源为用户提供的大量 Tavern 卡片资源转化、我们协助编写及未来 UGC。
U21：卡片包默认是受控数据，不携带任意可执行代码；需要执行能力的部分拆为插件。Tavern 卡片转化不导入 Tavern 平台代码，并记录原件 hash、来源、格式、转换器版本、字段映射和变更。
U22：插件仍由模镜统一管理模型、凭据、路由、预算、长期记忆和安全策略，并登记版本、兼容性、许可证、hash、能力与权限；不得形成第二控制面。
## 2. 第一阶段核心范围
“首版完整”指卡片主体从资源到交互的闭环完整，不指把目标卡每项附加玩法都做成通用引擎。
| 覆盖 ID | 第一阶段必须承载的能力 |
|---|---|
| CAP-01 | 玩家最终角色卡及开局配置的输入、解析和确认；能表达姓名、外貌、性格、偏好、模式、世界、身份、物资与天赋等字段 |
| CAP-02 | 少量代表性的世界、身份、天赋、背景、文风和世界书资源；形成可进入未来卡片市场的版本化卡包元数据；稳定 ID、来源、版本、别名和必要兼容信息；不直接执行原 HTML |
| CAP-03 | 自主设计的主持提示词与上下文编译：玩家/AI 权限、当前场景、相关资源、世界书触发、知识可见性、文风、历史预算和输出合同 |
| CAP-04 | 独立运行框架：模镜模型选择与调用适配、流式响应、取消、错误处理、调用回执、会话标识和最小必要运行状态；包含插件发现、能力/权限声明、兼容检查、启停和故障隔离的最小宿主合同，但首版不装载可选插件 |
| CAP-05 | 核心交互闭环：配置或导入角色卡 → 进入场景 → 自由输入/非穷尽建议动作 → 生成 → 叙事与信息模块呈现 → 下一回合 |
| CAP-06 | 自有信息架构与基础 UI：连续叙事为主、场景和角色信息可查、世界书/状态来源可解释、生成状态集中、键盘和窄屏可用 |
| CAP-07 | 运行连续性：沿用模镜会话与记忆治理，保留资源版本、上下文装配和模型调用证据；仅保存框架运行所必需的状态 |
| CAP-08 | 卡片特化扩展的轻量兼容：任务经济、卡内存读档、死亡重生、结算继承优先由卡片配置、提示词或世界书表达；只选少量样例验证可呈现和可继续 |
| CAP-09 | 安全与评测基础：资源和模型输出按不可信数据处理；mock 与真实模镜调用分栏；核心链路、提示词/世界书质量和玩家体验分别留证 |
| CAP-10 | 零可选插件的代表性竖切交付：少量资源通过真实运行框架贯通核心链路，能够独立审阅，并清楚标明未实现的特化扩展、插件和后续全量迁移边界 |
| CAP-11 | 生态就绪边界：首版只验证卡包/插件最小合同、缺失插件降级和隔离边界；不交付市场 UI、在线安装、评分、支付、发布审核、自动更新或 UGC 运营 |
角色创建中的世界、身份和天赋选择属于卡片资源入口，可以保留筛选、随机、指定和自定义等核心操作。涉及积分、刷新、退款或复杂概率时，第一版按代表内容所需做轻量表达，不建设通用经济后台。
## 3. 必要核心、插件市场与卡片市场的分界
| 类别 | 第一版责任 | 第一版后归属与边界 |
|---|---|---|
| 必要运行核心 | 卡包校验与加载、基础内容/上下文编译、模镜适配、生成/流式/取消/错误、基础安全渲染、最小状态与回执 | 仅保留每张卡都必须依赖且无法安全卸载的能力；不能因“可能有用”扩张 |
| 最小插件宿主 | 能力和权限声明、版本/兼容检查、显式启停、失败隔离与缺失降级合同 | 第一版零可选插件；市场、在线安装和插件具体能力后置 |
| 卡片主体 | 角色卡结构、资源、提示词、世界书、文风、核心回合行为和声明式生成信息模块 | 进入卡片市场；默认仅含受控数据 |
| 卡片特化扩展 | 少量任务经济、命名存读档、死亡重生、结算继承样例可由卡片数据表达 | 若只是某卡事实/规则，留在卡包；若成为可选且跨卡复用的行为，进入插件市场，不进入内核 |
| 可选增量能力 | 第一版不实现 | 向量/图检索、记忆宫殿、自动总结、复杂规则、扩展 UI、媒体、评测和创作工具等全部进入插件市场 |
| 双市场运营 | 第一版不实现 | 插件市场管理能力包；卡片市场管理用户提供资源转化、协助编写与未来 UGC |
判断规则：每张卡运行所必需且必须由受信代码执行的能力才可进入核心；可独立启停的跨卡行为进入插件；角色、世界、文风、世界书及声明式规则进入卡包。如果某个特化规则需要跨回合保持一致，先为卡片声明最小字段或事件；不得先建立功能专属数据库表、全局枚举、硬编码流程或常驻 UI。
## 4. 两条研究主线
- **产品层**：AI RPG 的主持提示词、玩家自主权、自由输入、生成信息排版/UI、世界书、文风、角色与场景一致性，以及可选择吸收的游戏设计方法。
- **运行层**：资源编译、上下文装配、模镜适配、会话/回合调度、最小状态、错误恢复、安全、可观测性和评测。
游戏设计、任务、经济、死亡或继承研究是候选方法库，不自动成为第一版需求。产品层不能通过自由文本直接获得真实系统能力；运行层也不能把任一目标卡的特化玩法固化成所有卡必须遵守的领域模型。
## 5. 拟议架构分层（尚未实现）
| 层 | 责任 |
|---|---|
| 卡片与资源 | 玩家卡、世界、身份、天赋、背景、文风、世界书及声明式扩展；保留稳定身份、来源、版本和未来卡片市场元数据 |
| 内容编译 | 从代表资源生成统一、可检查的卡片运行包；校验引用、别名、可见性、预算和插件依赖声明，不执行来源 HTML |
| 上下文编排 | 组合自主主持规则、当前场景、相关世界书、模镜治理的会话上下文和玩家输入；保留装配回执；首版只用基础检索 |
| 运行适配 | 通过模镜模型 ID、路由和受控参数调用；处理流式、取消、错误、重试边界和调用证据 |
| 插件宿主 | 暴露最小能力/权限/兼容/生命周期接口并隔离故障；第一版无预装可选插件，不提供市场安装流 |
| 交互呈现 | 呈现叙事、建议动作、自由输入和卡片声明的信息模块；为插件保留受控插槽，不让特化模块占据永久一级导航 |
| 记忆与连续性 | 使用模镜会话/记忆能力；记忆宫殿、自动总结及独立检索记忆仅可作为后续插件，不把卡内读档伪装成平台持久化 |
## 6. 第一版后的双市场边界
- **卡片市场**承接全量资源迁移与审计，以及用户提供的 Tavern 卡片转化、我们协助编写和未来 UGC；卡包保存来源、hash、转换记录、许可证、兼容性及插件依赖声明。
- **插件市场**承接向量/图检索、记忆宫殿、自动总结、复杂任务/经济、分支存档、死亡复活、跨世界继承、程序化任务、动态难度、媒体、评测、创作工具等所有可选增量。
- 多个卡片出现相同需求只说明它可能成为插件，不构成进入内核的理由；只有无法安全卸载、每张卡都需要且属于受信执行边界的能力才评估进入核心。
- 插件和卡片市场可以复用模镜已有市场外壳及统一治理，但包类型、权限、生命周期和审核语义必须分开。
- 矩阵绿洲父模块接入、3D、多人和空间世界仍在第一版后独立决策。
## 7. 交付质量方向
代表资源能稳定编译；世界书和文风按可解释规则进入上下文；模型不替玩家补写未授权意图；核心生成链路在零可选插件下可连续操作；模镜调用、mock、错误和取消有可区分证据；资源/提示词/运行版本可追溯；插件缺失或失败不破坏核心；UI 不依赖目标站结构；实验可独立停用且不影响父模块。
对卡片特化扩展的验收只证明“该样例能够由卡片层表达并通过核心框架呈现”，不证明已交付通用任务、经济、存档、死亡或跨世界系统。
这里不规定轮内门禁、阈值、文件划分、实现命令或探针分配。
## 8. 变更与撤销
调整卡片核心与扩展边界时记录来源和影响。暂停实验可停用独立入口并保留可导出的卡片资源和运行证据；具体回退方案在对应轮计划中制定。本次文档没有迁移游戏数据或改动稳定入口。
