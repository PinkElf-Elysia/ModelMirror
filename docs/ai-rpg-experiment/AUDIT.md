## 3. 已审读资源和实现形态
实际开场 srcdoc 为 1,756,353 个 JavaScript UTF-16 字符单位，title 为“无限重生系统 - 启动协议 v16.2 (Pyrite修复版)”。622 世界、3,117 身份、10,359 世界天赋条目和 472 通用天赋，共 10,831 条；不是独立机制数量。详细字段、权重、源行号和计数保存在 RESOURCE_INVENTORY.json。
世界字段为 name/desc/boss/identities/talents，身份为 name/items，天赋为 name/color/cost/desc/type；无独立稳定 ID、lore/style 字段。worldDB 1,644,979 字符单位，通用天赋字面量 50,448。作品统计“固定设定 3,469、世界书 387,391”单位和安装版本对应关系未证实，不能作为 token 计量。
开局器将档案、模式、世界简介、身份物资、天赋等导出为文本，要求复制进聊天；继承模式带积分、遗产和任务证明。所见 HTML 没有 fetch/XMLHttpRequest/postMessage/localStorage/sessionStorage/indexedDB 字样，仅限这一源码范围，不推断平台无存储。
回复包含场景头、叙事、玩家、NPC、任务商店、世界、记忆表和候选行动。作者日志声称某些世界书以世界名 AND 人物名触发；精确召回、历史扫描、递归、缓存和预算尚未验证。样本显示第三人称、感官描写、生存压力与状态表，但不能证明全部世界有独立文风。
## 4. 主要技术发现
| 编号 | 已观察依据 | 影响与建议性质 |
|---|---|---|
| F1 | 新增存档生成文本快照，并提示人工加入会话世界书 | 不证明事务保存；RP-02 只补充同会话回退表现。首版将其视为卡片特化内容能力，不据此建设通用分支存档引擎 |
| F2 | selectTalent/buyTalent/refundTalent 用 name 判断；214 组同名，263 次多余同名出现 | 可能误去重、误退款；建议稳定 ID，保留来源和展示名 |

| F4 | 337 条 E/中文色名天赋落入默认权重100；15条负价格 | rank与色彩语义需显式映射；负价格可能是负面特质补偿，不能一概删除 |

| F6 | 模型原文同时包含叙事与全部可见状态 | 少量数量测试正确不证明长期状态权威；建议校验提案与提交状态分离 |
| F7 | HTML 混合数据、样式、随机、积分与输出；存在 innerHTML 插值 | 不宜直接移入模镜同源执行；现有 iframe 不含 allow-same-origin，未测试或证明隔离突破 |
| F8 | 交易探针保住资源但额外补写玩家准备承伤的意图 | 查询/世界动作语义需明确；仅凭耗时不能判违规，擅自决定玩家意图是本样本问题 |

## 8. 用户角色样本的合同意义
完整原文独立保存。人物档案/龙人族公主背景与当前E级外门弟子身份分开；稀有度与当前战力、成长潜力分开。至尊仙胎蛊的“拥有/已激活”、坚持的精神特质、春秋蝉死亡触发及失败风险、九转资质的潜力不能混为即时数值奖励。
“系统核心权限·root”是虚构游戏能力，不是真实系统权限。每世界刷新五件S+商品与一次无掉落原地复活是不同效果；后者是否每世界重置未明确。系统记住越权可表示剧情事件，不要求记忆宫殿。
样本有四个同世界天赋，与开局器标准两项配额不同；应识别规则模式/来源差异，不把用户样本判无效或默默按标准抽取重写。世界背景与NPC知情范围、重生/复活优先级、世界与知识/永久用量的回退范围需审计。样本用于机制覆盖，不要求首版实现所有高阶天赋组合。

## 10. AI RPG 双轨研究结论
“产品层/卡片本身”明确指 AI RPG 整体的角色卡与资源、提示词与主持、玩家交互、AI 生成信息排版/UI、世界书、背景和文风，不限原卡、原平台或其他卡片。运行层覆盖内容编译、生成调度、模镜适配、会话连续性、最小状态、安全、可观测性和评测。研究目录是候选方法库，不是首版功能清单。
前六个主题研究分支分两波覆盖；随后另用游戏设计、安全/供应链和评测/运营研究补齐用户列举范围之外的关键面向。最终研究来源横跨论文、标准、官方工程文档、开源实现、专有产品公开机制和互动叙事实践：
1. 互动叙事/内容工具：ink、Yarn Spinner、Twee/SugarCube、boardgame.io、TextWorld、BALROG。
2. 结构化生成/编排/评测：PydanticAI、XState、LangGraph、promptfoo、Inspect AI。
3. 长期记忆：Mem0、Letta Code、Graphiti、Generative Agents。
4. AI RPG 提示词/主持：Re3、DOC、RoleLLM、D&D Dialog Challenge、CALM、IBSEN。
5. 世界书/上下文：NovelAI、AI Dungeon、SillyTavern公开文档、Lost in the Middle、GraphRAG。
6. 交互和信息排版/UI：WCAG、Xbox XAG、Microsoft HAX、ink、Ren'Py，加上模镜现有产品设计语言。
7. 游戏设计：Agency Reconsidered、Failbetter QBN/storylet、GUMSHOE、Blades in the Dark、Doran/Parberry 任务生成、Hunicke DDA、PAYADOR 与 ink 确定性随机；覆盖能动性、有意义选择、线索可达、失败推进、节奏、成长、防刷、任务因果和经济。
8. 安全与内容供应链：OWASP、CommonMark/DOMPurify/Trusted Types、JSON Schema、SLSA 与 NIST；覆盖不可信内容、间接提示注入、渲染/脚本能力、来源、版本、迁移与完整性。
9. 评测与运营：Inspect AI、promptfoo、BALROG、RPEval、RoleEval、PXI 与 LLM-as-judge 研究；覆盖确定性不变量、长局/跨模型/多语言质量、模型裁判偏差、人工玩家体验、成本/延迟和不可变回执。
综合结论经最新纠偏后是：第一版的中心是把代表卡片资源稳定编译成受控上下文，经模镜调用后在自有界面完成连续交互，并在零可选插件下通过竖切。框架只持有调用、会话、资源版本、基础上下文装配、卡片明确声明的最小状态及安全装载所需的插件宿主合同；模型输出不能直接获得真实系统能力。世界书按作用域、可见性、中文别名、优先级和预算可解释装配。任务经济、存读档、死亡重生、结算继承及更复杂的检索、记忆、storylet、线索、成长和随机机制都属于可选设计材料或卡片特化扩展，后续行为能力进入插件市场，内容进入卡片市场，不自动进入通用内核。
评测继续分为运行合同、模型生成质量和真人玩家体验，但首版优先验证资源→上下文→模镜调用→呈现→继续交互的核心链路。卡片特化样例只检查可表达、可显示和不破坏核心流程，不以完整规则覆盖率评价首版。mock 不证明叙事质量或真实计费/限流；LLM judge 不替代人工校准和玩家体验。
所有候选保持“未采用”。特别边界包括：LangGraph time travel 会重新执行后续 LLM/API；XState 恢复会重启 invocations；PydanticAI 校验重试可能再次调用模型；PAYADOR 为 GPL-3.0；GUMSHOE 与 Blades SRD 为 CC BY 3.0 且不覆盖商业设定/素材；RPEval 论文许可不自动覆盖未标 LICENSE 的代码/数据；Yarn 品牌下不同组件分别使用 MIT 或具限制的 YSPL；Twine/Tweego/SugarCube 许可各不相同；Mem0/Letta/Graphiti 的根代码许可不覆盖平台、模型、数据或品牌素材；promptfoo 存在缓存、默认遥测及部分托管推理路径。详细证据、第一阶段/后续划分见 BEST_PRACTICES.md，许可证和服务边界见 OSS_REUSE_REGISTER.md。

## 11. “一切可选皆插件”与双市场决策
- 第一版保留必要运行核心和最小插件宿主合同，并以未安装任何可选插件作为验收前提；插件市场和卡片市场本身不在第一版交付范围。
- 第一版后的向量/图检索、记忆宫殿、自动总结、复杂规则、扩展 UI、媒体、评测、运营、创作和转换辅助等所有可选功能、模块与优化包进入插件市场。
- 其他角色卡及其世界、身份、天赋、背景、文风、世界书、开场和示例进入卡片市场；来源固定为用户提供的 Tavern 卡片资源转化、我们协助编写和未来 UGC。
- Tavern 转化只处理获准内容数据，不导入 Tavern 平台代码；卡包默认不可执行，并记录来源、原件 hash、格式、转换器版本、字段映射和变更。
- 卡片可声明必要/推荐插件及缺失降级，但不能静默安装。用户负责选择和授权；插件仍受模镜模型、凭据、预算、记忆、权限和安全控制面治理。
- 两个市场可复用模镜市场外壳，但插件包和卡包的能力、权限、审核、版本与生命周期合同分开。

该决策改变后续能力的归属。后续获批的 RPG-01 已采用 Ajv 8.20.0 实现合同校验；仍无模型调用和无新探针。
