## 一次生成协议

示例：

```text
你收起空药包，准备回到药圃。
<state_delta>{"operations":[{"type":"quantity","id":"medicine","delta":-2,"reason":"本轮服用两份养息丹"}]}</state_delta>
```

这只是协议示例，不是真实模型证据。程序依据已有数量计算，不接受 `value:3` 覆盖余额；非法数量或未知初值使整批拒绝。正文、状态、事件、操作结果同一次正式提交；原始回执先保存，便于拒绝或中断后核对。

允许的类型见 `adapter.mjs` 的协议说明及 `rules.mjs`：

- 定性：set、mark、condition、progress、relationInfo、faction。
- 追加档案：addAbility、addItem、addRelation。
- 程序计算：quantity、balance、relation。
- 引用：equip。

没有任意 JSON 路径覆盖、删除档案或普通增量改写锚定资料的接口。关系的类别和幅度是模型提案；程序保证区间、最终范围和前后值，不保证救命／背叛等事件的语义真实性。

## 上下文和插件

前后置词、自定义世界书和 Mod 先通过现有模块装配。历史面板仅供本地触发匹配，最终历史使用正文；非展示型正则按既有语义作用于历史正文。状态和已确认事件随后作为只读系统资料加入，不再次触发玩家输入链。

没有新增全量变量 JSON 输出，也没有每轮固定规划调用。真实模型适配尚未接入本预览；模拟供应商生成一次完整回执，候选预览为独立的确定性样例。

总结／记忆输入复用原有指令，输入正文和已提交变化，剔除渲染面板。它们不持有本地状态写接口。真实总结效果、旧原生会话的全面插件 UI 联调留待后续授权，当前报告仅覆盖实际请求装配。

## 运行记录

- `stateRevision` 表示状态检查点；`revision` 用于记录 CAS。
- 操作编号与请求指纹绑定；相同编号不同内容拒绝，相同请求返回原记录。
- 未知回执只能查询原操作；模拟供应商回执独立持久化，进程重启后无需再次生成。
- 截断、空正文、非法增量保留回执但不提交正文或状态。已知失败可明确放弃整条回复，无自动重试。
- 候选只预览；采用校验状态版本和候选指纹，正式入账一次。
- 明确改写需原因，保存完整前后状态；有未确认回合时不能改写。
- 检查点分支复制对应状态和正文边界，不能单独回退正文。
