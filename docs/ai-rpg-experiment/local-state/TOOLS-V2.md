## 交付与接口
- 原生函数表：`query_local_state`。参数只含 queries：最多3个查询，支持 items、abilities、relations、balances、equipment、traits；按 id/name/kind 筛选，每项最多50条。
- 宿主绑定当前会话和冻结状态；工具没有 sessionId、文件路径或写入参数。结果有 stateRevision、覆盖范围、匹配条目与未设定字段。
- coverage 的 complete-registered-scope 只表示指定的已登记范围完整；不表示所有世界事实或物品容器归属。
- 首次生成使用 auto；可直接完成，也可返回一个原生 tool_call。宿主执行查询，保留 assistant 消息及不透明元数据，追加对应 tool 结果，第二次生成使用 none。
- 每回合最多2次生成。不递归、不自动重试；异常、截断、未声明工具不入账。最终正文与合法增量沿用第一轮原子提交。
- 新适配绑定 `cultivation-local-state-tools/2`；第一轮仍为原模式。新档案或用户确认的分支进入新版，旧记录不静默迁移。
- 只读查询不重复触发世界书、前后置词、Mod 或输入正则；正式历史及记忆源不携带工具协议。已知配置冲突校验沿用第一轮，不宣称识别任意自然语言冲突。

新增默认关闭接口：
- POST `/api/rpg/v1/local-state/chat/completions`
- GET `/api/rpg/v1/local-state/results/{session_id}/{request_id}`

后端同时要求既有服务认证及 `RPG_LOCAL_STATE_TOOLS_ENABLED=true`；本轮未在共享服务启用。原文本接口校验不放宽。支持现有 default/god-long-v1 参数档案，冻结具体路由和版本；当前目录中的 tools/tool_choice 声明只代表候选能力，不等于真实工具调用已验证。
后端工具 schema 内置在自身模块，不依赖实验文件的部署；合同测试检查它与 Node 工具表相同。
Gemini 的 extra_content（包括 thought_signature）随原调用位置保存、回传，不显示到聊天正文。不能把名字和参数重新拼成消息而丢掉签名。
