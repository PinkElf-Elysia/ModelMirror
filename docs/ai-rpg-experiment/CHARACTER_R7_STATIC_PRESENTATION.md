# R7 交付点 1 · 手动表情与静态背景

基线为合并 R6b 和古代卡地图 PR 后的 `6a724da6`。本交付点的入口为角色封存版本预览、单聊与手动群聊。现有续写页支持单独设置分支画面，便于核对派生规则。

## 作者与玩家操作

展开「表情与背景」。版本预览中的选择只在当前页有效。单聊按会话保存。群聊中先选带序号的角色实例，再选该角色的表情；整组共用一个背景，选项标出来源实例。选择「恢复角色肖像」或「清除背景」即可复原。图片集中在会话上方的画面区，消息正文保留原有底色和历史头像语义。

显示范围限于固定版本已绑定的本地静态 PNG、JPEG、WebP。表情使用 `emotion` 声明，背景使用 `background`。远程、缺失和未识别的声明不进入候选。表情图片加载失败时先恢复封存肖像，肖像也无法显示时使用角色首字。

## 接口与数据

创作宿主在原角色 API 下提供 `appearance/preview/<作品>/<版本>` 和 `appearance/single/<会话>`；群聊、续写宿主各自在同源 API 下提供 `appearance/group/<群聊>` 与 `appearance/branch/<会话族>/<分支>`。

GET 返回可见成员及选择项，图片按该范围内的资源标识读取。POST 接受预期画面修订、选择用途、实例和资源标识，清除时标识为空。预览仅接受读取。宿主从已验证绑定解析角色版本，复核声明、图片归属及内容哈希；会话管理、模型请求和导出沿用原合同。双标签页冲突时重新读取已有选择，由玩家决定是否重新操作。

独立的 `character-presentation-v1` 存储使用 SessionRecords 的所有权锁、CAS 及恢复机制。表情绑定成员实例。背景标识还绑定来源成员的参与区间，即使整个离场和重入过程都没有打开页面，旧背景也不会重新生效。派生分支按会话族和分支 ID 使用自己的偏好记录。旧存档无需迁移。

## 离线验收

| 验收项 | 实际结果 |
|---|---|
| 三个入口与两个封存版本 | 桌面 960px、窄屏 390px 均走通。旧版「微笑」、新版「浅笑（新版）」分别来自各自的版本。作者试选刷新后恢复默认。 |
| 会话、实例、缺席与分支 | 两个单聊各自保存；群内两位同名实例可分别选表情。背景来源离场、重入后清除。真实续写页从开场派生子分支，子分支默认、父分支保留表情。 |
| 刷新、冲突、重启 | 浏览器双标签页旧修订被拒。独立预览进程退出、回收原所有权并使用同一数据目录和端口后，版本预览、两份单聊、群聊、父子分支六个页面的选择及解码图片逐一比对一致。 |
| 运行边界 | 浏览器对照单聊完整会话、同输入的上下文预览和版本 CHARX 字节；宿主测试对照群聊完整记录、预算和实际装配函数的结果。操作前后一致。跨会话、跨成员及跨用途的旧资源标识被拒。 |
| 可访问性与回退 | 键盘展开控件、窄屏无横向溢出。快速切换时先清除旧画面，过期响应失效。空资源、选择复原、图片加载失败均有离线覆盖。两种宽度的页面流程中未发生外部资源请求。 |
| 自动检查与构建 | Windows 去重组合回归 66/66，禁网 Linux 表现层回归 6/6。父前端和聊天前端生产构建通过，父前端延续产物体积提示。 |
| Provider 登记 | 五个原有浏览器及宿主模块更新源码指纹。Python 3.12 下候选和同基线干净副本均失败，11 行诊断逐字节相同。 |

首次浏览器检查脚本误读封存版本响应字段；修正后发现编辑器的模块导入位置导致页面无法初始化。修正导入位置后重新走查通过。初次空白检查发现 16 行行尾差异，定点修正后通过。原失败记录和中性截图留在独立数据目录。
